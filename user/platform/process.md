# 업무 흐름 개선

> 업무 문서(매뉴얼·인터뷰 기록·요구사항)에서 지금의 업무 흐름(As-Is)과 문제점(Pain point)을 뽑고, 개선안(To-Be)을 AI 가 제안합니다. 단계마다 문서 원문을 인용하게 하고, 그 인용이 실제 문서에 있는지 서버가 대조해 **근거 등급(녹·황·적)**을 매깁니다. **대상**: 모든 사용자(같은 워크스페이스 사람과 분석을 함께 봄). **메뉴**: 왼쪽 메뉴 › 내 작업 › 업무 흐름 개선.

## 화면 구성

<figure><img src="img/platform/u-process.png" alt="업무 흐름 개선 화면 — 위 카드에 설명·분석 목록(인사 발령 프로세스 · 완료 · hnix-local · 토큰 · 만든 시각 · 삭제)과 새 분석 단추, 아래 카드에 분석 결과(단계 9, Pain point 5, 녹 4, 황 10, 적 0 꼬리표)와 To-Be 저장·보고서(MD)·BPMN As-Is·BPMN To-Be·Mermaid 단추, As-Is 흐름 표"><figcaption>'인사 발령 프로세스' 분석을 연 모습. 아래 탭으로 As-Is·Pain point·To-Be·설계도를 오갑니다.</figcaption></figure>

| 영역 | 하는 일 |
|---|---|
| 위 카드 — **새 분석** · 목록 | 분석 목록(제목·상태·모델·토큰·만든 시각·**삭제**). 제목을 누르면 아래에 결과가 열립니다 |
| 결과 머리 | 제목, 상태(**분석 중 · 완료 · 실패**), **To-Be 저장 · 보고서(MD) · BPMN As-Is · BPMN To-Be · Mermaid** |
| 요약 꼬리표 | 단계 수, Pain point 수, **녹 · 황 · 적** 개수, (PMS-X 시스템을 골랐으면) 레거시 화면 연결 수, 문서 조각·묶음·모델 |
| 탭 | **As-Is 흐름 · Pain point · To-Be (AI 제안) · 설계도(BPMN)** |

### 근거 등급

| 등급 | 뜻 |
|---|---|
| **녹** | 문서에 원문 그대로 있음 |
| **황** | 요약·의역 — 낱말 대부분이 문서에 있음 |
| **적** | 문서에서 찾지 못함 — 사람이 꼭 확인 |

등급 꼬리표에 마우스를 올리면 인용한 문장과 문서 제목 › 소제목이 보입니다. 등급은 모델이 아니라 서버가 매기므로, **적**이 많으면 AI 가 지어낸 내용이 섞였을 수 있다는 뜻입니다.

## 새 분석 시작하기

먼저 분석할 업무 문서를 [문서 RAG](/user/platform/docs.md) 컬렉션에 올려 두세요.

1. **새 분석**을 누릅니다.
2. **새 프로세스 분석** 창을 채웁니다.

| 칸 | 넣는 것 |
|---|---|
| **제목** | 예: 인사 발령 프로세스 |
| **업무 문서 컬렉션** (필수) | 문서 RAG 의 컬렉션 |
| **문서 (비우면 컬렉션 전체)** | 그 컬렉션에서 특정 문서만 고를 때 |
| **레거시 화면 연결 (선택) — PMS-X 시스템** | 허브에 PMS-X 가 연결돼 있으면 시스템을 골라, 각 단계를 PMS-X 가 분석한 레거시 화면과 잇습니다 |
| **모델** (필수) | 분석할 모델 별칭 |

3. **분석 시작**을 누릅니다.
4. 결과 칸에 *분석 중입니다 — 끝나면 자동으로 보입니다.*가 나옵니다. 문서 양에 따라 몇 분 걸릴 수 있습니다. 실패하면 빨간 글로 이유가 나옵니다.

## 결과 읽기

### As-Is 흐름

| 칸 | 뜻 |
|---|---|
| **#** | 순서 |
| **담당** | 하는 사람·부서 |
| **단계** | 하는 일 |
| **시스템** | 쓰는 시스템(문서에 있으면) |
| **입력 → 산출** | 받는 것 → 만드는 것 |
| **근거** | 녹·황·적 |
| **레거시 화면** | PMS-X 시스템을 골랐을 때 이어진 화면(코드·이름) |

### Pain point

문서에 적힌 문제점 목록입니다(**ID · Pain point · 관련 단계 · 근거**). 문서에 문제점이 없으면 *문서에 적힌 문제점이 없습니다*.

### To-Be (AI 제안) — 고쳐서 확정하기

<figure><img src="img/platform/u-process-tobe.png" alt="To-Be (AI 제안) 탭 — 안내 'AI 제안입니다. 단계·변화·이유를 고쳐 To-Be 저장을 누르면 확정본이 되고 설계도에 반영됩니다.', 표에 담당·단계 입력칸, 변화 고르기(유지·신규), As-Is 단계, 푸는 문제(P1·P2), 이유 입력칸"><figcaption>To-Be 는 표에서 바로 고칩니다. 고치면 To-Be 저장 단추가 켜집니다.</figcaption></figure>

1. **To-Be (AI 제안)** 탭을 엽니다.
2. 줄마다 **담당 · 단계 · 이유**를 고치고 **변화**를 고릅니다.

| 변화 | 뜻 |
|---|---|
| **유지** | 그대로 둠 |
| **변경** | 방법을 바꿈 |
| **자동화** | 사람 대신 시스템이 함 |
| **제거** | 없앰 |
| **신규** | 새로 생김(As-Is 칸이 '신규') |

3. **To-Be 저장**을 누릅니다. 확정본이 되고 설계도에 반영됩니다.

> **주의** 고친 내용은 **To-Be 저장**을 눌러야 남습니다. 같은 워크스페이스 사람도 분석을 열고 고칠 수 있으니, 함께 쓰는 분석은 미리 말을 맞추세요.

### 설계도(BPMN)

As-Is 와 To-Be 를 나란히 그림으로 보여 줍니다. BPMN 은 업무 흐름을 그리는 표준 그림 형식입니다.

## 내려받기

| 단추 | 받는 파일 |
|---|---|
| **보고서(MD)** | As-Is·Pain point·To-Be 를 정리한 Markdown 보고서 |
| **BPMN As-Is / BPMN To-Be** | BPMN 도구(예: 업무 모델링 프로그램)에서 열 수 있는 파일 |
| **Mermaid** | To-Be 흐름을 Mermaid 글 그림으로 |

## 피드백 남기기

요약 꼬리표 옆 *분석이 쓸 만했나요?*에서 👍·👎 를 누릅니다. 모은 피드백은 [AI 사용 현황](/user/platform/usage.md) › 품질 · 지연에 나옵니다.

## 분석 지우기

목록의 **삭제** → *이 분석을 지울까요?*에서 확인합니다. 되돌릴 수 없습니다.

> **참고** **삭제**는 내가 만든 분석에만 보입니다. 다른 사람이 만든 분석은 만든 사람이나 워크스페이스 관리자·시스템 관리자가 지웁니다. 결과 고치기(To-Be 저장)는 같은 워크스페이스 구성원 누구나 함께 합니다.
