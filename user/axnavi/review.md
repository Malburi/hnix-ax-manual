# 변경 리뷰와 보안 점검

> 내가 바꾼 코드를 머지 전에 판정(GO · HOLD · STOP)받고, 지적 사항을 AI 로 고칩니다. 저장소나 폴더의 보안 점검(OWASP 기준)도 같은 방식입니다. **대상**: 개발자. **메뉴**: 소스 제어 뷰 · 상태 표시줄 **리뷰** · 아래쪽 패널 AX-NAVI › 점검 결과 · 명령 팔레트 › AX-NAVI.

변경 리뷰와 보안 점검은 **AI 를 부르지 않습니다.** 코드 색인과 규칙만으로 판정하므로 같은 변경에는 늘 같은 결과가 나오고, CI 머지 요청에서 받는 판정과도 같습니다.

| 영역 | 하는 일 |
|---|---|
| 상태 표시줄 | 판정 `리뷰 GO` / `리뷰 HOLD`(노랑) / `리뷰 STOP`(빨강). 누르면 다시 리뷰합니다. 결과가 없을 때는 `리뷰` 이고 눌러서 리뷰를 시작합니다 |
| **점검 결과** (아래쪽 패널 AX-NAVI 탭) | 판정·대상 줄 아래 심각도(**치명 · 높음 · 중간 · 낮음**)별 지적 목록. 결과가 없으면 **변경 리뷰 실행** · **보안 점검** 버튼이 보입니다 |
| 점검 결과 제목줄 버튼 | 변경 리뷰 · 보안 점검(방패) · 단계 게이트 · **점검 결과 심각도 필터**(깔때기) · **점검 결과 파일별로 묶기 / 심각도별로 묶기** · **점검 결과 지우기** |
| 지적 항목 오른쪽 | **파일로 이동**, **AX-NAVI로 고치기**(반짝이) |
| **상세** 칸 | 고른 지적의 심각도·머지 차단 여부, 제목, 규칙(OWASP·CWE), 코드, 영향, 권장 조치와 **파일로 이동 / AX-NAVI로 고치기 / 닫기** |
| 문제 탭·편집기 | 같은 지적이 진단으로 들어가 코드에 물결 밑줄이 그어집니다. 문제 탭에서는 치명이 오류, 높음·중간이 경고, 낮음이 정보입니다 |

## 변경 리뷰 실행

| 범위 | 하는 곳 |
|---|---|
| 작업 트리(HEAD 대비 지금 바뀐 것) | 소스 제어 뷰 제목줄의 리뷰 버튼, 상태 표시줄 **리뷰**, 점검 결과의 **변경 리뷰 실행**, 명령 **AX-NAVI: 변경 리뷰 (작업 트리)** |
| 스테이지한 것만 | 소스 제어 뷰의 **변경 리뷰 (스테이지)**, 또는 같은 이름의 명령 |
| 브랜치 전체 | 명령 **AX-NAVI: 변경 리뷰 (범위 지정 — origin/main..HEAD)** — 범위를 묻는 칸에 git 범위를 넣습니다(지난번 값 기억) |

1. 위 중 하나를 실행합니다.
2. 오른쪽 아래에 `AX-NAVI 변경 리뷰 (작업 트리)` 진행 알림이 돕니다. 취소할 수 있습니다.
3. 끝나면 상태 표시줄 판정과 점검 결과가 바뀌고, 오른쪽 아래에 `AX-NAVI 리뷰 STOP(중단) — 머지 차단 1건 · 지적 3건 · 위험도 5.1/100(높을수록 위험)` 같은 요약 알림과 **보고서 열기** 버튼이 뜹니다.

> **참고** Git 저장소여야 합니다. 폴더가 '제한 모드'면 점검 결과에 `제한 모드라 AX-NAVI 가 꺼져 있습니다` 가 나옵니다. 믿을 수 있는 폴더면 **이 폴더 신뢰하고 AX-NAVI 켜기**를 누릅니다.

### 판정 읽기

| 판정 | 뜻 | 할 일 |
|---|---|---|
| **GO** | 진행 | 그대로 커밋·머지 요청 |
| **HOLD** | 사람이 확인하고 진행 | 지적을 읽고 판단. CI 에서는 경고로 통과 |
| **STOP** | 철회·재설계 | 고치고 다시 리뷰. CI 에서는 머지를 막습니다 |

판정은 회귀 위험, 컨벤션 일치, 사이드 이펙트, 롤백 가능성, 보안, 테스트 적정성 점수로 냅니다. 다음은 **즉시 STOP** 입니다.

- 평문 비밀번호·키
- SQL 문자열 결합, MyBatis `${}`
- 인가 검사 제거
- `DROP`·`TRUNCATE`·`WHERE` 없는 `DELETE`
- 검증 명령 실패

색인이 있으면 바뀐 메서드의 호출자 수, 관련 테이블, 거슬러 올라간 화면 이벤트까지 함께 나옵니다. "어느 화면이 영향받나"가 곧 회귀 테스트 범위입니다.

## 지적 살펴보기

1. 점검 결과에서 지적 항목을 누릅니다. 오른쪽 **상세** 칸에 내용이 나옵니다.
2. **파일로 이동**을 누르면 그 줄로 가고 물결 밑줄이 보입니다.
3. 많으면 깔때기(**점검 결과 심각도 필터**)에서 볼 심각도만 고릅니다. 필터가 걸리면 점검 결과 제목 옆에 `필터: 치명·높음` 처럼 보입니다.
4. 파일 단위로 보려면 **점검 결과 파일별로 묶기**, 되돌리려면 **점검 결과 심각도별로 묶기**.
5. 다 봤으면 **점검 결과 지우기** — 목록과 상태 표시줄 판정이 비워집니다.

## AX-NAVI로 고치기

지적 하나를 에이전트 작업으로 넘깁니다. 작업 지시에는 위치, 규칙(OWASP·CWE), 코드, 영향, 권장 조치가 들어갑니다.

1. 다음 중 하나를 누릅니다.
   - 상세 칸의 **✨ AX-NAVI로 고치기**
   - 점검 결과 항목 오른쪽의 **AX-NAVI로 고치기**(반짝이)
   - 편집기의 밑줄 위 전구(빠른 수정) › **AX-NAVI로 고치기**
2. 채팅에 새 작업이 열립니다(이미 돌고 있는 작업이 있으면 먼저 묻습니다). 에이전트는 최소한으로 고치고, 같은 패턴이 그 파일의 다른 곳에도 있는지 확인합니다. 의도적으로 남겨야 하는 경우라면 고치지 않고 이유를 설명합니다.
3. 파일을 읽고 저장할 때 승인 모드에 따라 승인을 묻습니다. diff 를 확인하고 승인합니다.
4. 고친 뒤 **변경 리뷰를 다시 실행**해 GO 가 나오는지 봅니다. 채팅에서 파일을 고치면 바뀐 파일 목록 옆에 **변경 리뷰** 버튼이 생겨 바로 돌릴 수 있습니다.

## 의도된 코드는 사유와 함께 억제

규칙에 걸리지만 의도적으로 둔 코드는, 그 줄이나 바로 윗줄에 이유를 적습니다. 억제한 항목도 리포트에 사유와 함께 남습니다.

```java
// axnavi:allow SEC-SQLI-CONCAT 정렬 컬럼은 허용 목록으로 검증함
String sql = "SELECT * FROM TB_EMP ORDER BY " + sortColumn;
```

> **주의** 같은 머지 요청에서 새로 넣은 억제 주석은 CI 에서 판정을 낮추지 못하고 HOLD(리뷰어 확인)가 됩니다.

## 보안 점검

저장소 전체나 고른 폴더를 OWASP 기준으로 점검합니다. 바뀐 것만이 아니라 지금 있는 코드 전부를 봅니다.

1. 다음 중 하나로 실행합니다.
   - 점검 결과 제목줄의 방패 버튼(결과가 없으면 **보안 점검** 버튼) — 작업 폴더 전체
   - 탐색기에서 폴더(여러 개 가능)를 우클릭 › **보안 점검 (OWASP)**
   - 명령 **AX-NAVI: 보안 점검 (OWASP)**
2. 끝나면 `AX-NAVI 보안 점검 — 파일 49개 · 치명 0 · 높음 0 · 중간 0 · 낮음 0` 같은 알림이 뜨고, 점검 결과에 `보안 점검 — 치명 … · 높음 …` 묶음이 생깁니다.
3. 지적은 변경 리뷰와 같은 방법으로 보고 **AX-NAVI로 고치기**로 고칩니다.

채팅에서 `/security-scan` 스킬로 돌리면 `_workspace/reports/security_scan.md` 보고서도 남습니다.

## '서버만' 좌석일 때

관리자가 엔진 위치를 **서버만**으로 정했다면 PC 에 판정 엔진이 없고 플랫폼이 대신 판정합니다.

| 기능 | 서버 엔진에서 |
|---|---|
| 변경 리뷰 | PC 의 `git diff` 를 플랫폼으로 보내 판정받습니다. 진행 알림에 `서버 엔진 · <저장소>` 가 붙습니다 |
| 보안 점검 | 플랫폼이 저장소의 Git 사본으로 돌립니다 |
| 색인 만들기 | 플랫폼이 Git 최신본으로 만듭니다 |
| 단계 게이트·환경 점검 | 쓸 수 없습니다 — `서버 엔진만 쓰는 좌석이라 이 기능은 쓸 수 없습니다` |

처음 실행하면 `이 작업 폴더는 플랫폼의 어느 저장소인가요?` 를 묻습니다. 목록에서 고르면 다음부터 묻지 않습니다. 작업 폴더의 `origin` 주소가 플랫폼에 등록된 주소와 같으면 자동으로 고릅니다.

## 명령줄로 같은 판정

IDE 터미널에서도 같은 엔진을 그대로 씁니다([CLI](/user/axnavi/cli.md)).

```bash
axnavi review                                  # HEAD 대비 작업 트리
axnavi review --staged                         # 스테이지한 것만
axnavi review --diff origin/main..HEAD --format md --out review.md
axnavi scan security src/ --fail-on high
```

종료 코드는 GO 0 · HOLD 3 · STOP 4 입니다.

## 자주 묻는 질문

| 질문 | 답 |
|---|---|
| 리뷰가 '실패'로 끝나요 | Git 저장소인지, 범위(`origin/main..HEAD`)의 브랜치가 실제로 있는지 봅니다. **AX-NAVI: 환경 진단** 으로 엔진 상태도 확인합니다 |
| 컨벤션 점수가 비어 있어요 | 컨벤션 일치는 AI 판정이라 이 판정에서는 평가하지 않고 리포트에 그렇게 적습니다 |
| 영향 범위가 안 나와요 | 색인이 없습니다. **AX-NAVI: 색인 만들기 (전체)** 를 먼저 실행합니다 |
