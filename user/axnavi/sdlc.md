# SDLC 산출물과 단계 게이트

> 요구 → 설계 → 개발 → 테스트 단계마다 필요한 산출물을 조직 양식으로 만들고, 다음 단계로 넘어가도 되는지 GO · HOLD · STOP 으로 판정받습니다. **대상**: 개발자·PL. **메뉴**: 채팅 `/sdlc-docs` · 명령 팔레트 › AX-NAVI: 단계 게이트 점검 · 점검 결과 제목줄.

양식 만들기와 판정은 **AI 를 부르지 않습니다.** 서술은 사람이 쓰거나, 채팅의 `/sdlc-docs` 스킬이 색인과 리포트를 근거로 붙여 채웁니다.

## 화면 구성

AX-NAVI IDE 에는 산출물 전용 화면이 따로 없습니다. 아래 세 곳을 씁니다.

| 하는 곳 | 하는 일 |
|---|---|
| 채팅 `/sdlc-docs` | 산출물 양식의 절을 근거를 붙여 채웁니다("설계서 써줘") |
| 명령 팔레트 › **AX-NAVI: 단계 게이트 점검** (점검 결과 제목줄의 체크 목록 버튼도 같음) | 단계를 골라 판정. 결과는 Markdown 리포트로 열리고 상태 표시줄에 뜹니다 |
| IDE 터미널 `axnavi doc` · `axnavi adr` · `axnavi gate` | 양식 만들기, 현황, ADR, 판정을 진행 기록서에 남기기 |

## 산출물 종류

| 단계 | 산출물 | 종류 이름 | 자동으로 채우는 것 |
|---|---|---|---|
| 요구 | 프로젝트 정의서 | `project` | 규모, 스택 |
| 요구 | 요구사항 명세서 | `srs` | — |
| 설계 | 설계서 | `sdd` | 모듈, API 경로, 상위 테이블 |
| 설계 | 개발 표준 | `standards` | 코드 패턴 |
| 설계 | 아키텍처 결정 기록(ADR) | `adr` | — |
| 개발 | 진행 기록서 | `progress` | 게이트 이력 |
| 테스트 | 품질 검증서 | `quality` | 보안 점검 요약 |

자동 항목은 색인과 리포트에서 채웁니다. 사람이 써야 하는 절은 비워 둡니다. 산출물은 `docs/sdlc/`, ADR 은 `docs/adr/NNNN-제목.md` 에 생깁니다.

## 산출물 만들기

1. 저장소를 열고 색인이 있는지 확인합니다(없으면 **AX-NAVI: 인덱스 만들기 (전수 색인)**).
2. 터미널(`` Ctrl+` ``)에서 양식을 만듭니다.

   ```bash
   axnavi doc new all          # 모든 양식을 docs/sdlc/ 에
   axnavi doc new sdd          # 설계서만
   axnavi doc list             # 필수 절 작성 · 승인 상태
   ```

3. 채팅에서 `/sdlc-docs 설계서 써줘` 처럼 요청하면, 에이전트가 근거를 붙여 절을 채웁니다. 파일 저장은 승인을 받습니다.
4. 사람이 내용을 검토하고 다듬습니다.
5. 검토가 끝나면 검토자가 문서 머리말의 `상태:` 를 `승인` 으로 바꿉니다.

> **참고** `axnavi` 명령은 로그인한 IDE 의 터미널에서 그대로 통합니다. PC 에 CLI 를 깔 필요가 없습니다. 이미 있는 양식을 다시 만들려면 `--force` 를 붙입니다.

### 아키텍처 결정 기록(ADR)

```bash
axnavi adr new "주문 취소 사유를 코드 테이블로 관리"     # docs/adr/0003-….md
axnavi adr new "세션 저장소를 Redis 로" --status 채택
axnavi adr list
```

상태는 `제안 · 채택 · 폐기 · 대체됨` 중 하나입니다. 변경에 아키텍처 결정이 담겨 있으면 에이전트가 ADR 을 상태 `제안` 으로 새로 쓰기도 합니다. 기존 문서를 자동으로 고치지는 않습니다.

## 조직 양식

회사 표준 양식을 한 번 넣어 두면 모든 프로젝트가 같은 목차로 산출물을 만듭니다. 양식은 이 순서로 찾습니다.

1. 프로젝트 `.axnavi/templates/<종류>.md`
2. 조직 공용 폴더(환경 변수 `AXNAVI_TEMPLATES_DIR`)
3. 플랫폼에서 받은 조직 설정의 `templates/`
4. 내장 양식

양식 머리말의 `required:` 에 적은 절이 작성 필수입니다.

```markdown
---
required: [개요, 구조, 인터페이스]
---
# 설계서
## 개요
## 구조
## 인터페이스
```

조직 설정 배포는 관리자가 합니다([조직 설정 배포와 CI 게이트](/admin/axnavi/profiles.md)).

## 단계 게이트 점검

1. 명령 팔레트(`Ctrl+Shift+P`) › **AX-NAVI: 단계 게이트 점검** 을 실행합니다.
2. `AX-NAVI 단계 게이트 — 어느 단계까지 점검할까요?` 에서 단계를 고릅니다.

   | 고르는 것 | 보는 것 |
   |---|---|
   | **요구 정의** (`req`) | 프로젝트 정의서·요구사항 명세(SRS) |
   | **설계** (`design`) | 설계서(SDD)·아키텍처 결정 기록(ADR) |
   | **개발** (`dev`) | 개발 표준 + 변경 리뷰 |
   | **테스트** (`test`) | 품질 검증서 + 보안 점검(치명 0건) |

3. 판정 리포트가 Markdown 으로 열리고, 상태 표시줄에 `설계 게이트 STOP` 처럼 뜹니다(마우스를 올리면 미충족 건수).

게이트는 앞 단계를 **누적해서** 봅니다. 예를 들어 `dev` 는 요구·설계 항목도 함께 확인합니다.

| 단계 | 판정 기준 |
|---|---|
| `req` | 필수 절이 빠지면 STOP, 문서가 승인 상태가 아니면 HOLD |
| `design` | 위 + ADR 유무, 제안 상태 ADR(HOLD), ADR 본문 |
| `dev` | 위 + 변경 리뷰 결과(STOP 이면 STOP, HOLD 면 HOLD) |
| `test` | 위 + 보안 점검 치명(STOP)·높음(HOLD) |

리포트는 항목마다 이렇게 보입니다.

```text
# 단계 게이트 — 설계 (design)
판정: STOP · 종료 코드 4
⛔ 요구  요구사항 명세서 작성   없음 — axnavi doc new srs 로 양식을 만든다
⛔ 설계  개발 표준 작성         없음 — axnavi doc new standards 로 양식을 만든다
✅ 설계  아키텍처 결정 기록     ADR 2건
⚠️ 설계  ADR 결정              제안 상태 1건: ADR-0002
```

각 줄의 안내대로 산출물을 만들고 채운 뒤 다시 점검합니다.

### 작성된 것으로 보지 않는 절

- 양식 그대로인 절
- 자동 항목만 있는 절
- `(…)` 안내문이나 `확인 필요` 줄만 있는 절

### 판정을 진행 기록서에 남기기

IDE 의 점검은 결과만 보여 줍니다. 진행 기록서의 이력 표에 남기려면 터미널에서 실행합니다.

```bash
axnavi gate design --record
axnavi gate dev --diff origin/main..HEAD --record
```

종료 코드는 변경 리뷰와 같습니다(GO 0 · HOLD 3 · STOP 4). CI 에서도 같은 명령을 씁니다.

> **주의** '서버만' 좌석에서는 단계 게이트를 쓸 수 없습니다(`서버 엔진만 쓰는 좌석이라 이 기능은 쓸 수 없습니다`). 필요하면 관리자에게 좌석 엔진을 'PC'로 바꿔 달라고 합니다.
