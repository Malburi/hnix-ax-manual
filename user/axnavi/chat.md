# 채팅 · 모드 · 스킬

> 오른쪽 AX-NAVI 채팅으로 코드를 찾고, 고치고, 스킬(슬래시 명령)을 부립니다. AI 연결(구독·API 키·사내 게이트웨이)도 여기서 고릅니다. **대상**: 개발자. **메뉴**: IDE 오른쪽 보조 사이드바 › AX-NAVI.

먼저 [설치 · 로그인 · 기기 승인](/user/axnavi/install.md)을 마쳐야 합니다. 로그인 전에는 채팅과 슬래시 명령이 잠겨 있습니다.

## 화면 구성

<figure><img src="img/axnavi/chat-work.png" alt="AX-NAVI IDE — 가운데 EmpDao.java 편집기, 오른쪽 채팅에 질문과 색인 조회·파일 읽기 단계, '작업 완료' 답, 아래 입력창과 코드 모드·사내 게이트웨이·매번 확인"><figcaption>채팅에서 일하는 모습. 에이전트가 무엇을 하려는지 보여 주고, 끝나면 <b>작업 완료</b>로 답합니다.</figcaption></figure>

| 영역 | 하는 일 |
|---|---|
| 채팅 제목줄 | 연필(새 작업), 톱니(설정 — 연결 프로필, 자동 승인, **MCP** 탭 등), 더 보기, 크게 보기, 닫기 |
| 대화 칸 | 요청, 에이전트의 진행(파일 읽기·검색·명령), 승인 요청, 결과. 작업 중에는 나침 표식의 바늘이 흔들리고 "생각하는 중…" 같은 문구가 돕니다 |
| **새 작업 시작** | 지금 대화를 끝내고 새 작업을 엽니다 |
| 입력창 | 첫 화면 `할 일을 적어 주세요`, 작업 중 `메시지 입력…` — `@` 로 파일·문맥 추가, `/` 로 스킬, Shift 를 누른 채 파일을 끌어 놓기. 오른쪽에 파일 첨부 |
| 입력창 아래 | 왼쪽부터 **모드**(예 `💻 코드`), **AI 연결 프로필**(예 `사내 게이트웨이`, `Claude 구독`), **승인 모드**(방패 아이콘과 `매번 확인` 같은 이름) |

채팅은 **오른쪽 보조 사이드바**에 있습니다. 닫았다면 **보기 › 모양 › 보조 사이드바**(`Ctrl+Alt+B`)로 다시 엽니다. 첫 화면에서는 마스코트 **나침이**가 인사하고, **예시 요청** 버튼(누르면 입력창에 채움)과 최근 작업이 아래에 나옵니다.

## 채팅으로 일하기

1. 입력창에 하고 싶은 일을 씁니다. 예: "사원을 이름으로 검색하는 함수가 어느 파일 몇 번째 줄에 있어?"
2. `Enter` 로 보냅니다.
3. 에이전트가 파일을 읽거나 고치거나 명령을 돌리기 전에 무엇을 하려는지 보여 줍니다. 승인 모드에 따라 승인 버튼이 뜨면 내용을 보고 승인하거나 거부합니다.
4. 파일 수정은 diff 로 보여 줍니다. 확인하고 승인해야 저장됩니다.
5. 끝나면 바늘이 북쪽에 멈추며 **작업 완료**가 뜹니다.

> **참고** 작업마다 체크포인트가 남아 이전 상태로 되돌릴 수 있습니다. 채팅의 답은 설정에서 언어를 바꾸지 않으면 늘 한국어입니다.

### 대화에 문맥 붙이기

| 방법 | 하는 일 |
|---|---|
| `@` | 파일·폴더·문제 목록을 대화에 붙입니다 |
| 파일 첨부(입력창 오른쪽) | 고른 파일이 `@` 멘션으로 들어갑니다. 작업 폴더 밖 파일(내려받은 구현 명세 등)은 `<작업 폴더>/.axnavi/attachments` 로 복사되고 git 상태·변경 리뷰에 섞이지 않습니다 |
| 끌어 놓기 | 탐색기에서 파일·이미지를 **Shift 를 누른 채** 입력창에 놓습니다. 문서는 첨부, 이미지는 이미지로 붙습니다 |

## 모드 고르기

입력창 아래 왼쪽의 모드 칸을 눌러 고릅니다. `Ctrl+.` 는 다음 모드, `Ctrl+Shift+.` 는 이전 모드입니다.

| 모드 | 쓰는 때 |
|---|---|
| **🏗️ 설계** | 계획과 설계. 바꾸기 전에 범위와 단계를 정합니다 |
| **💻 코드** | 코드를 쓰고 고칩니다. 파일 수정은 diff 로 보여 주고 승인받습니다 |
| **❓ 질문** | 읽기만 합니다. "이 버튼을 누르면 어디까지 가나?" |
| **🪲 디버그** | 오류 원인을 좁혀 갑니다 |
| **🪃 작업 분배** | 큰 작업을 하위 작업으로 나눠 여러 모드에 맡깁니다 |

> **참고** 관리자가 조직 설정으로 팀 전용 모드(예: **서비스 요청 처리**)를 배포했다면 이 목록에 함께 나옵니다.

## 승인 모드 — 묻지 않고 할 범위

파일 수정, 터미널 명령, MCP 도구 호출은 실행 전에 승인을 받습니다. 입력창 아래의 승인 칸(방패 아이콘)을 눌러 하나를 고르면 됩니다. 칸에는 아이콘과 짧은 이름(`매번 확인` · `읽기 자동` · `수정 자동` · `모두 자동`)이 보입니다.

| 승인 모드 | 묻지 않고 하는 일 | 여전히 묻는 일 |
|---|---|---|
| **매번 확인** | 코드 색인 조회, AX-NAVI 엔진 명령, 플랫폼 허브의 조회 도구(서비스 요청·문서 조회) | 파일 읽기·수정·명령 실행 등 그 밖의 모든 것 |
| **읽기까지 자동** | 파일 읽기·검색 | 수정, 명령 |
| **수정까지 자동** | 작업 폴더 안 파일 읽기·수정, 모드 전환, 하위 작업 | 터미널 명령, MCP 쓰기 도구 |
| **모두 자동** | 위에 더해 터미널 명령, MCP 도구 | 거부 목록의 명령, 작업 폴더 밖·보호 파일 수정, 사용자에게 하는 질문 |

> **주의** **모두 자동**은 플랫폼 허브(`hnix-ax`)의 쓰기 도구도 묻지 않고 실행합니다. 서비스 요청 등록·댓글·문서 저장 같은 변경이 바로 반영될 수 있습니다.

- 항목을 하나씩 고르려면 제목줄 톱니(설정) › 자동 승인으로 갑니다. 그렇게 고른 상태는 **사용자 지정**으로 보입니다.
- 코드 색인 조회와, 스킬이 판정 엔진을 직접 부르는 명령은 승인 모드와 상관없이 바로 돕니다. 엔진 밖 명령이 섞이면 원래대로 묻습니다.

## 스킬 — 슬래시 명령

<figure><img src="img/axnavi/chat-slash.png" alt="입력창에 / 를 입력하자 뜬 슬래시 명령 목록 — 'AX-NAVI 스킬' 머리글 아래 /analyze-impact, /cross-repo-modify, /cross-repo-scaffold, /find 와 두 줄 설명"><figcaption><code>/</code> 를 누르면 AX-NAVI 스킬이 설명과 함께 나옵니다.</figcaption></figure>

1. 입력창에 `/` 를 입력합니다.
2. 목록에서 스킬을 고르거나 이어서 이름을 칩니다(예 `/find`).
3. 뒤에 요청을 붙여 보냅니다. 예: `/find 발령 등록 버튼이 저장하는 테이블`

| 하고 싶은 일 | 명령 |
|---|---|
| 처음 맡은 코드베이스 파악 | `/harness-init` — 색인, 프로젝트 규칙(`CLAUDE.md`), 코드 패턴, 검증 리포트 |
| 기능 위치 찾기 | `/find` (`/find-feature`) |
| 흐름·로직 따라가기 | `/flow` (`/trace-logic`) — 진입점부터 DB 까지 |
| 바꾸면 어디가 영향받나 | `/impact` (`/analyze-impact`) — 직간접 영향과 위험도 |
| 안전하게 고치기 | `/modify` (`/safe-modify`) — 사전 영향 분석 → 적용 → 사후 안전성 평가 |
| 작은 수정은 빠르게 | `/vibe` — 영향·안전성 게이트는 건너뛰고 패턴과 최소 검증만 |
| 새 기능 뼈대 | `/scaffold` (`/scaffold-feature`) — 프로젝트 관례대로 Controller·Service·DAO·테스트 |
| SQL 리뷰 | `/sql` (`/review-sql`) — 사용처, 인덱스, N+1, 인젝션, 락 |
| 보안 점검 | `/security-scan` |
| 요구사항 명확화 | `/spec-gate` — 시작 전 목적·범위·제약 인터뷰 |
| 산출물 | `/sdlc-docs` — [SDLC 산출물과 단계 게이트](/user/axnavi/sdlc.md) |
| 위키 | `/wiki` (`/generate-wiki`), `/publish-wiki`, `/wiki-hub` |
| 마이그레이션 계획 | `/plan-migration` |
| 백엔드·프론트엔드 저장소가 나뉜 경우 | `/pair-init` 으로 짝짓고 `/cross-repo-modify`, `/cross-repo-scaffold` |

괄호 안은 같은 스킬의 원래 이름입니다.

> **참고** 스킬은 로그인할 때 플랫폼에서 받아 옵니다. 플랫폼의 스킬이 갱신되면 다음 확인 때 함께 바뀝니다. '서버만' 좌석이면 서버 도구만으로 도는 스킬(`/find`, `/flow`, `/impact`, `/review-sql`, `/security-scan` 등)만 보이고, PC 에서 빌드·검증하는 스킬(`/safe-modify`, `/harness-init` 등)은 보이지 않습니다.

## 프로젝트 열고 색인 만들기

에이전트는 grep 으로 추측하지 않고 **코드 색인**(화면 → 버튼 → 함수 → SQL → 테이블)을 조회합니다. 처음 연 저장소는 색인부터 만듭니다.

1. **파일 › 폴더 열기**로 저장소를 엽니다.
2. 명령 팔레트(`Ctrl+Shift+P`) › **AX-NAVI: 색인 만들기 (전체)** 를 실행합니다. 터미널에서 돌며 AI 를 부르지 않습니다.
3. 코드가 바뀌면 **AX-NAVI: 색인 갱신 (변경분)**.
4. 처음 맡는 프로젝트라면 채팅에서 `/harness-init` 을 실행합니다.

색인은 MCP 도구 `QueryIndex` 로 에이전트에 자동으로 붙습니다(설정 `axnavi.mcp.autoRegister`). 채팅에는 조회 대상과 결과만 짧게 보입니다.

> **참고** '서버만' 좌석이면 인덱스 만들기를 누를 때 플랫폼이 Git 최신본으로 색인을 만듭니다. 아직 푸시하지 않은 내 변경은 서버 색인에 없습니다.

## AI 연결 — 구독 · API 키 · 사내 게이트웨이

채팅 에이전트가 쓸 모델 연결은 **프로필**로 고릅니다. 입력창 아래 가운데 칸에 지금 프로필 이름이 보이고, 이 이름이 곧 누구에게 과금되는지 알려 줍니다.

| 연결 | 준비 | 프로필 이름 | 과금 |
|---|---|---|---|
| **사내 게이트웨이** | 로그인하면 자동 | `사내 게이트웨이` | 조직 |
| **Claude 구독**(Pro·Max·Team·Enterprise) | PC 에 Claude Code 를 깔고 터미널에서 `claude` 를 한 번 실행해 로그인 | `Claude 구독` | 본인 구독·좌석 |
| **API 키** | 환경 변수 `ANTHROPIC_API_KEY` 또는 프로필에 키 입력 | `Anthropic API 키` | 키 주인 |

- IDE 를 열 때 가진 것을 찾아 프로필을 만들고 하나를 고릅니다. 순서는 **조직 선호 → 개발자 선호(`AXNAVI_AUTH`) → 구독 로그인 → API 키 → 게이트웨이**입니다.
- 바꾸려면 입력창 아래 프로필 칸에서 고르거나, 명령 팔레트 › **AX-NAVI: AI 모델 연결 설정 (구독·API 키·사내 게이트웨이)** 을 실행합니다. 1.2.6 까지의 긴 프로필 이름(`AX-NAVI 구독 (Claude Code)` 등)은 새 이름으로 저절로 바뀝니다.
- 구독 연결은 내가 로그인한 `claude` 를 언어 모델로만 부릅니다. 이때 API 키 환경 변수를 빼므로 의도와 다르게 종량제로 과금되지 않습니다. 구독 자격 증명은 회사 서버로 가지 않습니다.
- PC 에서 돌리는 로컬 모델(`localhost` 의 Ollama, LM Studio 등)은 설정 화면에서 프로필을 직접 추가해 씁니다.

> **주의** 조직 정책이 허용하지 않는 연결은 프로필이 만들어지지 않고, 있던 것도 지워집니다. 정책에 없는 연결로 작업을 시작하면 그 자리에서 멈추고 이유(예: `기밀 과제는 사내 게이트웨이만 씁니다`)를 보여 줍니다. 정책은 관리자가 정합니다.

## 플랫폼 도구 쓰기 — MCP 허브 `hnix-ax`

로그인하면 채팅에 MCP 허브 `hnix-ax` 가 붙어 지식 문서·매뉴얼·서비스 요청·에이전트를 도구로 씁니다.

| 해 볼 말 | 쓰는 도구 |
|---|---|
| "사원 조회에 퇴사자가 나오는 문제와 비슷한 지식 문서를 찾아줘" | `pmsx__similar` → `pmsx__kb` |
| "운영 매뉴얼에서 계정 잠금 해제 방법을 찾아줘" | `docs__search` |
| "SR-0042 구현 명세를 읽고 고칠 곳을 찾아줘" | `pmsx__spec` |
| "구매 발주 관리 화면의 As-Is 분석서를 요약해 줘" | `pmsx__menus` → `pmsx__asis_report` (플랫폼 0.9.4~) |
| "발주 승인 프로시저가 무슨 일을 하는지, 업무 규칙만 뽑아줘" | `pmsx__screen_plsql` → `pmsx__routine_logic` (플랫폼 0.9.4~) |
| "경보 진단 에이전트에게 '야간 배치 실패' 원인을 물어봐줘" | `agents__run` |

- 허브의 조회 도구는 승인 없이 바로 돌고, 그 밖의 허브 도구는 승인 모드에 따라 승인 창을 거칩니다. 쓰기 도구는 회사 정책에 따라 플랫폼 승인함에서 승인을 기다릴 수 있습니다.
- 허브 도구가 안 보이면 상태 표시줄 AX-NAVI › **키 다시 받기**를 누릅니다.
- 다른 MCP 서버를 더하려면 채팅 제목줄 톱니 › **MCP** 탭에서 추가합니다.

## 주요 설정

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `axnavi.platform.url` | (비움) | 플랫폼 주소 — 보통 연결할 때 IDE 가 넣습니다 |
| `axnavi.offline` | 켬 | 폐쇄망 모드 — 시작할 때 공개 모델 목록을 받아 오지 않습니다 |
| `axnavi.mcp.autoRegister` | 켬 | 색인 도구를 에이전트 MCP 서버로 자동 등록 |
| `axnavi.gateway.baseUrl` · `axnavi.gateway.model` | (비움) | 사내 게이트웨이 주소·모델 별칭. 보통 로그인 때 받은 값을 씁니다 |
| `axnavi.claudeCode.autoConfigure` | 켬 | 로그인하면 PC 의 Claude Code 에도 사용량 전송과 MCP 허브를 넣습니다 |

명령 팔레트에서 `AX-NAVI` 를 입력하면 모든 명령이 나옵니다. 환경이 이상하면 **AX-NAVI: 환경 진단** 부터 실행합니다.
