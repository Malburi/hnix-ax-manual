# AI 보조 기능

> PMS-X 안의 AI 기능 — 서비스 요청 분류·배정 추천, 지식 문서 초안, 버튼·함수 설명 초안 — 을 쓰는 법과, AI가 꺼져 있을 때 무엇이 대신 나오는지 설명합니다. AI의 결과는 늘 **제안**이고, 사람이 확인하고 반영·확정해야 저장됩니다. **대상**: 운영 담당·PM·PL·분석 담당. **메뉴**: 운영 (SM) › 서비스 요청(SR) · As-Is 분석 › 화면 분석 뷰어(설명 탭).

## AI가 켜져 있는지 확인하기

PMS-X의 AI는 **기본으로 꺼져 있고**, 관리자가 서버 설정으로 켭니다. 켜면 HNIX AX 플랫폼의 LLM 게이트웨이로만 호출하고, 끈 상태에서는 외부 호출이 없습니다. 켜는 방법은 [시스템 — AI 설정](/admin/pmsx/system.md#ai-설정)을 보세요.

화면의 버튼 이름으로 알 수 있습니다.

| 기능 | AI가 켜져 있을 때 | AI가 꺼져 있을 때 |
|---|---|---|
| 요청 분류·배정 추천 | **AI 분류 추천** | **분류 추천**(규칙 결과만) |
| 지식 문서 초안 | **AI 지식 문서 초안** 버튼이 보임 | 버튼 없음 — **지식 문서로 만들기**만 |
| 버튼·함수 설명 | **AI 초안 만들기** | **흐름 요약 초안**(규칙 기반) |

AI로 만든 결과에는 만든 **모델 별칭**(예: `hnix-local`)이 칩으로 표시됩니다. AI 호출이 실패하면 규칙 결과로 대신하고 그 사실을 알려 줍니다("AI 를 쓰지 못해 규칙 결과만 보여 줍니다 — …", "AI 를 쓰지 못해 흐름 요약 초안으로 만들었습니다.").

> **참고** 인수인계 갭 리포트, 인수인계 퀴즈, 구현 명세, 한국어 설명 탭, 영향도 분석은 AI를 쓰지 않습니다. 결과가 매번 같습니다.

## 서비스 요청 분류·배정 추천

<figure><img src="img/pmsx/u-ai-triage.png" alt="요청 상세의 분류·배정 추천 패널 — 유형·우선순위·대상 화면·담당자 선택칸, 각 칸 아래 'AI 선택'/'규칙 1순위' 표시와 이유, 반영 버튼"><figcaption>분류·배정 추천 — 칸마다 근거(AI 선택·규칙 1순위·현재 값 유지)와 이유</figcaption></figure>

**대상**: 요청을 처리할 수 있는 사람(PM·PL, 운영 담당은 본인 담당·미배정 요청). 종료·반려된 요청에는 보이지 않습니다.

1. **운영 (SM) › 서비스 요청(SR)**에서 요청을 엽니다.
2. **AI 분류 추천**(또는 **분류 추천**)을 누릅니다.
3. **분류·배정 추천** 패널에 요약과 네 칸이 나옵니다: **유형 · 우선순위 · 대상 화면 · 담당자**.
4. 칸 아래 표시로 근거를 봅니다.

| 표시 | 뜻 |
|---|---|
| AI 선택 | 규칙이 좁힌 후보 안에서 AI가 고른 값과 이유 |
| 규칙 1순위 | 규칙(코드 목록·화면 그래프·비슷한 요청·화면 담당자)으로 1순위인 값 |
| 현재 값 유지 | 지금 값이 그대로 |
| 근거가 있는 후보가 없습니다 | 고를 후보가 없음 |

5. 필요하면 칸의 값을 다른 후보로 바꿉니다.
6. **반영**을 누르면 요청에 저장됩니다("추천을 요청에 반영했습니다."). 닫기(✕)를 누르면 아무것도 바뀌지 않습니다.

> **주의** AI는 PMS-X가 먼저 좁힌 후보 안에서만 고릅니다. 그래도 "추천은 제안일 뿐입니다 — 확인 후 반영하세요." **담당자** 칸은 PM·PL만 바꿀 수 있습니다.

## 지식 문서 초안

<figure><img src="img/pmsx/u-ai-kbdraft.png" alt="지식 문서 초안 (AI 요약) 창 — 제목과 증상·원인·처리 내용 초안, 지식 문서 등록 버튼"><figcaption>지식 문서 초안 (AI 요약) — 끝난 요청의 본문과 처리 코멘트를 요약</figcaption></figure>

1. 상태가 **처리 완료 · 고객 확인 · 종료**인 요청을 엽니다.
2. 상세 머리의 **AI 지식 문서 초안**을 누릅니다.
3. 창에 **제목**과 본문 초안이 나옵니다. "AI 가 요청 본문·처리 코멘트로 요약한 초안입니다. 사실 여부를 확인한 뒤 등록하세요."
4. 내용을 고치고 **지식 문서 등록**을 누릅니다. 등록한 문서는 다음 요청부터 **비슷한 지식 문서 · 요청**에 추천됩니다.

> **참고** AI 없이 만들려면 **지식 문서로 만들기**를 누릅니다([서비스 요청 처리와 지식 문서](/user/pmsx/sr.md#지식-문서)).

## 비슷한 사례 추천

요청 상세의 **비슷한 지식 문서 · 요청**은 이 요청의 제목·내용과 글이 비슷한 지식 문서와, 처리가 끝난(처리 완료·고객 확인·종료) 과거 요청을 점수(%) 순으로 최대 5건 보여 줍니다. AI가 아니라 글자 유사도로 계산하므로 AI 설정과 상관없이 늘 나옵니다. 누르면 해당 문서나 요청으로 갑니다.

## 버튼·함수 설명 초안

<figure><img src="img/pmsx/u-ai-desc.png" alt="화면 분석 뷰어 오른쪽 '설명' 탭 — 근거 충분 표시, AI 초안 만들기·직접 작성 버튼"><figcaption>뷰어의 설명 탭 — 근거 등급과 초안 버튼</figcaption></figure>

As-Is 화면 분석 뷰어에서 버튼(요소)의 업무 설명을 만듭니다. 근거는 수집된 워크플로우(이벤트 → 함수 → SQL → 테이블)와 연결 신뢰도입니다.

1. 뷰어에서 캡처의 번호를 눌러 요소를 고르고, 오른쪽 **설명** 탭을 엽니다.
2. 맨 위 근거 등급을 봅니다. **근거 흐름**을 펼치면 근거가 된 흐름이 보입니다.

| 근거 등급 | 뜻 |
|---|---|
| 근거 충분 | 흐름이 테이블까지 이어지고 모든 연결 신뢰도 0.8 이상 |
| 근거 보통 | 확정되지 않은 저신뢰 연결이 있거나 흐름이 중간에서 끊김 |
| 근거 없음 | 연결된 처리 흐름이 없음 — 초안을 믿지 말고 화면 담당자에게 확인 |

3. **AI 초안 만들기**(AI가 꺼져 있으면 **흐름 요약 초안**)를 누릅니다. 초안이 만들어지고 출처 칩(**AI 초안** · **흐름 요약** · **직접 작성**)과 상태(**초안**)가 붙습니다.
4. **수정**으로 다듬고 **초안으로 저장**, 또는 **확정**을 누릅니다. 처음부터 쓰려면 **직접 작성**.

| 누가 | 할 수 있는 일 |
|---|---|
| PM·PL·분석 담당·개발자·품질 담당·운영 담당·협력사 | 초안 만들기·수정·초안으로 저장 |
| PM·PL·분석 담당 | **확정**, 확정된 설명 바꾸기·지우기 |

> **주의** AI 초안은 분석자가 확정한 뒤에 다른 사람에게 보입니다("AI 초안은 분석자가 확정한 뒤에 볼 수 있습니다."). 수집을 다시 해 흐름이 바뀌면 "초안을 만든 뒤 처리 흐름이 바뀌었습니다. 내용을 다시 확인하세요."가 뜹니다.

> **참고** 확정된 설명을 새 초안으로 바꾸면 다시 확정해야 합니다.

## 자주 묻는 질문

**Q. AI 버튼이 안 보여요.** 서버에서 AI가 꺼져 있습니다. 규칙 기반 기능(분류 추천·흐름 요약 초안·지식 문서로 만들기)은 그대로 씁니다. 켜야 하면 관리자에게 요청하세요.

**Q. 고객 정보가 AI로 나가나요?** AI는 회사 AX 플랫폼 게이트웨이로만 갑니다. 관리자가 데이터 등급을 `restricted`로 두면 게이트웨이가 사내(로컬) 모델만 씁니다.
