# DB · PL/SQL 분석과 산출물

> 수집한 테이블·DB 오브젝트(뷰·패키지·프로시저·트리거 등)와 화면 사이의 관계를 보고, 바꾸면 어디가 영향을 받는지 찾고, 화면정의서·테이블 정의서 같은 산출물을 내려받습니다. **대상**: 분석 담당·PM·PL·개발자·운영 담당. **메뉴**: As-Is 분석 › 테이블 정의서 · PL/SQL 분석 · ERD · CRUD 매트릭스 · 화면 이동 맵 · 영향도 분석 · 산출물 출력.

모든 화면은 오른쪽 위 **시스템**에서 분석 대상 시스템을 먼저 고릅니다.

## 테이블 정의서

<figure><img src="img/pmsx/u-db-tables.png" alt="테이블 정의서 — 왼쪽 테이블 목록의 CHAR·PL/SQL 참조·화면 배지, 오른쪽 TB_EMP 컬럼 탭"><figcaption>테이블 정의서 — 품질 배지가 붙은 목록과 TB_EMP 상세</figcaption></figure>

| 영역 | 하는 일 |
|---|---|
| **테이블명·코멘트** / **주제영역** | 목록을 거릅니다 |
| 목록 (테이블 · 주제영역 · 컬럼 · 사용 화면) | 테이블 이름 아래 코멘트와 품질 배지 |
| **테이블 정의서 엑셀** | 시스템의 테이블 정의서를 엑셀로 |
| 상세 머리 | **ERD에서 보기** · **영향도 분석** · **주제영역·코멘트 편집** |

품질 배지(마우스를 올리면 설명):

| 배지 | 뜻 |
|---|---|
| PK 없음 | 기본키가 없음. 중복 행·변경 추적 주의 |
| CHAR n | 고정길이 CHAR 컬럼 수 — 비교·이관 때 공백 주의 |
| 코멘트 없음 / 컬럼 코멘트 n/m 없음 | 테이블·컬럼 코멘트 누락 |
| PL/SQL 참조 n | 이 테이블을 읽거나 쓰는 프로시저·함수·트리거 수 |
| 화면 n | 이 테이블을 쓰는 화면 수 |

상세 탭:

| 탭 | 내용 |
|---|---|
| **컬럼** | 컬럼·타입·NULL·기본값·코멘트, PK·FK, 연결된 **표준용어** |
| **인덱스** · **관계** | 인덱스, FK와 추정 관계(부모/자식, 근거 SQL 수, 신뢰도). 권한이 있으면 **확정 · 기각 · 미결정으로** |
| **사용 화면·요소** | 이 테이블을 쓰는 화면·요소. 누르면 뷰어로 이동 |
| **확인할 화면** | 이 테이블을 바꾸면 확인할 화면을 **직접 SQL · 트리거 경유 · 간접(프로시저 경유)**로 나눠 보여 줌. **엑셀**로 내려받기 |
| **참조 오브젝트** | 이 테이블을 쓰는 트리거·뷰·패키지·프로시저 |
| **DDL** | 수집한 메타로 만든 DDL(원본 정의가 있으면 원본) |

**주제영역 정리하기** (PM·PL·분석 담당·개발자·운영 담당)

1. 테이블을 고르고 **주제영역·코멘트 편집**을 누릅니다.
2. 주제영역과 코멘트를 넣고 저장합니다. 목록의 `(미분류)`가 바뀌고, ERD에서 주제영역별로 볼 수 있습니다.

> **참고** "확인할 화면"은 테스트 범위를 정할 때 씁니다. 직접 SQL만 보면 놓치는, 트리거나 프로시저를 거쳐 같은 테이블에 닿는 화면까지 나옵니다.

## PL/SQL 분석

<figure><img src="img/pmsx/u-db-dbobjects.png" alt="PL/SQL 분석 — 종류별 건수 칩과 HR 계정 트리, 오른쪽 트리거 TRG_EMP_HIST의 원본 소스와 참조 관계"><figcaption>PL/SQL 분석 — 트리거 TRG_EMP_HIST를 고른 상태</figcaption></figure>

1. 왼쪽 위 **오브젝트 이름·코멘트 검색**에 이름을 넣거나, 종류 칩(**테이블 · 뷰 · 패키지 · 프로시저 · 함수 · 트리거 · 시퀀스 · 시노님**)으로 거릅니다.
2. 계정(스키마) › 종류 트리에서 오브젝트를 고릅니다.
3. 오른쪽에서 확인합니다.

| 오른쪽 영역 | 내용 |
|---|---|
| 정보 표 | 트리거는 **대상 테이블 · 시점·이벤트**(행 단위/문장 단위), 패키지는 **멤버**, 시퀀스는 **시퀀스 옵션**, 그리고 **위치**(파일) |
| **원본 소스** | 하이라이트된 소스, **복사**. 패키지는 **명세(SPEC)** · **본문(BODY)** |
| **참조하는 오브젝트** · **이 오브젝트를 참조하는 곳** | 관계 종류(접근·호출·트리거 발생 등)와 CRUD 배지 |
| 테이블일 때 | **테이블 정의서에서 보기** · **영향도 분석** |

프로시저·함수를 고르면 네 탭으로 읽습니다.

| 탭 | 내용 |
|---|---|
| **개요** | 파라미터, 저장·조회하는 테이블, 부르는 루틴, 이 루틴을 쓰는 화면 |
| **로직** | **순서도** · **의사코드** · **한국어 설명**. 줄 번호를 누르면 원본의 그 줄로 갑니다 |
| **점검** | 복잡도 지표, 업무 규칙 후보, 동적 SQL · 오류 삼킴 · 루틴 안 트랜잭션처럼 확인이 필요한 곳 |
| **소스·참조** | 원본 소스와 참조 관계 |

> **참고** "수집된 DB 오브젝트가 없습니다."가 보이면 수집기에 DDL 파일이나 DB 읽기 전용 접속을 넣고 다시 수집해야 합니다([As-Is 수집기 운영](/admin/pmsx/collector.md)).

## ERD

<figure><img src="img/pmsx/u-db-erd.png" alt="자동 배치된 ERD — 엔터티 분류 색, FK 실선과 추정 관계 점선, 관계 추가·PNG 저장 버튼"><figcaption>ERD — 점선은 SQL로 추정한 관계(확정 전)</figcaption></figure>

| 영역 | 하는 일 |
|---|---|
| **보기 기준** | **주제영역·테이블**(주제영역·**테이블 선택**으로 범위) 또는 **메뉴 기준**(메뉴 폴더 아래 화면들이 읽고 쓰는 테이블) |
| **추정 관계** / **기각 관계** | 추정 관계 점선, 기각한 관계를 보일지 |
| **다시 배치** · **관계 추가** · **PNG 저장** | 자동 배치, 수동 관계 추가, 그림 저장 |
| 범례 | 선: FK·확정(실선) · 추정(미확정) · 수동 · 기각. 엔터티 분류: 중심 · 기본 · 행위 · 코드 · 일반(이름·컬럼·관계 수로 추정한 참고용) |
| 왼쪽 아래 | 확대·축소·화면 맞춤, 오른쪽 아래 미니맵 |

**추정 관계 확정하기** (PM·PL·분석 담당·개발자·운영 담당)

1. 점선을 누르면 **관계** 창이 뜹니다(근거 SQL 수·신뢰도).
2. **확정** 또는 **기각**을 누릅니다. 되돌리려면 **미결정으로**.
3. 빠진 관계는 **관계 추가** → **자식 테이블** · **부모 테이블** · **컬럼 대응**을 넣고 저장합니다.

> **참고** 테이블은 한 번에 300개까지 그립니다. 많으면 주제영역이나 메뉴 기준으로 좁히세요.

## CRUD 매트릭스

<figure><img src="img/pmsx/u-db-crud.png" alt="CRUD 매트릭스 — 화면 행과 테이블 열의 C·R·U·D 표시"><figcaption>CRUD 매트릭스 — 화면 × 테이블</figcaption></figure>

1. **행 기준**을 **화면** 또는 **요소**로 고릅니다.
2. **메뉴**와 **테이블 이름 필터**로 범위를 좁힙니다. 위에 `5행 × 5테이블`처럼 크기가 보입니다.
3. 칸의 C·R·U·D는 등록·조회·수정·삭제입니다. 열 머리에는 테이블별 합계가 보입니다.

## 화면 이동 맵

<figure><img src="img/pmsx/u-db-navmap.png" alt="화면 이동 맵 — 화면 상자들과 팝업·이동 화살표"><figcaption>화면 이동 맵 — 화면을 누르면 뷰어가 열립니다</figcaption></figure>

- 화면 사이의 **팝업** · **이동** · **탭** 관계를 화살표로 봅니다. 화살표의 글자는 이동을 일으키는 함수입니다.
- **연결 없는 화면 숨김**으로 홀로 있는 화면을 뺍니다. **PNG 저장**으로 그림을 내려받습니다.

## 영향도 분석

<figure><img src="img/pmsx/u-db-impact.png" alt="영향도 분석 — 대상 TB_EMP, 영향 화면 5·영향 버튼·요소 18·API 13·최근 1년 요청 0, 화면별 경로와 코드 목록"><figcaption>영향도 분석 — 테이블 TB_EMP를 바꾸면 영향을 받는 화면과 경로</figcaption></figure>

1. **As-Is 분석 › 영향도 분석**을 엽니다. 테이블 정의서·PL/SQL 분석의 **영향도 분석** 버튼으로 와도 됩니다.
2. **대상 유형**(테이블 · 함수 · API · SQL · 프로시저)을 고르고 **대상**을 이름으로 찾습니다.
3. 테이블이면 **컬럼 (선택)**을 고를 수 있습니다. 고르면 그 컬럼을 쓰는 경로만 봅니다.
4. 결과를 확인합니다.

| 결과 | 내용 |
|---|---|
| 요약 | **영향 화면 · 영향 버튼·요소 · API · 최근 1년 요청** |
| **영향 화면** | 화면별로 버튼과 경로(버튼 → 함수 → API → 서버 → SQL → 테이블), CRUD 배지. **화면 뷰어**로 이동 |
| **코드** | API · 서버 함수 목록 |
| **배치·진입점** | 화면에서 부르지 않는 스케줄러·배치 진입점 |
| **최근 이력** | 관련 서비스 요청·결함 |
| **담당자** | 관련 담당자와 그 이유(이름 아래 작은 글씨) |

5. 오른쪽 위 **엑셀 내보내기**로 결과를 내려받습니다.

> **참고** 결과가 많으면 "결과가 많아 일부만 표시"가 뜹니다. 컬럼을 골라 좁히세요.

## 산출물 내보내기

<figure><img src="img/pmsx/u-db-export.png" alt="산출물 출력 — 화면정의서·프로그램 사양서·테이블 정의서·CRUD 매트릭스·인터페이스 목록 카드와 형식·대상 화면·고객사 템플릿 선택"><figcaption>산출물 출력</figcaption></figure>

| 산출물 종류 | 담기는 것 | 형식 |
|---|---|---|
| 화면정의서 | 화면당 1시트/1슬라이드 — 번호를 합성한 캡처 + 요소 표 + 이벤트 표 + 메모 | XLSX · PPTX |
| 프로그램 사양서 | 화면별 이벤트 → 핸들러 → API → 서버 함수 → SQL → 테이블(CRUD) | XLSX · PPTX |
| 테이블 정의서 | 테이블별 컬럼 표 + 관계 + 사용 화면 | XLSX |
| CRUD 매트릭스 | 화면 × 테이블 | XLSX |
| 인터페이스 목록 | API — 메서드·경로·서버 함수·호출 화면 | XLSX |

1. **As-Is 분석 › 산출물 출력**에서 시스템을 고릅니다.
2. **산출물 종류** 카드를 고릅니다.
3. **형식**(XLSX/PPTX)을 고릅니다.
4. 화면 단위 산출물은 **대상 화면**을 고릅니다: **전체 화면 (n개)** · **확정된 화면만 (n개)** · **직접 선택**(→ **화면 선택**).
5. 필요하면 **고객사 템플릿 (엑셀)**을 고릅니다. 없으면 **기본 양식**입니다.
6. **내려받기**를 누릅니다. 화면이 많으면 몇 분 걸립니다.

> **주의** 한 번에 300화면까지 출력합니다. 넘으면 "선택한 화면이 300개를 넘습니다."가 뜹니다.

> **참고** 고객사 엑셀 양식은 관리자가 [엑셀 양식 연결](/admin/pmsx/settings.md#엑셀-양식-연결)에 등록합니다.

## 현행 프로그램 대장

**As-Is 분석 › 현행 프로그램 대장**은 현행 시스템 프로그램을 업무 구조별로 정리하고 반영 유형(신규·변경·삭제·유지)과 설계 일감을 관리하는 목록입니다. **현행 화면 가져오기** · **엑셀 가져오기** · **엑셀 내보내기** · **프로그램 추가**를 씁니다.
