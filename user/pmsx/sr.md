# 서비스 요청 처리와 지식 문서

> SM 프로젝트에서 고객의 서비스 요청을 접수·분류·배정·처리하고, 처리 기한을 지키며, 해결 방법을 지식 문서로 남깁니다. 고객은 **고객 요청 창구**에서 요청을 등록하고 결과를 확인합니다. **대상**: 운영 담당·PM·PL(처리), 고객 담당자(요청). **메뉴**: 운영 (SM) › 서비스 요청(SR) · 지식 문서 · 처리 기한(SLA) 현황 / 고객: 고객 요청 창구.

| 영역 | 하는 일 |
|---|---|
| 머리 버튼 | **엑셀 내보내기** · **요청 등록**(PM·PL·운영 담당) |
| 필터 | **조회**(검색) · **상태 · 유형 · 우선순위 · 처리 기한**(임박·기한 초과) · **진행 중만** · **내 담당만** |
| 목록 | **번호 · 제목 · 상태 · 처리 기한**. 제목 아래 우선순위·유형·대상 화면. 🌐는 고객 요청 창구, ✉는 메일로 들어온 요청 |
| 상세 머리 | 번호·상태·우선순위·유형, **구현 명세**, **지식 문서로 만들기**·**AI 지식 문서 초안**(처리 완료 뒤), ✎ 수정 |
| 처리 기한 상자 | 남은 시간 또는 초과 시간, 적용 정책, **응답 기한 · 해결 기한**, 정지 시간 |
| 대상 화면 | 화면 이름과 **화면 뷰어에서 보기** |
| **처리 절차** | 업무 템플릿 체크리스트(**템플릿 고르기** → **시작**) |
| 분류·배정 추천 | **분류 추천** / **AI 분류 추천** — [AI 보조 기능](/user/pmsx/ai.md#서비스-요청-분류·배정-추천) |
| 상태 버튼 | 지금 상태에서 갈 수 있는 다음 단계 |
| **작업 공수** | 이 요청에 입력된 시간, **작업일지에 입력** |
| **비슷한 지식 문서 · 요청** | 비슷한 순서와 점수(%) |
| **처리 내역** | 코멘트 타임라인. 주황 점은 내부 메모 |
| **상태 변경 이력** · **첨부파일** | 펼쳐서 확인 / 파일 올리기 |

### 요청 상태

| 상태 | 다음 단계(버튼) |
|---|---|
| 접수 | **분류 완료** |
| 분류 | **담당 배정** (담당자 지정 필요) |
| 배정 | **처리 시작** |
| 처리 중 | **보류(고객 대기)** · **처리 완료** |
| 보류 | **처리 시작** |
| 처리 완료 | **고객 확인 처리** · **처리 시작**(재요청) |
| 고객 확인 | **종료** |
| 종료 · 반려 | 끝 |

종료 전 어느 단계에서든 **반려**할 수 있습니다.

### 처리 기한 표시

| 표시 | 뜻 |
|---|---|
| 정상 · "n시간 남음" | 기한 안 |
| 임박 | 기한이 가까움 |
| 기한 초과 · "n시간 n분 초과" | 해결 기한을 넘김 |
| 준수 · "기한 내 처리" | 기한 안에 처리 완료 |
| 일시정지 · "보류 중(시간 정지)" | 보류(고객 대기) 동안 시간이 멈춤 |

남은 시간은 1분마다 갱신됩니다. 기한은 업무시간·공휴일을 빼고 셉니다(정책은 관리자가 정함).

## 요청 접수하기

고객은 고객 요청 창구로, 메일·경보 연동이 있으면 자동으로도 들어옵니다. 전화 등으로 받은 요청은 직접 등록합니다.

1. **요청 등록**을 누릅니다.
2. **유형**(문의·개선·데이터 추출·장애·권한), **우선순위**(P1 긴급 ~ P4 낮음), **제목**, **요청 내용**을 넣습니다.
3. **요청자 이름 · 소속 · 연락처**를 넣습니다.
4. **대상 화면**의 **화면 선택**을 누르고 시스템·화면을 고릅니다. 특정 버튼 문제면 **버튼·요소 (선택)**까지 고르면 처리자가 워크플로우를 바로 봅니다.
5. PM·PL은 **담당자**도 지정할 수 있습니다. **저장**을 누릅니다.

## 요청 처리하기

1. 목록에서 요청을 누릅니다. **내 담당만**을 켜면 내 일만 남습니다.
2. **화면 뷰어에서 보기**로 대상 화면의 버튼 워크플로우를 확인합니다([As-Is 화면 분석](/user/pmsx/asis.md)).
3. **비슷한 지식 문서 · 요청**에서 과거 해결 방법을 찾습니다.
4. **처리 절차**에서 템플릿을 고르고 **시작** → 단계를 끝낼 때마다 체크합니다. 체크한 사람·시각이 기록됩니다.
5. 상태 버튼을 눌러 다음 단계로 보냅니다. 창에서 바뀌는 상태를 확인하고 코멘트를 남긴 뒤 확인합니다.

<figure><img src="img/pmsx/u-sr-transition.png" alt="처리 완료 상태 변경 창 — 처리 중 → 처리 완료, 코멘트 입력칸"><figcaption>상태 변경 창 — 바뀌는 상태와 코멘트</figcaption></figure>

6. **처리 내역 / 고객 안내 작성** 칸에 진행 상황을 쓰고 **추가**를 누릅니다. **내부 메모(고객에게 보이지 않음)**를 체크하면 고객 요청 창구에 보이지 않습니다.
7. 처리 시간은 **작업일지에 입력**에서 서비스 요청 대상으로 기록합니다.

> **주의** **반려**, **보류(고객 대기)**, 처리 완료 뒤 **처리 시작**(재요청)은 사유를 꼭 써야 합니다("사유 (필수)"). **담당 배정**은 담당자를 골라야 합니다.

> **참고** 운영 담당은 **본인 담당이거나 담당이 없는 요청**만 처리할 수 있습니다. 담당 배정은 PM·PL이 합니다.

## 처리 기한(SLA) 현황

<figure><img src="img/pmsx/u-sr-sla.png" alt="처리 기한(SLA) 현황 — 해결 준수율·응답 준수율·처리 기한 대상 요청·지금 임박 카드, 유형별 준수 차트, 기한 초과 요청 목록"><figcaption>처리 기한(SLA) 현황 — 월별 준수율과 임박·초과 요청</figcaption></figure>

1. **운영 (SM) › 처리 기한(SLA) 현황**을 엽니다.
2. 위에서 달을 고릅니다(**이전 달 · 다음 달**).
3. **해결 준수율 · 응답 준수율 · 처리 기한 대상 요청(준수 n · 초과 n) · 지금 임박**과 **유형별 준수**를 봅니다.
4. **기한 임박 요청** · **기한 초과 요청** 목록에서 요청을 누르면 상세로 갑니다.
5. **처리 기한 정책** 버튼은 정책 화면(관리)으로 갑니다.

## 지식 문서

<figure><img src="img/pmsx/u-sr-kb.png" alt="지식 문서 — 왼쪽 목록(제목·번호·태그), 오른쪽 '사원 저장 시 입사일 오류 대응' 본문"><figcaption>지식 문서 — 요청 처리 화면에서 비슷한 문서로 추천됩니다</figcaption></figure>

**찾기**: **운영 (SM) › 지식 문서**에서 **제목·내용·태그 검색**에 넣고 문서를 누릅니다. 원본 요청과 대상 화면이 있으면 **원본 요청**, **화면 뷰어에서 보기**로 이어집니다.

**처리한 요청에서 만들기** (PM·PL·운영 담당)

1. 상태가 처리 완료·고객 확인·종료인 요청을 엽니다.
2. **지식 문서로 만들기**를 누릅니다. 요청 내용으로 지식 문서 초안이 바로 등록되고, 지식 문서 화면이 수정 상태로 열립니다("지식 문서 초안을 만들었습니다. 내용을 다듬어 저장하세요.").
3. 증상·원인·해결 방법·확인 쿼리를 다듬고 **태그**(쉼표로 구분)를 넣어 **저장**합니다.

AI가 켜져 있으면 **AI 지식 문서 초안**으로 요약 초안을 받을 수 있습니다([AI 보조 기능](/user/pmsx/ai.md#지식-문서-초안)).

**직접 쓰기**: **지식 문서 작성** → 제목·내용·태그 → **저장**. 고치기는 ✎, 지우기는 🗑.

## 고객 요청 창구 — 고객용

고객 역할만 있는 계정으로 로그인하면 이 화면만 보입니다.

<figure><img src="img/pmsx/u-sr-portal.png" alt="고객 요청 창구 — 인사말, 새 요청 버튼, 내 요청 목록(번호·제목·상태·요청일)"><figcaption>고객 요청 창구 — 내 요청과 진행 상태</figcaption></figure>

**새 요청 등록**

<figure><img src="img/pmsx/u-sr-portal-new.png" alt="새 요청 창 — 요청 유형, 제목, 내용, 관련 화면(선택)과 화면 선택 버튼"><figcaption>새 요청 — 어떤 화면에서 무엇을 하다가 어떤 결과가 나왔는지 적습니다</figcaption></figure>

1. **새 요청**을 누릅니다.
2. **요청 유형**, **제목**, **내용**을 넣습니다.
3. 관련 화면을 알면 **화면 선택**으로 고릅니다(선택).
4. **요청 등록**을 누릅니다.

**진행 확인과 답변**

<figure><img src="img/pmsx/u-sr-portal-detail.png" alt="고객 요청 상세 — SR-0017 처리 중, 담당 서운영, 진행 내역과 추가 문의 입력칸, 첨부파일"><figcaption>요청 상세 — 담당자 답변과 추가 문의</figcaption></figure>

1. **내 요청**에서 요청을 누릅니다(**조회** · **상태**로 거르기).
2. **진행 내역**에서 담당자 안내를 읽습니다. 내부 메모는 보이지 않습니다.
3. 더 물을 것이 있으면 **추가 문의 / 답변**에 쓰고 **보내기**를 누릅니다. 파일은 **첨부파일**로 올립니다.
4. 처리가 끝나면(처리 완료) 결과를 확인하고 **확인 (종료)**를 누릅니다. 남은 문제가 있으면 **재요청**을 누르고 **남은 문제 / 재요청 사유**를 씁니다.

> **참고** 처리 완료되어 확인을 기다리는 요청이 있으면 목록 위에 "처리 완료되어 확인을 기다리는 요청이 n건 있습니다."가 보입니다. 참여 중인 운영 프로젝트가 없으면 담당자에게 문의하세요.

## 운영 (SM)의 다른 메뉴

| 메뉴 | 하는 일(화면 안내 문구) |
|---|---|
| 장애 | 장애 등급·타임라인·영향 범위·원인 분석(RCA)·재발 방지 대책. 위쪽에 모니터링 경보 목록 |
| 문제 | 반복되는 요청·장애를 묶어 근본 원인 추적. 같은 화면·비슷한 제목 3건 이상이면 문제 후보 |
| 변경·배포 | 변경 요청 → CAB 승인 → 배포 → 종료. 목록·캘린더 |
| 정기 작업 | 정기 점검·백업 확인·월마감 같은 반복 작업을 달력에서 체크 |
| 운영 자산 | 서버·계정·인증서·라이선스·도메인 대장. 만료 30·7·1일 전 알림 |
| 월간 운영보고 | 요청·처리 기한·장애·변경·공수 자동 집계, 총평·다음 달 계획 작성 |
| 업무 템플릿 | 요청 유형별·장애·변경 처리 절차 체크리스트(편집: PM·PL·운영 담당) |
| 인수인계 퀴즈 | [인수인계와 구현 명세](/user/pmsx/handover.md#인수인계-퀴즈) |

## 자주 묻는 질문

**Q. 상태 버튼이 안 보여요.** 다른 사람이 담당인 요청이거나(운영 담당), 종료·반려된 요청입니다.

**Q. 기한이 주말에도 줄어요.** 그 요청에 24×7 정책(예: P1 긴급)이 적용된 경우입니다. 상세의 처리 기한 상자에서 정책 이름을 확인하세요.
