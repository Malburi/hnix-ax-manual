# As-Is 화면 분석

> 수집기가 분석한 레거시 화면을 캡처 그대로 보고, 버튼 하나가 어떤 함수 → API → 서버 → SQL → 테이블로 이어지는지 따라갑니다. 비교(To-Be)가 아니라 **현행 화면을 읽는 뷰어**입니다. **대상**: 분석 담당·PM·PL·개발자·품질 담당·운영 담당·협력사(허용 범위). **메뉴**: As-Is 분석 › 화면 분석 뷰어 · 분석 진척 현황.

## 화면 구성

<figure><img src="img/pmsx/u-asis-viewer.png" alt="화면 분석 뷰어 — 왼쪽 메뉴 트리, 가운데 사원관리 화면 캡처와 번호 핫스팟, 오른쪽 저장 버튼의 워크플로우(fn_save → POST /hr/emp/save.do → EmpController → SQL → TB_EMP)"><figcaption>화면 분석 뷰어 — 캡처에서 11번 [저장] 버튼을 고른 상태</figcaption></figure>

| 영역 | 하는 일 |
|---|---|
| **시스템** (왼쪽 위) | 분석 대상 시스템을 고릅니다. 예: 인사시스템 (HR) |
| 검색칸 `화면·버튼·함수·테이블` | 화면·요소·함수·테이블을 이름으로 찾습니다 |
| 메뉴 트리 | 레거시 시스템의 메뉴 구조. 화면 이름 옆 점 색이 분석 상태입니다. 팝업은 부모 화면 아래에 들어 있습니다 |
| 분석 진척 (왼쪽 아래) | `인사시스템 분석 진척 2/6 화면 (33%)`처럼 확정된 화면 비율 |
| 열린 화면 탭 | 연 화면이 탭으로 쌓입니다. 브라우저 탭을 닫으면 사라집니다 |
| **기본 · 상하분할 · 드로어** | 화면 배치. 기본은 3단, 상하분할은 상세를 캡처 아래에, 드로어는 상세를 오른쪽에서 밀어 냅니다 |
| 화면 머리 | 화면명·화면 ID·상태 칩, 메뉴 경로, 화면 기술, 소스 파일, **담당**·**검토**, 캡처 회차·일시, **편집 모드**, **첨부** |
| 화면 요약 줄 | `조회+입력` 같은 화면 성격과 한 줄 설명, **이벤트 n · SQL n · 쓰기 n·읽기 n 테이블 · 프로시저 n** |
| 가운데 탭 | **캡처 · 컴포넌트 목록 · 이벤트 목록 · CRUD · 코드 순서도 · 통합 추적 · 데이터 흐름도 · 한국어 설명 · 트리거** |
| 오른쪽 상세 | 고른 요소의 정보와 **워크플로우 · 사용 테이블 · 메모 · 설명 · 연결 이력** 탭. 요소를 고르지 않으면 **화면 정보**(화면 메모 · 분석 이력) |

### 분석 상태

| 상태 칩 | 뜻 |
|---|---|
| 자동수집 | 수집기가 올린 그대로 |
| 분석중 | 담당자가 보정 중 |
| 검토요청 | 분석자가 PM·PL에게 확인 요청 |
| 확정 | PM·PL이 확정. 산출물 출력의 "확정(DONE) 화면만" 대상 |

## 화면 찾기

<figure><img src="img/pmsx/u-asis-search.png" alt="뷰어 왼쪽 검색칸에 '저장'을 넣어 나온 화면·버튼 결과 목록"><figcaption>뷰어 검색 — 결과를 누르면 그 화면(과 요소)이 열립니다</figcaption></figure>

1. **As-Is 분석 › 화면 분석 뷰어**를 엽니다.
2. 왼쪽 위 **시스템**을 고릅니다.
3. 메뉴 트리에서 화면을 누르거나, 검색칸에 화면명·화면 ID·버튼 라벨·함수명·테이블명을 넣습니다.
4. 검색 결과를 누르면 그 화면이 열립니다. 버튼 결과는 화면이 열리면서 그 버튼이 선택됩니다.

> **참고** 함수·테이블 결과 중 특정 화면에 묶이지 않은 것은 흐리게 보이고 누를 수 없습니다. 테이블은 [영향도 분석](/user/pmsx/db.md#영향도-분석)이나 [테이블 정의서](/user/pmsx/db.md#테이블-정의서)에서 보세요.

> **참고** 다른 화면에서 바로 뷰어로 올 수도 있습니다 — 서비스 요청의 **화면 뷰어에서 보기**, 영향도 분석의 **화면 뷰어**, 화면 이동 맵의 화면 상자.

## 캡처에서 버튼 워크플로우 보기

1. 화면을 열면 **캡처** 탭에 실제 화면 그림과 번호(핫스팟)가 보입니다.
2. 번호를 누르면 오른쪽에 그 요소의 **요소 ID · 바인딩 · 이벤트 · 좌표**와 **워크플로우**가 나옵니다.
3. 워크플로우는 위에서 아래로 **화면 → 프론트 → API → 서버 → SQL → 테이블** 순서입니다. 연결마다 **신뢰도**와 출처(정적·동적·수동)가 붙습니다.
4. 단계를 누르면 아래에 그 노드의 **소스**, **호출 트리**(호출하는 대상 / 호출하는 곳), **사용처**(이 노드를 쓰는 화면·요소)가 나옵니다. `</>` 표시가 있는 단계는 소스가 있습니다.
5. 이벤트가 여러 개인 요소는 워크플로우 위 칩(예: `click`, `change`)으로 이벤트를 바꿉니다.

### 캡처 표시 옵션

| 옵션 | 하는 일 |
|---|---|
| 범례 (버튼·입력·콤보·그리드·팝업호출) | 요소 종류별 색 |
| 요소 순번 / 이벤트·워크플로우 있음 | 번호 배지와, 흐름이 연결된 요소 표시 |
| **버튼만** | 버튼 번호만 표시 |
| **번호 숨김** | 번호를 모두 숨김 |
| **컨트롤 ID 표시** | 번호 대신 소스의 컨트롤 ID 표시 |
| **화면 맞춤 / 원본 크기** | 캡처 크기 |
| 원본 숨김 컨트롤 (n) | 원본 화면에 보이지 않는 컨트롤 목록. 캡처에는 없지만 흐름은 분석되어 있습니다 |

| 캡처 표시 | 뜻 |
|---|---|
| 점선 핫스팟 · "핸들러 미매칭" | 캡처에서는 찾았지만 소스에서 이벤트 핸들러를 못 찾은 요소 |
| "캡처에 없음" | 소스에는 있지만 화면에 보이지 않는 요소(숨김 필드 등) |
| 점선 연결 | 신뢰도 90% 미만이고 아직 사람이 확정하지 않은 연결 |
| **와이어프레임** | 실제 캡처가 아니라 소스 좌표로 그린 그림(Nexacro 등) |
| **정적 렌더링** | 서버 없이 JSP를 HTML로 바꿔 그린 그림. 조회 데이터·콤보 값은 비어 있음 |
| ⚠ 위험 버튼 · 동적 클릭 제외 | 저장·삭제 같은 버튼이라 수집 때 누르지 않음(정적 분석만) |

### 오른쪽 상세 탭

| 탭 | 내용 |
|---|---|
| **워크플로우** | 위의 버튼 흐름 |
| **사용 테이블** | 이 요소가 쓰는 테이블과 CRUD, 컬럼. 테이블을 누르면 상세 |
| **그리드 컬럼** | 그리드 요소에만. 머리글·필드·폭·표시·편집 여부, 원본 비표시 열 |
| **메모** | 이 요소의 업무 규칙 메모(Markdown) |
| **설명** | 버튼·함수 설명 초안과 확정본 — [AI 보조 기능](/user/pmsx/ai.md#버튼·함수-설명-초안) |
| **연결 이력** | 이 요소에 등록된 결함·이슈, 요구사항 추적 링크. **이 요소에 결함 등록** · **이슈 등록** 버튼 |

| **트리거** | 이 화면의 등록·수정·삭제가 일으키는 DB 트리거와 연쇄(최대 5단계) |

카드나 행을 누르면 그 요소가 캡처에서 선택됩니다.

## 분석 보정하기 (편집 모드)

화면 머리의 **편집 모드**는 PM·PL·분석 담당(본인 담당 또는 미배정 화면)·개발자·운영 담당·협력사에게 보입니다.

1. **편집 모드**를 누릅니다. 캡처 위에 안내가 뜹니다.
2. 할 일에 따라 고칩니다.
   - 새 요소: 캡처의 빈 곳을 드래그 → **요소 ID · 라벨 · 타입 · 바인딩**을 넣고 **저장**. 요소 ID를 소스의 id와 같게 적으면 재수집 때 연결됩니다.
   - 위치·크기: 요소를 끌어 옮기고, 모서리 핸들로 크기를 바꿉니다.
   - 숨기기: 오른쪽 상세의 눈 아이콘. 숨긴 요소는 **숨긴 요소 표시**에서 복원합니다. 직접 추가한 요소는 숨기기 대신 삭제됩니다.
   - 캡처 교체: **수동 캡처 업로드**로 PNG·JPG를 올립니다(와이어프레임이거나 캡처가 없을 때).
3. 연결 보정은 **워크플로우** 탭에서 합니다.
   - 단계 사이의 ⋮(**연결 보정**) → **확정** · **기각** · **조건·CRUD 편집**. 직접 추가한 연결만 **연결 삭제**가 됩니다.
   - 빠진 연결: **이 요소에서 연결 추가** 또는 단계 아래 **여기서 연결 추가** → **연결 종류**, **연결 대상**(기존 노드 검색 또는 새 노드)을 고르고 저장.
4. 다 고쳤으면 **편집 끝내기**를 누릅니다.

> **참고** 수동 보정(요소·연결·메모·확정)은 수집 결과를 다시 올려도 유지됩니다.

## 메모 남기기와 상태 바꾸기

1. 요소의 **메모** 탭, 또는 요소를 고르지 않은 상태의 **화면 메모** 탭에서 **메모 작성**을 누릅니다.
2. 업무 규칙·예외·확인할 점을 Markdown으로 쓰고 저장합니다(20,000자까지).
3. 화면 머리의 상태 칩 옆 ▾를 눌러 **분석 상태 변경**을 엽니다.
4. **분석중** 또는 **검토요청**을 고릅니다. 검토요청이면 **검토자**(PM·PL)와 **코멘트**를 넣습니다.
5. PM·PL이 확인하고 **확정**으로 바꿉니다.

> **주의** **확정**은 PM·PL만 할 수 있습니다. 분석 담당은 본인 담당이거나 담당이 없는 화면만 편집할 수 있습니다.

**담당 배정** (PM·PL)

1. 화면 목록에서 화면을 여러 개 체크합니다.
2. **담당 배정**을 누릅니다.
3. **담당자**와 **검토자**를 고르고 저장합니다. 비워 두면 지정이 해제됩니다.

> **참고** 배정받은 사람에게는 "작업 배정" 알림이 갑니다. 화면 분석 작업은 [작업 배분](/user/pmsx/resource.md#작업-배분)에서도 배정할 수 있습니다.

## 자주 묻는 질문

**Q. 메뉴 트리가 비어 있어요.** "메뉴가 없습니다. 수집 결과를 먼저 업로드하세요."가 보이면 아직 수집 결과가 없습니다. 분석 담당이나 관리자가 [수집 결과를 올려야](/admin/pmsx/collector.md) 합니다.

**Q. 캡처가 없다고 나와요.** 테스트계 접속이 안 되었거나 수동 캡처를 기다리는 화면입니다. 편집 모드의 **수동 캡처 업로드**로 올리세요.

**Q. 협력사인데 일부 시스템만 보여요.** 협력사 인력은 PM이 정한 **열람 범위**의 시스템·메뉴만 봅니다.
