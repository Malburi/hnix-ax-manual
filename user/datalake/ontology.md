# 온톨로지 — 업무 객체 보기

> 테이블을 **업무 객체**(장애·서비스·구성 요소·변경·담당자…)로 보고, SQL 없이 관계를 따라갑니다. 예: 이 장애 → 같은 구성 요소의 직전 72시간 변경 → 그 변경의 요청자. 객체에 메모를 남기거나 진단 에이전트를 부르는 **액션**도 실행합니다. **대상**: 분석가, 운영 담당, 데이터 엔지니어. **메뉴**: 데이터 › 객체 탐색.

## 화면 구성

<figure><img src="img/datalake/u-ontology.png" alt="객체 탐색 — 왼쪽 유형 버튼(구성 요소·담당자·문제·변경·서비스·서비스 요청·장애)과 장애 목록, 오른쪽 장애 INC-0300 회원 접속 오류의 속성 표, 관계 버튼 5개, '직전 72시간 변경' 을 눌러 나온 변경 CHG-0200 WAS 패치, 위 오른쪽 진단 메모 남기기·진단 에이전트 요청(승인) 버튼"><figcaption>장애 INC-0300 을 열고 <b>직전 72시간 변경</b> 관계를 누른 모습.</figcaption></figure>

| 영역 | 하는 일 |
|---|---|
| 탭 | **객체 탐색** · **실행 요청** (엔지니어·관리자에게는 **정의** 탭이 더 있음) |
| 유형 버튼 | 객체 유형(색 점 + 이름). 누르면 그 유형의 객체를 찾습니다 |
| 찾기 칸 | `장애 이름·키로 찾기` — `Enter` 로 찾고, X 로 지우면 다시 전체 |
| 결과 목록 | `키 이름` 과 요약 속성. 100건까지 보입니다 |
| 객체 카드 머리 | 유형 꼬리표, 키, 이름, 오른쪽에 쓸 수 있는 **액션** 버튼 |
| 카드 탭 | **속성·관계** · **관계 그래프** |

> **참고** 객체도 테이블과 **같은 규칙**을 따릅니다. 행 제한으로 못 보는 행은 객체로도 안 보이고, 가린 열은 속성에서도 가려집니다(예 담당자 이름 `박*호`). 볼 수 있는 유형이 없으면 `볼 수 있는 객체 유형이 없습니다.` 가 나옵니다 — 관리자에게 온톨로지 테이블의 조회 권한을 요청합니다.

## 객체 찾고 열기

1. 왼쪽 메뉴 **객체 탐색**을 누릅니다.
2. 위의 유형 버튼(예 **장애**)을 누릅니다. 목록에 그 유형의 객체가 나옵니다.
3. 좁히려면 찾기 칸에 이름이나 키 일부(예 `접속`, `INC-03`)를 넣고 `Enter`.
4. 목록에서 객체를 누릅니다. 오른쪽에 카드가 열립니다.

> **참고** 지금 보는 유형·객체는 주소창에 남습니다(`/ontology?type=incident&key=INC-0300`). 주소를 동료에게 보내면 같은 객체가 열립니다(그 사람이 볼 수 있는 경우).

## 속성과 관계 따라가기

**속성·관계** 탭에서:

1. 위 표에서 객체의 속성(예 등급·상태·발생·해결·소속·서비스·구성 요소·담당자)을 봅니다.
2. **관계** 아래 버튼을 봅니다. 버튼마다 `관계 이름 · 상대 유형 · 개수` 가 적혀 있습니다(예 `직전 72시간 변경 변경 1`). 개수가 0 이면 누를 수 없습니다.
3. 버튼을 누르면 아래에 `직전 72시간 변경 — 변경 1건` 과 상대 객체 표(**키 · 이름 · 속성**)가 나옵니다.
4. 표의 **열기**를 누르면 그 객체로 넘어갑니다. 이렇게 관계를 따라 계속 이동합니다.
5. 객체에 남긴 메모가 있으면 맨 아래 **메모**에 시각·작성자와 함께 보입니다.

| 장애 객체의 관계 예(ITO 표준) | 따라가면 |
|---|---|
| 담당자 | 장애 담당자 |
| 발생 구성 요소 | 장애가 난 서버·DB·WAS |
| 근본 문제 | 연결된 문제 |
| 직전 72시간 변경 | 같은 구성 요소에서 장애 직전 72시간 안에 끝난 변경 |
| 영향 서비스 | 영향을 받은 서비스 |

관계 이름과 조건은 관리자가 정의합니다([온톨로지 정의](/admin/datalake/ontology.md)).

## 관계 그래프

<figure><img src="img/datalake/u-ontology-graph.png" alt="관계 그래프 탭 — 가운데 장애 '회원 접속 오류' 노드에서 오른쪽으로 담당자 박*호, 구성 요소 member-l4-01, 문제 회원 배치 지연 누적, 변경 WAS 패치, 서비스 회원으로 이어진 그래프와 1단계·2단계 버튼"><figcaption>관계 그래프 1단계. 담당자 이름은 가린 값으로 보입니다.</figcaption></figure>

1. 카드에서 **관계 그래프** 탭을 누릅니다.
2. **1단계**(바로 이어진 것) 또는 **2단계**(한 번 더 건너간 것)를 고릅니다.
3. 왼쪽은 이 객체를 가리키는 것, 오른쪽은 이 객체가 가리키는 것입니다. 선 위에 관계 이름이 적힙니다.
4. 노드를 누르면 그 객체로 갑니다. 끌어서 옮기고 휠로 확대하며, **맞춤**으로 다시 화면에 맞춥니다.

관계가 많으면 `(일부만 — 관계마다 개수를 줄였습니다)` 가 붙습니다.

## 액션 실행

객체 카드 오른쪽 위 버튼이 그 객체에 쓸 수 있는 액션입니다. 관리자가 내 역할에 허용한 액션만 보입니다.

| 액션 방식 | 하는 일 |
|---|---|
| 메모 | 객체에 메모를 남깁니다. **원본 데이터는 바꾸지 않습니다** |
| 웹훅 | 지금 보이는 이 객체의 속성(가린 값은 가린 채)과 입력을 외부(플랫폼 에이전트·ITSM·메신저)로 보냅니다 |

버튼 이름 끝에 `(승인)` 이 붙은 액션은 엔지니어·관리자의 승인 뒤에 실행됩니다.

<figure><img src="img/datalake/u-ontology-action.png" alt="진단 메모 남기기 창 — 설명 '확인한 내용·추정 원인을 장애에 남긴다. 원본 데이터는 바꾸지 않는다.', 메모 입력칸(필수), 실행 버튼"><figcaption>액션 창. 별표(*)가 붙은 칸은 꼭 채웁니다.</figcaption></figure>

1. 객체를 열고 액션 버튼(예 **진단 메모 남기기**)을 누릅니다.
2. 창의 설명을 읽고 입력 칸을 채웁니다. 별표(*)는 필수입니다.
3. 웹훅 액션이면 `지금 보이는 이 객체의 속성(가린 값은 가린 채)과 입력을 보냅니다.` 안내가 보입니다.
4. 버튼을 누릅니다 — 승인이 필요 없으면 **실행**, 필요하면 **요청**.
5. 결과는 **실행 요청** 탭에서 봅니다.

> **주의** 요청한 사람은 자기 요청을 스스로 승인할 수 없습니다. 에이전트가 요청한 웹훅도 사람이 승인해야 나갑니다.

## 실행 요청 — 내가 한 요청 보기

<figure><img src="img/datalake/u-ontology-runs.png" alt="실행 요청 탭 — '실행 요청' 카드 제목 오른쪽에 상태 전체 고르기·새로 고침, 표에 요청 시각, 액션 '진단 에이전트 요청', 대상 장애 INC-0300·INC-0241, 입력, 요청자·경로(화면/에이전트), 상태 보냄, 결과 '보냄 — 상대가 받아 실행을 시작함(응답 202)'"><figcaption>분석가에게는 내가 한 요청만 보입니다.</figcaption></figure>

| 열 | 내용 |
|---|---|
| **요청 시각** · **액션** | 언제 어떤 액션을 |
| **대상** | `유형 키 — 이름`. 누르면 객체 탐색에서 그 객체를 엽니다 |
| **입력** | 액션 창에 넣은 값 |
| **요청** | 요청자 · 경로(**화면** · **API** · **에이전트**) |
| **상태** | **승인 대기** · **실행 중** · **완료** · **실패** · **거절**. 웹훅 액션이 끝나면 **보냄** |
| **결과** | 웹훅 결과 요약(예 `보냄 — 상대가 받아 실행을 시작함(응답 202)`), 오류, 거절 사유, 또는 `승인 <이름>` |

- **실행 요청** 카드 제목 오른쪽의 `상태 전체` 칸으로 상태를 거르고, **새로 고침**으로 다시 읽습니다.
- 엔지니어·관리자에게는 다른 사람의 **승인 대기** 줄에 **승인·실행** / **거절** 버튼이 보입니다([온톨로지 정의](/admin/datalake/ontology.md)).

## AI 에이전트에서 쓰기

같은 객체를 AI 에이전트도 MCP 도구(`ontology_types` · `find_objects` · `get_object` · `linked_objects` · `propose_action`)로 씁니다. 에이전트는 키 주인과 같은 권한·가림이 걸리고, 웹훅 액션은 사람 승인 뒤에 나갑니다.
