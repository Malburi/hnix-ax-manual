# 계보와 영향 범위

> 데이터가 어디서 와서(원본 DB·Kafka 토픽·파일) 어떤 레이크 테이블·뷰를 거쳐 어디서 쓰이는지(객체 유형·화면·API·에이전트·AI 질문) 한 그림으로 봅니다. 노드를 고르면 **영향 범위** — 이것이 바뀌면 함께 확인할 곳이 나옵니다. **대상**: 분석가, 데이터 엔지니어, 원본 시스템 담당. **메뉴**: 데이터 › 계보.

## 화면 구성

<figure><img src="img/datalake/u-lineage.png" alt="계보 화면 — 위에 종류별 개수 꼬리표(Kafka 토픽 1, 파일 2, 레이크 테이블 12, 객체 유형 7, 소비 경로 3), 소비 경로 체크, 노드 찾기 칸, 새로 고침, 가운데 층 그래프에서 ito.incident 를 고른 모습, 오른쪽 칸에 어디서 왔나 0, 영향 범위 3(장애 · 업무 객체, 에이전트(MCP) · 조회, 화면 조회 · 조회)과 최근 실행"><figcaption><code>ito.incident</code> 를 고른 계보. 위·아래로 이어진 노드만 진하게 보이고 오른쪽에 영향 범위가 나옵니다.</figcaption></figure>

| 영역 | 하는 일 |
|---|---|
| **데이터 흐름** 꼬리표 | 종류별 노드 개수(색 점은 그래프의 색과 같음) |
| **소비 경로(최근 30일 조회)** | 켜면 화면·API·에이전트·AI 질문 같은 조회 경로까지 그립니다 |
| `노드 찾기 — 테이블·원본·토픽` | 이름으로 노드를 골라 그 노드로 갑니다 |
| **새로 고침** | 계보를 다시 읽습니다 |
| 그래프 | 왼쪽(원본) → 오른쪽(소비) 층 그래프. 끌어서 옮기고 휠로 확대, **맞춤**으로 화면에 맞춤 |
| 오른쪽 칸 | 고른 노드의 종류, **카탈로그에서 열기**(또는 **객체 탐색에서 열기**), **어디서 왔나**, **영향 범위 — 어디로 가나**, **최근 실행** |

### 노드 종류

| 종류 | 예 |
|---|---|
| **원본 DB** | 원본 연결(Oracle·SQL Server·PostgreSQL·REST API 등) |
| **Kafka 토픽** · **HTTP 입구** | 실시간 수집이 받는 곳 |
| **파일** | 파일 수집으로 올린 파일, 문서 폴더 |
| **레이크 테이블** · **뷰** | 레이크 안의 테이블과 뷰 |
| **객체 유형** | 온톨로지의 업무 객체(장애·변경 등) |
| **소비 경로** | 화면 조회, API, 에이전트(MCP), AI 질문 |

### 선(이어진 방식)

| 선 글자 | 뜻 |
|---|---|
| 동기화 | 원본 연결의 동기화로 옮김 |
| 스트림 | 실시간 수집 |
| 파일 적재 · 문서 수집 | 파일 수집, 문서 묶음 |
| 뷰 정의 | 뷰가 읽는 테이블 |
| 작업 SQL | 엔지니어의 `CREATE TABLE AS`·`INSERT…SELECT`·`MERGE` 가 읽은 테이블 → 쓴 테이블 |
| 업무 객체 | 테이블을 객체 유형으로 봄 |
| AI 추출 | 문서 → 표(AI)로 문서 묶음에서 뽑은 테이블 |
| 조회 | 최근 30일 조회(점선) — 소비 경로를 켰을 때 |

## 영향 범위 보기

1. 왼쪽 메뉴 **계보**를 누릅니다. 카탈로그의 **계보 보기**로 들어오면 그 테이블이 골라진 채 열립니다.
2. 그래프에서 노드를 누르거나, 위의 노드 찾기 칸에서 이름(예 `ito.incident`)을 고릅니다.
3. 그 노드의 위·아래로 이어진 노드만 진하게 남고 나머지는 흐려집니다.
4. 오른쪽 칸을 읽습니다.

   | 칸 | 내용 |
   |---|---|
   | **어디서 왔나** | 이 노드로 들어오는 곳. 단계마다 안쪽으로 들여 쓰고 `· 동기화` 처럼 방식이 붙습니다. 없으면 `처음 들어오는 곳입니다.` |
   | **영향 범위 — 어디로 가나** | 이 노드에서 나가는 곳 전부. 없으면 `여기서 끝납니다.` |
   | 노란 안내 | 원본·테이블이면 `이 테이블의 구조가 바뀌면 아래 3곳을 함께 확인하세요.` |
   | **최근 실행** | 그 노드에 걸린 최근 동기화·조회 등(예 `화면 조회 84회 · 3명 · 2026-11-07 13:47:13`) |

5. 오른쪽 칸의 다른 노드 이름을 누르면 그 노드로 옮겨 갑니다.
6. **카탈로그에서 열기**로 그 테이블의 상세를, 객체 유형이면 **객체 탐색에서 열기**로 객체 화면을 엽니다.

지금 고른 노드는 주소창(`/lineage?node=lake:ito.incident`)에 남아 동료에게 그대로 보낼 수 있습니다.

## 이럴 때 씁니다

| 상황 | 보는 방법 |
|---|---|
| 원본 DB 의 컬럼을 바꾸려 한다 | 원본 노드를 골라 **영향 범위**의 테이블·뷰·객체 유형·소비 경로를 확인합니다 |
| 이 숫자가 어디서 왔는지 모르겠다 | 테이블을 골라 **어디서 왔나**를 원본까지 따라갑니다 |
| 이 테이블을 지워도 되나 | 소비 경로를 켜고, 최근 30일에 누가(화면·API·에이전트) 읽었는지 봅니다 |
| 실시간 수집이 멈췄다 | 토픽 노드의 **영향 범위**로 영향받는 테이블·객체를 압니다 |

## 볼 수 있는 범위

- 분석가는 **볼 수 있는 테이블 둘레만** 봅니다. 권한이 없는 테이블과 그 위·아래는 그려지지 않습니다.
- 계보는 동기화·스트림·파일 적재·문서 수집·뷰 정의·온톨로지 정의·작업 SQL 실행·최근 30일 조회 기록에서 그때그때 만듭니다. 아직 아무것도 이어지지 않았으면 `아직 이어진 데이터가 없습니다.` 가 나옵니다.
- AI 에이전트는 MCP 도구 `table_lineage` 로 같은 계보를 조회합니다.

> **참고** 계보는 "누가 어디서 읽었나"까지 보여 주지만 값은 보여 주지 않습니다. 값은 카탈로그·SQL 작업창에서 권한대로 봅니다.
