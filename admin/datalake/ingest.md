# 수집 — 파일 · 원본 연결 · 실시간

> 업무 데이터를 레이크로 들입니다. 파일을 올리고, 업무 DB·Snowflake·REST API·공유 폴더를 주기적으로 동기화하고, Kafka·HTTP 이벤트를 실시간으로 받고, Word·PDF·한글 문서를 개인정보를 가려 넣습니다. **대상**: 데이터 엔지니어, 관리자. **메뉴**: 수집 › 파일 수집 · 원본 연결 · 실시간 수집, 데이터 › 문서 수집.

| 할 일 | 엔지니어 | 관리자 |
|---|---|---|
| 파일 수집 | ○ | ○ |
| 원본 연결 **추가·고치기·삭제** | — | ○ |
| 원본 연결 **연결 시험**, 동기화 만들기·실행·고치기·삭제 | ○ | ○ |
| 스트림 만들기·시작·멈추기·고치기·삭제 | ○ | ○ |
| 문서 묶음 **만들기·고치기·삭제** | — | ○ |
| 문서 묶음 실행·파일 올리기·파일 목록 | ○ | ○ |

수집한 테이블과 그 출처는 모두 [계보](/user/datalake/lineage.md)에 자동으로 나타납니다.

## 파일 수집

<figure><img src="img/datalake/a-ingest.png" alt="파일 수집 화면 — 1. 파일 올리기 끌어 놓기 칸(CSV·TSV·Excel·Parquet·JSON·NDJSON, EUC-KR 자동 변환)과 수집 기록 표(시각·파일·테이블·방식·행·결과)"><figcaption>파일 수집. 파일을 올리면 '2. 확인하고 넣기' 칸이 나타납니다.</figcaption></figure>

1. 왼쪽 메뉴 **파일 수집**을 누릅니다.
2. **1. 파일 올리기** 칸에 파일을 끌어다 놓거나 눌러서 고릅니다. CSV·TSV·Excel(XLSX)·Parquet·JSON·NDJSON 을 받습니다. EUC-KR(CP949) CSV 는 자동으로 UTF-8 로 바꿔 읽습니다(`EUC-KR → UTF-8` 꼬리표).
3. **2. 확인하고 넣기** 에서 열 수와 앞부분 미리 보기를 확인합니다.
4. **스키마**와 **테이블** 이름을 정합니다.
5. **방식**을 고릅니다.

   | 방식 | 뜻 |
   |---|---|
   | **새로 만들기** | 새 테이블을 만듭니다 |
   | **통째로 바꾸기** | 있던 테이블 내용을 이 파일로 바꿉니다 |
   | **뒤에 붙이기** | 있던 테이블 뒤에 행을 더합니다 |

6. **레이크에 넣기**를 누릅니다.
7. 아래 **수집 기록**에 **시각 · 파일 · 테이블 · 방식 · 행 · 결과**가 남습니다.

> **주의** **통째로 바꾸기**는 기존 행을 바꿉니다. 이전 모습은 보관 기간 안에서만 시점 조회로 볼 수 있습니다.

## 원본 연결과 동기화

<figure><img src="img/datalake/a-sources.png" alt="원본 연결 화면 — 위 원본 연결 표(ERP 계약(시연), SQLite 파일, 위치, 연결 시험·고치기·삭제)와 연결 추가 버튼, 아래 동기화 표(erp-contracts, main.contracts → erp.contracts, 병합(키로 바꿈), 60분, 마지막 실행, 지금 실행·고치기·삭제)와 동기화 만들기 버튼"><figcaption>원본 연결. 위는 연결(어디에 붙나), 아래는 동기화(무엇을 어떻게 가져오나)입니다.</figcaption></figure>

업무 DB 에는 **읽기 전용**으로 붙습니다. 드라이버·클라이언트를 따로 깔지 않고, 비밀번호·토큰은 암호화해 둡니다. 붙지 못할 때 오류에 비밀을 남기지 않습니다.

### 연결 추가 — 관리자

1. **원본 연결** › **연결 추가**.
2. **이름**(예 `ERP 운영(읽기 전용)`)과 **종류**를 고릅니다. 종류마다 입력 칸이 바뀝니다.

   | 종류 | 넣는 것 |
   |---|---|
   | **Oracle** | 호스트, 포트(1521), **서비스 이름**, 사용자, 비밀번호 |
   | **SQL Server** | 호스트, 포트(1433), 데이터베이스, 사용자, 비밀번호, **인증서**(사내 인증서 그대로 믿기) |
   | **PostgreSQL** · **MySQL·MariaDB** | 호스트, 포트, 데이터베이스, 사용자, 비밀번호 |
   | **SQLite 파일** | 서버에서 본 파일 경로 |
   | **Snowflake** | 계정(`조직-계정`), 주소(선택), 웨어하우스, 역할, 데이터베이스, 스키마, 접근 토큰(PAT — 읽기 전용 역할로) |
   | **REST API** | 기본 주소, 인증 헤더·방식, 토큰, **자원**(한 줄에 `이름=경로[;목록 위치]`), 목록 위치, 증분 이름, **쪽 넘김**(없음 · 쪽 번호 · 건너뛰기 · 커서). **미리 채우기**에 Jira·ServiceNow |
   | **폴더·S3** | 서버에서 본 공유 폴더 경로 또는 `s3://버킷/접두사`, 형식(확장자로 · CSV · Parquet · JSON). S3 면 엔드포인트·리전·키 ID·비밀 키 |

3. **저장**.
4. 줄의 **연결 시험**을 누릅니다. `붙었습니다 — 테이블 N개` 가 뜨고, 아래에 `<연결> 의 테이블` 목록이 열립니다.

> **주의** DB 계정은 반드시 **읽기 전용** 계정을 씁니다. 연결을 **삭제**하면 그 동기화도 지워집니다(레이크 테이블은 남음).

### 동기화 만들기

<figure><img src="img/datalake/a-sources-sync.png" alt="동기화 만들기 창 — 이름, 원본 연결, 가져올 것(테이블/원본 SQL)과 스키마.테이블, 레이크 스키마 raw, 레이크 테이블, 방식(통째로·증분·병합), 워터마크 열, 주기(자동으로·사용), 안내 문구, 저장"><figcaption>동기화 만들기. 연결 시험 뒤 테이블 목록에서 누르면 칸이 미리 채워집니다.</figcaption></figure>

1. **동기화 만들기**를 누릅니다(또는 연결 시험 뒤 나온 테이블 목록에서 테이블을 누릅니다).
2. 칸을 채웁니다.

   | 칸 | 넣는 것 |
   |---|---|
   | **이름** · **원본 연결** | 동기화 이름, 어느 연결에서 |
   | **가져올 것** | **테이블**(`스키마.테이블`, REST API 는 자원 이름, 폴더는 `daily/*.csv` 같은 패턴) 또는 **원본 SQL**(Oracle·SQL Server·Snowflake 만) |
   | **레이크 스키마** · **레이크 테이블** | 넣을 곳(스키마 기본 `raw`) |
   | **방식** | 아래 표 |
   | **워터마크 열** | 증분·병합의 기준 열(예 `updated_at` — 갱신 시각·순번) |
   | **키 열** | 병합일 때 행을 맞출 키 |
   | **주기** | **자동으로** 체크 후 몇 분마다(1~10080), **사용** 체크 |

   | 방식 | 언제 |
   |---|---|
   | **통째로** | 매번 새로 — 작은 코드·기준 테이블 |
   | **증분(새 행만)** | 워터마크 열이 지난번보다 큰 행만 붙임 — 로그·이력 |
   | **병합(키로 바꿈)** | 새로 바뀐 행을 키로 바꿔 넣음 — 주문·고객처럼 고쳐지는 테이블 |

3. **저장**. 줄의 **지금 실행**으로 바로 돌려 봅니다.
4. **마지막 실행**에 `N행`(성공) 또는 `실패`와 오류가 보입니다. 도는 중이면 `도는 중`.

> **참고** 원본·방식을 바꾸면 처음부터 다시 가져옵니다. 테이블 변경과 새 워터마크는 한 트랜잭션이라 중간에 멈춰도 빠지거나 겹치지 않습니다. 주기 실행은 감사 기록에 '시스템'의 `sync.run` 으로 남습니다.

## 실시간 수집 — Kafka · HTTP

<figure><img src="img/datalake/a-streams.png" alt="실시간 수집 화면 — 스트림 표(이름·대상 테이블·방식·상태·누적 행과 마지막 쓰기·분당 행·대기 행·밀린 메시지(건)), erp-orders-cdc 와 monitoring-alerts 가 '오류' 상태와 원인(Kafka 브로커에 연결하지 못했습니다), 밀린 메시지 '세어 보기', 오른쪽 끝에 고정된 다시 시작·멈추기·삭제, 위 오른쪽 스트림 만들기"><figcaption>실시간 수집. 시연 환경은 Kafka 를 끄고 있어 두 스트림이 '오류'로 보입니다.</figcaption></figure>

| 열 | 내용 |
|---|---|
| **이름** | 스트림 이름과 받는 곳(`Kafka · 토픽` 또는 `HTTP`) |
| **대상 테이블** · **방식** | 쓰는 테이블, 붙이기 · 키로 바꾸기 · 변경 반영(CDC) |
| **상태** | **실행 중** · **멈춤** · **오류**(아래에 원인) |
| **누적 행** | 지금까지 쓴 행. 둘째 줄은 마지막으로 레이크에 쓴 시각(`아직 안 씀`) |
| **분당 행** · **대기 행** | 분당 행, 아직 안 쓴 행. 형식이 맞지 않아 건너뛴 메시지가 있으면 `건너뜀 N` 꼬리표 |
| **밀린 메시지(건)** | Kafka 에 남은 메시지 — **세어 보기**를 누르면 셉니다 |
| 버튼(오른쪽 끝 고정) | **시작** / **멈추기**, 오류면 **다시 시작**, HTTP 면 **보내는 법**, 멈춘 상태에서 **고치기**, **삭제** |

### 스트림 만들기

1. **스트림 만들기**를 누릅니다.
2. **이름**과 **받는 곳**(**Kafka** · **HTTP**)을 정합니다. 둘은 만든 뒤 바꿀 수 없습니다.
3. Kafka 면 **브로커**(`host:port`), **토픽**, **소비자 그룹**(비우면 자동), **처음부터**(토픽의 처음 메시지부터), **보안**(TLS · SASL 로그인 — 방식·사용자·비밀번호)을 넣습니다.
4. **형식**(**JSON** · **Debezium(CDC)**)과 **쌓는 방식**을 고릅니다.

   | 쌓는 방식 | 언제 |
   |---|---|
   | **붙이기** | 받은 그대로 쌓기 — 로그·이벤트. **출처 열**을 켜면 `_ingested_at`·파티션·오프셋 열을 붙입니다 |
   | **키로 바꾸기** | 같은 키는 최신 값만 — 상태 테이블(**키 열** 필요) |
   | **변경 반영** | Debezium 의 생성·수정·삭제를 그대로 — 원본 DB 복제본(**키 열** 필요) |

5. **스키마**·**테이블**(없으면 첫 묶음으로 만듦), **묶음(행)**·**묶음(밀리초)** — 이만큼 모이거나 시간이 지나면 한 번에 씁니다.
6. **저장** 후 **시작**.

> **참고** 새 필드가 오면 열을 늘리고, 중첩 객체는 JSON 글자로 둡니다. 묶음마다 테이블 변경과 읽은 위치를 같은 트랜잭션에 쓰므로 멈췄다 다시 켜도 빠지거나 겹치지 않습니다. 점검 때 서버 설정 `streams.enabled` 로 모두 끌 수 있습니다(정의는 남음).

### HTTP 로 보내기

HTTP 스트림의 **보내는 법**을 누르면 보낼 주소와 예시 명령이 나옵니다.

- JSON 객체 하나, JSON 배열, 또는 NDJSON(`Content-Type: application/x-ndjson`)을 `POST /api/v1/streams/<id>/events` 로 보냅니다.
- 주소 끝에 `?wait=1` 을 붙이면 레이크에 쓴 뒤에 답합니다.
- 키는 **내 API 키**에서 **수집** 범위로 만듭니다([AX-DataLake 관리 개요](/admin/datalake/README.md)).

## 문서 묶음 — Word · PDF · 한글 문서

<figure><img src="img/datalake/a-documents-form.png" alt="문서 묶음 만들기 창 — 이름·표시 이름·설명, 폴더, 스키마·테이블, 등급, 소속, 주민번호·전화번호·이메일·카드번호·사업자번호별 처리 방식([주민번호] 표시로 바꿈·일부 가림·가리지 않고 개수만 셈 등), 의미 검색·글자 인식 체크, 주기(분, 비우면 수동 실행), 안내 문구"><figcaption>문서 묶음 만들기(관리자). 개인정보는 레이크에 쓰기 <b>전에</b> 처리합니다.</figcaption></figure>

### 만들기 — 관리자

1. 데이터 › **문서 수집** › **문서 묶음 만들기**.
2. 칸을 채웁니다.

   | 칸 | 넣는 것 |
   |---|---|
   | **이름** · **표시 이름** · **설명** | 예 `ops-manual` · `운영 매뉴얼`. 이름은 나중에 바꿀 수 없습니다 |
   | **폴더** | 서버에서 본 경로(공유 폴더·NAS 를 붙여 둔 곳). 비우면 올린 파일만 받습니다 |
   | **스키마** · **테이블** | 조각 테이블. 파일 목록은 `테이블_files` 로 함께 생깁니다 |
   | **등급** · **소속** | 등급(기밀이면 사내 모델만), 소속은 행 제한용 `org` 열 값(예 `HD01`) |
   | 개인정보 종류별 처리 | 주민번호·전화번호·이메일·카드번호·사업자번호마다 **일부 가림**(`010-****-5678`) · **[주민번호] 표시로 바꿈**(값이 남지 않음) · **가리지 않고 개수만 셈** · **문서 통째로 제외** |
   | **의미 검색** | 조각 임베딩 만들기 — 서버에 임베딩 모델이 설정됐을 때만 켤 수 있습니다 |
   | **글자 인식** | 스캔 PDF 쪽·이미지(png·jpg) 읽기 — 이 서버 안에서만(한국어·영어, 한 쪽 1~3초) |
   | **주기(분)** | 5분 이상. 비우면 수동 실행 |

3. **저장**.

> **주의** 개인정보 규칙을 바꾸면 다음 실행에서 모든 문서를 다시 넣습니다. 묶음을 **삭제**해도 레이크 테이블은 남습니다.

### 실행하고 확인 — 엔지니어·관리자

<figure><img src="img/datalake/a-documents.png" alt="문서 수집 화면 관리자 보기 — 문서 묶음 표(E2E 운영·영업 문서, 운영 매뉴얼, 운영·영업 문서와 원본·레이크 테이블·등급·문서·조각·개인정보 처리·마지막 실행), 오른쪽 끝에 고정된 실행·파일 올리기 단추와 ⋯, 운영 매뉴얼 줄의 ⋯ 메뉴(모두 다시(바뀌지 않은 문서도)·파일 올리기·파일 목록·고치기·삭제)를 연 모습, 아래 문서 찾기"><figcaption>문서 묶음 표. 줄 오른쪽 끝에 <b>실행</b>(올린 파일만 받는 묶음은 <b>파일 올리기</b>) 단추와 <b>⋯</b> 메뉴가 고정되어 있습니다.</figcaption></figure>

| 버튼 | 하는 일 |
|---|---|
| **실행** | 폴더의 바뀐 파일만 다시 넣습니다(폴더 묶음만) |
| **⋯** › **모두 다시(바뀌지 않은 문서도)** | 모든 파일을 다시 넣습니다(폴더 묶음만) |
| **파일 올리기** | 파일을 직접 올립니다. 올린 파일만 받는 묶음은 줄에 바로, 폴더 묶음은 **⋯** 안에. 끝나면 `파일 — 조각 N · 가린 개인정보: …` |
| **⋯** › **파일 목록** | 파일마다 **상태**(넣음 · 개인정보로 제외 · 실패), 크기, 조각·표 수 |
| **⋯** › **고치기** · **삭제** | 관리자만 |

받는 파일: `.docx` · `.pdf` · `.hwp` · `.hwpx` · `.html` · `.txt` · `.md` · 소스·설정 파일(`.java`·`.jsp`·`.sql`·`.xml` 등), 글자 인식을 켜면 이미지도. **마지막 실행**에 시각, 추가·바뀜·그대로 건수, 가린 개인정보 건수, 오류가 보입니다.
