# 온톨로지 정의

> 레이크 테이블 위에 **객체 유형**(장애·서비스·구성 요소…), **관계**(열=열 또는 조건식), **액션**(메모·웹훅)을 정의하고, 사용자가 요청한 액션을 승인합니다. ITO 표준 템플릿으로 한 번에 설치할 수도 있습니다. **대상**: 데이터 엔지니어(유형·관계·승인), 관리자(액션 정의·웹훅). **메뉴**: 데이터 › 객체 탐색 › 정의 탭 · 실행 요청 탭.

사용자가 객체를 보는 방법은 [온톨로지 — 업무 객체 보기](/user/datalake/ontology.md)에 있습니다.

## 화면 구성

<figure><img src="img/datalake/a-ontology-defs.png" alt="객체 탐색의 정의 탭 — ITO 표준 템플릿 카드(시연 데이터 체크, 진단 에이전트 웹훅 주소·토큰, 설치), 객체 유형 표(구성 요소·담당자·문제·변경·서비스·서비스 요청·장애와 테이블·키·이름·속성, 고치기·삭제)와 유형 추가, 관계 표와 관계 추가"><figcaption>정의 탭(관리자 화면). 엔지니어에게는 웹훅 칸과 액션 추가·고치기가 보이지 않습니다.</figcaption></figure>

| 카드 | 하는 일 | 누가 |
|---|---|---|
| **ITO 표준 템플릿** | 유형 7 · 관계 11 · 진단 메모 액션을 한 번에 설치 | 엔지니어·관리자(웹훅 칸은 관리자) |
| **객체 유형** | **유형 · 테이블 · 키 · 이름 · 속성**, **유형 추가**, 줄마다 **고치기 · 삭제** | 엔지니어·관리자 |
| **관계** | **관계 · 출발 → 도착 · 조건**, **관계 추가**, **고치기 · 삭제** | 엔지니어·관리자 |
| **액션** | **액션 · 대상 · 방식 · 승인**, **액션 추가**, **고치기 · 삭제** | 관리자 |

## ITO 표준 템플릿 설치

`ito` 스키마의 서비스·구성 요소·장애·변경·문제·서비스 요청·담당자 테이블에 맞춘 정의를 설치합니다.

1. **정의** 탭의 **ITO 표준 템플릿** 카드로 갑니다.
2. 시연용이면 **시연 데이터 테이블도 만들기(없는 것만 — 장애 300건 등)** 를 체크합니다. 실제 데이터가 있으면 끕니다.
3. (관리자) 진단 에이전트를 부르려면 **진단 에이전트 웹훅 주소**(플랫폼 `/hooks/…`)와 **웹훅 토큰**을 넣습니다. 그러면 '진단 에이전트 요청' 웹훅 액션도 함께 생깁니다.
4. **설치**를 누릅니다.
5. 결과 칸에 `유형 7 · 관계 11 · 액션 N` 이 나옵니다. 고객 테이블에 필요한 열이 없으면 `<유형> 건너뜀 — <테이블> <이유>: <필요한 열>` 이 나옵니다.

> **참고** 고객 테이블 이름·열이 다르면 설치한 뒤 유형·관계를 고칩니다. 다시 설치해도 됩니다.

## 객체 유형 만들기

<figure><img src="img/datalake/a-ontology-type.png" alt="객체 유형 창 — API 이름, 표시 이름, 설명, 테이블 선택, 키 열, 이름 열, 보일 속성(한 줄에 열=표시 이름), 색, 저장"><figcaption>객체 유형. 테이블 하나 + 키 열 + 이름 열이 한 유형입니다.</figcaption></figure>

1. **객체 유형** 카드의 **유형 추가**를 누릅니다.
2. 칸을 채웁니다.

   | 칸 | 넣는 것 |
   |---|---|
   | **API 이름** | 영문 이름(예 `incident`) — 주소·에이전트 도구에서 씁니다 |
   | **표시 이름** · **설명** | 화면에 보일 이름(예 `장애`) |
   | **테이블** | 레이크 테이블 |
   | **키 열** · **이름 열** | 객체를 가리키는 키, 목록에 보일 이름 |
   | **보일 속성** | 한 줄에 `열=표시 이름`(예 `severity=등급`). 비우면 모든 열 |
   | **색** | 유형 버튼·그래프의 색 |

3. **저장**.

유형을 **삭제**하면 `이 유형과 걸린 관계·액션을 지울까요? 테이블은 남습니다.` 를 묻습니다.

## 관계 만들기

<figure><img src="img/datalake/a-ontology-link.png" alt="관계 창 — API 이름 incident_recent_change, 출발 유형 장애, 도착 유형 변경, 이름(→) 직전 72시간 변경, 반대 이름(←) 72시간 안에 난 장애, 방식 조건식, 조건식 b.ci_id = a.ci_id AND b.ended_at BETWEEN a.opened_at - INTERVAL 72 HOUR AND a.opened_at, 저장(한 번 엮어 보고)"><figcaption>조건식 관계의 예 — 장애 → 같은 구성 요소에서 장애 직전 72시간 안에 끝난 변경.</figcaption></figure>

1. **관계** 카드의 **관계 추가**를 누릅니다.
2. **API 이름**, **출발 유형**, **도착 유형**을 고릅니다.
3. **이름(→)** 과 **반대 이름(←)** 을 넣습니다. 출발 객체에서는 이름이, 도착 객체에서는 반대 이름이 관계 버튼에 보입니다.
4. **방식**을 고릅니다.

   | 방식 | 넣는 것 | 예 |
   |---|---|---|
   | **열 = 열** | **출발 열**, **도착 열** | 출발 `service_id` = 도착 `id` |
   | **조건식** | `a` = 출발, `b` = 도착으로 쓴 SQL 조건 | `b.ci_id = a.ci_id AND b.ended_at BETWEEN a.opened_at - INTERVAL 72 HOUR AND a.opened_at` |

5. **저장(한 번 엮어 보고)** 을 누릅니다. 저장할 때 실제로 한 번 엮어 보고, 틀리면 오류를 보여 주며 저장하지 않습니다.

> **참고** 관계를 따라가는 조회도 레이크 SELECT 로 바뀌어 조회 검사를 지납니다. 도착 쪽 테이블에 권한이 없거나 행 제한이 걸리면 그만큼만 보입니다.

## 액션 만들기 — 관리자

1. **액션** 카드의 **액션 추가**를 누릅니다.
2. 칸을 채웁니다.

   | 칸 | 넣는 것 |
   |---|---|
   | **API 이름** · **표시 이름** · **설명** | 예 `open_ticket` · `처리 요청 만들기`. 설명은 액션 창 위에 보입니다 |
   | **대상 유형** | 이 액션을 쓸 객체 유형 |
   | **방식** | **메모**(객체에 메모 — 원본은 바꾸지 않음) 또는 **웹훅** |
   | **주소** (웹훅) | `https://…` — 플랫폼 `/hooks/<트리거 ID>`, ITSM, 메신저 |
   | **토큰 헤더** · **토큰** (웹훅) | 비우면 `Authorization: Bearer`. 토큰은 바꿀 때만 넣습니다(암호화 저장) |
   | **입력 항목** | 한 줄에 `이름=표시 이름`, 꼭 받을 것은 끝에 `*`(기본 `note=메모*`) |
   | **쓸 수 있는 역할** | 관리자 · 엔지니어 · 분석가 중 |
   | **승인** | **엔지니어·관리자가 승인한 뒤 실행** |

3. **저장**.

웹훅은 요청자가 본 객체(가림 적용)와 입력을 JSON 으로 보냅니다. 표의 **방식** 칸에 `웹훅 <주소>` 와 토큰이 있으면 `토큰` 꼬리표가 보입니다.

> **주의** 에이전트(MCP `propose_action`)가 요청한 웹훅은 **승인 칸을 끄더라도** 사람 승인을 기다립니다. 메모는 바로 남습니다.

## 액션 요청 승인 — 엔지니어·관리자

1. **실행 요청** 탭을 엽니다. 엔지니어·관리자에게는 모든 사람의 요청이 보입니다.
2. 위 오른쪽 `상태 전체` 칸에서 **승인 대기**를 고릅니다.
3. **대상**을 눌러 객체를 확인하고, **입력**과 **요청**(요청자 · 화면/API/에이전트)을 봅니다.
4. **승인·실행** 또는 **거절**을 누릅니다.
5. 상태가 **실행 중 → 완료**(또는 **실패**, **거절**)로 바뀌고 **결과**에 응답이나 `승인 <이름>` 이 남습니다.

> **주의** 내가 요청한 줄에는 승인 버튼이 나오지 않습니다. 요청자는 스스로 승인할 수 없습니다.

## 운영 팁

| 상황 | 할 일 |
|---|---|
| 분석가가 '볼 수 있는 객체 유형이 없습니다' | 그 유형 테이블의 조회 권한을 줍니다([거버넌스](/admin/datalake/governance.md)) |
| 관계 버튼이 늘 0 | 조건식의 열 이름·시간 범위를 확인합니다. SQL 작업창에서 같은 조인을 돌려 봅니다 |
| 웹훅이 실패 | 실행 요청의 **결과**에서 응답 코드를 봅니다. 주소·토큰을 고칩니다 |
| 유형 정의를 바꿈 | [계보](/user/datalake/lineage.md)에서 '온톨로지'로 이어진 테이블을 확인합니다 |
