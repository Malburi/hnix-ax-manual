# 거버넌스 — 권한 · 가림 · 행 제한

> 누가 어떤 테이블을 볼 수 있는지(조회 권한), 개인정보 열을 어떻게 가릴지(열 가림), 누가 어떤 행만 볼지(행 제한)를 정하고, 가림이 빠진 개인정보 열을 찾습니다. **대상**: 관리자(정책 변경), 데이터 엔지니어(보기·점검). **메뉴**: 관리 › 거버넌스.

## 화면 구성

<figure><img src="img/datalake/a-gov-grants.png" alt="거버넌스 화면 조회 권한 탭 — 위 안내 문구, 탭(조회 권한 3·열 가림 5·행 제한 3·개인정보 열 찾기), 누구에게(역할/사용자)·스키마·테이블 입력과 권한 주기 버튼, 아래 '역할: 분석가'에게 ops·hr·ito 모든 테이블 권한 3줄"><figcaption>조회 권한 탭. 시연 환경은 분석가 역할에 ops·hr·ito 스키마 전체를 주었습니다.</figcaption></figure>

| 탭 | 하는 일 |
|---|---|
| **조회 권한 (N)** | 분석가가 볼 수 있는 테이블 |
| **열 가림 (N)** | 열마다 가림 방식과 원문을 보는 역할 |
| **행 제한 (N)** | 테이블마다 보이는 행 조건과 제한 없는 역할 |
| **개인정보 열 찾기** | 가림이 없는 개인정보 열을 모든 테이블에서 찾기 |

탭 위 입력 줄과 표의 **삭제**는 **관리자에게만** 보입니다. 엔지니어에게는 `정책을 바꾸는 것은 관리자만 할 수 있습니다.` 가 함께 나옵니다.

### 규칙이 걸리는 방식

| 누가 | 테이블 | 열 가림 · 행 제한 |
|---|---|---|
| 관리자 · 데이터 엔지니어 | 모든 테이블을 봅니다 | 예외 역할로 지정하지 않으면 **걸립니다** |
| 분석가 | 조회 권한을 준 테이블만 | 걸립니다 |

규칙은 SQL 작업창·API·AI 질문·에이전트(MCP)·시점 조회·변경 이력·객체 탐색·문서 찾기 어디서 읽어도 똑같이 적용됩니다. 사용자의 SQL 은 구조를 분석해, 가림·행 제한이 걸린 테이블을 가린 하위 조회로 바꿔 끼웁니다. 별칭·`WITH`·하위 조회·`JOIN` 으로 피해 갈 수 없습니다.

## 조회 권한 주기

1. **조회 권한** 탭을 엽니다.
2. **누구에게**에서 **역할** 또는 **사용자**를 고르고, 역할(예 분석가)이나 사용자(`아이디 (이름)`)를 고릅니다.
3. **스키마**를 고르거나 새로 칩니다.
4. **테이블**에 이름을 넣습니다. `*` 는 그 스키마의 **모든 테이블**입니다(표에 `(모든 테이블)` 로 보임).
5. **권한 주기**를 누릅니다.
6. 표에 **누구에게 · 무엇을 · 준 때**가 남습니다. 거두려면 **삭제**.

> **참고** 권한 단위는 테이블입니다. 테이블 안의 일부 열·행을 숨기려면 열 가림·행 제한을 함께 씁니다. 사람마다 다르게 주기보다 역할에 주는 편이 관리하기 쉽습니다.

## 열 가림

<figure><img src="img/datalake/a-gov-masks.png" alt="열 가림 탭 — 테이블·열·가림(부분 가림(형식별))·종류(주민등록번호)·원문 보는 역할(관리자) 입력과 가리기 버튼, 부분 가림 예 문구, hr.staff.name·rrn·phone, ito.person.name·phone 5줄"><figcaption>열 가림. 원문은 관리자만 봅니다.</figcaption></figure>

| 가림 | 결과 |
|---|---|
| **부분 가림(형식별)** | 종류에 맞게 일부만 — 주민등록번호 `900101-1******`, 전화 `010-****-5678`, 이메일 `h***@example.co.kr`, 이름 `홍*동`. 형식이 맞지 않는 값은 통째로 가립니다 |
| **전체 가림(\*\*\*\*)** | 값 전체를 가립니다 |
| **해시(같은 값끼리는 묶임)** | 원문은 숨기되 같은 값은 같은 해시라 집계·조인에 씁니다 |
| **비움(NULL)** | 값을 비웁니다 |

1. **열 가림** 탭을 엽니다.
2. **테이블**과 **열**을 고릅니다.
3. **가림** 방식과 **종류**(주민등록번호·전화번호·이메일·카드·계좌·이름·주소 등)를 고릅니다.
4. **원문 보는 역할**을 고릅니다(기본 관리자). 고른 역할만 원문을 봅니다.
5. **가리기**를 누릅니다.

표에는 **열(스키마.테이블.열) · 가림 · 종류 · 원문을 보는 역할**이 나옵니다. 카탈로그 **열** 탭의 **보호** 칸에도 같은 정보가 보입니다.

> **주의** 가린 열은 조건·집계에도 가린 값으로 쓰입니다. 예를 들어 분석가가 전화번호로 `WHERE phone = '…'` 를 걸어도 원문과 비교되지 않습니다.

## 행 제한

<figure><img src="img/datalake/a-gov-rows.png" alt="행 제한 탭 — 테이블·조건(company_code = :org)·제한 없는 역할(관리자) 입력과 제한 걸기 버튼, :org 설명 문구, ops.incident company = :org, hr.staff company = :org, ito.incident org = :org 3줄"><figcaption>행 제한. <code>:org</code> 는 보는 사람의 소속으로 바뀝니다.</figcaption></figure>

1. **행 제한** 탭을 엽니다.
2. **테이블**을 고릅니다.
3. **조건**에 SQL 식을 씁니다. `:org` 는 보는 사람의 소속(사용자 화면의 **소속**)으로 바뀝니다.

   | 조건 예 | 뜻 |
   |---|---|
   | `company = :org` | 내 회사 행만 |
   | `org = :org OR org IS NULL` | 내 소속 행과 소속이 비어 있는 행 |
   | `region IN ('서울', '경기')` | 고정 조건 |

4. **제한 없는 역할**을 고릅니다(기본 관리자). 시연 환경은 관리자·데이터 엔지니어를 지정했습니다.
5. **제한 걸기**를 누릅니다.

표에는 **테이블 · 보이는 행 조건 · 제한 없는 역할**이 나옵니다. 분석가가 카탈로그에서 이 테이블을 열면 `행 제한이 걸린 테이블입니다 — 내 소속에 해당하는 행만 보입니다.` 가 보입니다.

> **주의** 소속이 없는 사람에게는 행 제한이 걸린 테이블의 **아무 행도 보이지 않습니다.** 사용자를 만들 때 소속을 꼭 넣으세요([AX-DataLake 관리 개요](/admin/datalake/README.md)).

## 개인정보 열 찾기

가림을 걸지 않은 개인정보 열이 없는지 정기적으로 점검합니다. AI 를 쓰지 않습니다.

1. **개인정보 열 찾기** 탭에서 **모든 테이블 점검**을 누릅니다.
2. 테이블마다 표본 100행을 읽어, 가림이 없는 열에서 주민등록번호·전화·이메일·카드(Luhn 검사)·계좌·이름·주소를 값 형식과 열 이름으로 찾습니다.
3. `테이블 N개 점검 · 가림 없는 개인정보 열 M개` 와 함께 **테이블 · 열 · 종류 · 근거**가 나옵니다(예 `표본 40개 중 40개가 전화번호 형식`).
4. 관리자는 줄의 **부분 가림 걸기**를 눌러 바로 가립니다.

> **참고** 새 원본을 붙이거나 파일을 올린 뒤에는 이 점검을 다시 돌리세요. 테이블 하나만 보려면 카탈로그의 **AI 설명 초안**에서도 같은 규칙으로 개인정보 열을 찾습니다.

## 등급

테이블마다 **공개 · 내부 · 대외비 · 기밀** 등급을 둡니다. 카탈로그의 **설명 고치기**에서 정합니다([AX-DataLake 관리 개요](/admin/datalake/README.md)).

- 기밀 등급 테이블이 섞인 AI 질문·문서 임베딩은 플랫폼 게이트웨이에 `restricted` 로 알려 사내 모델만 씁니다.
- 주민번호·카드·계좌가 있으면 기밀, 그 밖의 개인정보는 대외비를 권합니다(AI 설명 초안).

## 점검표

| 언제 | 확인 |
|---|---|
| 새 테이블이 들어왔을 때 | 개인정보 열 찾기, 등급, 분석가 조회 권한 |
| 새 분석가가 들어왔을 때 | 소속, 역할 권한으로 충분한지 |
| 조직 개편 | 사용자 소속 값과 행 제한 조건 |
| 정기 | 감사 기록에서 `governance.` 로 정책 변경 이력 확인 |
