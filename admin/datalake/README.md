# AX-DataLake 관리 개요

> AX-DataLake 의 역할과 관리자 메뉴, 사용자 계정, 감사 기록, API 키, 카탈로그 설명 다듬기를 다룹니다. **대상**: AX-DataLake 관리자, 데이터 엔지니어. **메뉴**: 관리 › 사용자 · 감사 기록 · 내 API 키 · 한눈에 보기.

AX-DataLake 는 HNIX AX 플랫폼과 **별도의 계정**을 씁니다. 처음 설치할 때 만든 `admin` 계정으로 들어가 사용자를 만듭니다. 설치·백업·설정 파일은 [운영 — 백업 · 업그레이드 · 점검](/admin/operations.md)을 봅니다.

## 역할

| 역할 | 화면 글자 | 할 수 있는 것 |
|---|---|---|
| 관리자 | **관리자** | 모든 것. 사용자, 감사 기록, 거버넌스 정책 바꾸기, 원본 연결 추가, 문서 묶음 정의, 온톨로지 액션 정의, 열 가림 |
| 데이터 엔지니어 | **데이터 엔지니어** | 모든 테이블 조회, 작업 SQL, 파일 수집, 동기화·스트림 만들기, 문서 묶음 실행, 거버넌스 보기, 온톨로지 유형·관계 정의, 액션 승인, 카탈로그 설명 |
| 분석가 | **분석가** | 조회 권한을 받은 테이블만 조회, AI 질문, 객체 탐색·액션 요청, 계보 보기 |

| 메뉴 | 분석가 | 엔지니어 | 관리자 |
|---|---|---|---|
| 한눈에 보기, 데이터(카탈로그 · 객체 탐색 · 계보 · SQL 작업창 · 문서(비정형)), 내 API 키 | ○ | ○ | ○ |
| 수집(파일 수집 · 원본 연결 · 실시간 수집), 거버넌스 | — | ○ | ○ |
| 사용자, 감사 기록 | — | — | ○ |

> **참고** 관리자·엔지니어도 **열 가림·행 제한**의 예외 역할로 지정되지 않았다면 가린 값으로 봅니다([거버넌스](/admin/datalake/governance.md)).

## 화면 구성 — 관리자의 한눈에 보기

<figure><img src="img/datalake/a-home.png" alt="관리자 한눈에 보기 — 볼 수 있는 테이블 15/스키마 6, 최근 시점 #100, 저장 용량 96.6 KB·파일 16개와 지금 정리 버튼, 실시간 수집 0/2·오류 2, 내 최근 조회, 테이블 등급, 최근 파일 수집"><figcaption>관리자에게는 저장 용량·실시간 수집·최근 파일 수집 카드가 더 보입니다.</figcaption></figure>

| 카드 | 내용 |
|---|---|
| **저장 용량** | 데이터 파일 크기와 개수. 관리자에게 **지금 정리** 버튼 |
| **실시간 수집** | `도는 중 / 전체`, 분당 행 수, 오류 개수. 누르면 실시간 수집 화면으로 |
| **최근 파일 수집** | `스키마.테이블 ← 파일 · 행 · 시각`, 실패 표시 |

### 지금 정리

매일 정한 시각(기본 새벽 3시)에 자동으로 도는 파일 정리를 바로 돌립니다.

1. **저장 용량** 카드의 **지금 정리**를 누릅니다.
2. `정리했습니다 — 소량 행 …건을 파일로, 파일 …개 합침, 지난 시점 …개·파일 …개 지움` 이 뜹니다.

> **주의** 정리하면 보관 기간(기본 30일)이 지난 시점이 지워져 그 시점으로는 시점 조회가 되지 않습니다. 결과는 감사 기록에 남습니다.

## 사용자

<figure><img src="img/datalake/a-users.png" alt="사용자 화면 — 로그인 ID·이름·소속·역할·상태·마지막 로그인 열의 표, 줄마다 고치기, 위 오른쪽 사용자 만들기"><figcaption>사용자. 소속은 행 제한의 <code>:org</code> 로 쓰입니다.</figcaption></figure>

| 열 | 내용 |
|---|---|
| **로그인 ID** · **이름** · **소속** | 소속은 계열사·조직 코드(예 `HD01`) |
| **역할** | 관리자 · 데이터 엔지니어 · 분석가 |
| **상태** | **사용** · **정지** |
| **마지막 로그인** | |

### 사용자 만들기

1. 왼쪽 메뉴 **사용자** › **사용자 만들기**.
2. **로그인 ID**, **이름**, **이메일**, **소속**(예 `HD01`), **역할**, **비밀번호**(8자 이상, 영문·숫자·특수문자 중 2종)를 넣습니다.
3. **저장**.
4. 분석가라면 [거버넌스](/admin/datalake/governance.md)에서 조회 권한을 줍니다. 권한이 없으면 아무 테이블도 보이지 않습니다.

### 고치기 · 정지

1. 줄의 **고치기**를 누릅니다. 로그인 ID 는 바꿀 수 없습니다.
2. 역할·소속을 바꾸거나, **상태**를 **정지**로 바꿉니다.
3. 비밀번호 칸은 바꿀 때만 넣습니다.
4. **저장**.

> **주의** 정지한 사용자는 로그인할 수 없고, 그 사람이 만든 API 키도 바로 막힙니다. 소속을 비우면 행 제한이 걸린 테이블에서 아무 행도 보이지 않습니다.

각 사용자는 머리띠의 **비밀번호 바꾸기**로 자기 비밀번호를 바꿉니다.

## 감사 기록

<figure><img src="img/datalake/a-audit.png" alt="감사 기록 화면 — 동작 앞부분으로 거르기 칸과 보기 버튼, 시각·누가·무엇을·대상·내용·IP 열의 표(auth.login, sync.run 등)"><figcaption>감사 기록. '누가'가 비어 있으면 시스템이 한 일입니다(예 주기 동기화).</figcaption></figure>

1. 왼쪽 메뉴 **감사 기록**을 누릅니다.
2. 동작 앞부분으로 거릅니다 — 칸에 `governance.` · `stream.` · `auth.` 처럼 넣고 **보기**(또는 `Enter`).
3. 표에서 **시각 · 누가 · 무엇을 · 대상 · 내용 · IP** 를 봅니다. 긴 내용은 마우스를 올리면 다 보입니다.

| 동작 예 | 뜻 |
|---|---|
| `auth.login` | 로그인 |
| `sync.run` | 동기화 실행(주기 실행이면 '시스템') |
| `governance.…` | 조회 권한·열 가림·행 제한 변경 |
| `stream.…` | 스트림 만들기·시작·멈추기 |

> **참고** 조회 내용(누가 어떤 SQL 을)은 감사 기록이 아니라 조회 이력에 남고, [계보](/user/datalake/lineage.md)의 소비 경로와 각자의 **실행 기록**에서 보입니다.

## 내 API 키

BI 도구·스크립트·로그 수집기·AI 에이전트를 레이크에 붙일 때 씁니다. 모든 역할이 자기 키를 만듭니다.

<figure><img src="img/datalake/a-keys.png" alt="내 API 키 화면 — 새 키 칸(이름, 범위 조회·수집·에이전트(MCP) 체크, 만료(일), 만들기)과 내 키 표(이름·앞자리·범위·만료·마지막 사용)"><figcaption>내 API 키. 키는 만든 사람의 역할·소속·가림 규칙 그대로 움직입니다.</figcaption></figure>

| 범위 | 쓰는 곳 | 누가 |
|---|---|---|
| **조회** | BI 도구·스크립트 — `POST /api/v1/query` | 모두 |
| **수집** | 로그 수집기·HTTP 스트림 — `POST /api/v1/streams/<id>/events` | 엔지니어·관리자 |
| **에이전트(MCP)** | AX Platform MCP 허브, Claude Code — `/mcp` | 모두 |

1. 왼쪽 메뉴 **내 API 키**를 누릅니다.
2. **이름**(예 `월간 보고 BI`)을 넣고 **범위**를 고릅니다.
3. **만료(일)** 를 정합니다(비우면 만료 없음).
4. **만들기**를 누릅니다. `키를 만들었습니다 — 지금만 보입니다.` 와 함께 키가 **한 번만** 보입니다. 안전한 곳에 옮깁니다.
5. 쓰지 않는 키는 **내 키** 표의 **폐기** — 그 키를 쓰는 곳이 바로 막힙니다.

> **주의** 허브·에이전트에 붙일 키의 주인이 곧 에이전트의 권한입니다. 운영 분석용이면 분석가 계정의 키를 써서 가림·행 제한이 걸린 데이터만 보게 합니다. 키 원문은 문서·채팅에 붙여 넣지 마세요.

### AI 에이전트 붙이기

- **AX Platform MCP 허브**: `http://<서버>:8790/mcp` 를 외부 MCP 서버로 등록하고 '에이전트(MCP)' 키를 넣습니다. 허브의 정책·승인·감사 아래에서 `datalake__*` 도구로 쓰입니다([MCP 허브 · 정책 · 승인](/admin/platform/hub.md)).
- **Claude Code 직접**: `claude mcp add --transport http ax-datalake http://<서버>:8790/mcp --header "X-API-Key: <키>"`

에이전트가 쓰는 도구는 `list_tables` · `describe_table` · `query`(최대 200행) · `table_history` · `table_changes` · `table_lineage` · 온톨로지 도구 · `list_document_collections` · `search_documents` · `propose_action` 입니다. `propose_action` 만 읽기 전용이 아니며, 웹훅은 사람 승인 뒤에 나갑니다.

## 카탈로그 설명 다듬기 — 엔지니어·관리자

카탈로그에서 테이블을 열면 **설명 고치기**와 **AI 설명 초안** 버튼이 보입니다.

<figure><img src="img/datalake/a-catalog-edit.png" alt="설명 고치기 창 — 설명 입력, 담당(사람·팀), 등급 선택, 태그(쉼표 구분), 열별 설명 입력칸, 저장"><figcaption>설명 고치기. 등급(공개·내부·대외비·기밀)도 여기서 정합니다.</figcaption></figure>

**설명 고치기**

1. 테이블을 열고 **설명 고치기**를 누릅니다.
2. 설명(`이 테이블은 무엇인가요? 어디서 오나요?`), **담당**, **등급**, **태그**(쉼표로 구분), **열 설명**을 넣습니다.
3. **저장**.

**AI 설명 초안**

1. **AI 설명 초안**을 누릅니다. 표본 200행에서 개인정보 열·등급을 규칙으로 찾고, 사내 모델에 설명·용어 초안을 묻습니다.
2. 창에서 반영할 것만 체크합니다.

   | 칸 | 내용 |
   |---|---|
   | **개인정보 열** | 가림 없는 개인정보 열과 근거(예 `표본 40개 중 40개가 전화번호 형식`). 체크하면 부분 가림을 겁니다 — **관리자만** 체크할 수 있습니다 |
   | **등급** | `내부 → 대외비` 처럼 권하는 등급(올리기만) |
   | **테이블 설명·태그** | AI 초안 — 고쳐 쓸 수 있습니다 |
   | **열 설명·업무 용어** | 기존 설명이 있는 열은 기본으로 체크하지 않습니다 |

3. **고른 것 반영**.

> **참고** 개인정보로 보이는 열의 값은 모델에 보내지 않습니다. 기밀 등급이면 사내 모델만 씁니다. 모델이 없으면 개인정보·등급만(AI 없이) 나옵니다. 초안·반영 모두 감사 기록에 남습니다.
