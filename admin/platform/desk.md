# 현업 창구 만들기와 매뉴얼 보강

> 현업 직원이 웹·메신저·메일로 물으면 운영 매뉴얼과 과거 처리 사례를 근거로 1차 답을 주는 창구를 만들고, 성과를 보고, 답하지 못한 질문으로 매뉴얼을 보강합니다. **대상**: 시스템 관리자(만들기·수정), 감사자(조회). **메뉴**: 현업·연동 › 현업 창구.

## 화면 구성

<figure><img src="img/platform/a-desks.png" alt="현업 창구 관리 화면 — 창구 카드(인사시스템 도움 창구 /desk/hr-help, 접수 방식 꼬리표, 마우스를 올리면 들어가기 →, 주소 복사·시험 질문·토큰 다시 만들기·수정·삭제 버튼, 30일 문의·자동 해결률·답변률·담당자 접수율·답 못 찾음·매뉴얼 보강 대기 수치), 아래 대화 기록 표와 매뉴얼 보강 안내"><figcaption>카드를 누르면 그 창구로 들어갑니다. 대화 기록은 아래 칸에서 봅니다.</figcaption></figure>

| 영역 | 하는 일 |
|---|---|
| **창구 만들기** | 새 창구(오른쪽 위) |
| 창구 카드 | 이름, 주소(`/desk/<주소 이름>`), `꺼짐`, 접수 방식(예: `접수 PMS-X 서비스 요청 · ○○공사 인사시스템 운영(SM)`), `Teams` 꼬리표 |
| 카드 누르기 | 그 창구로 들어갑니다(같은 탭 — Ctrl·가운데 단추는 새 탭). 창구 머리 줄의 **← 창구 관리**로 돌아옵니다(관리자에게만 보임) |
| 카드 버튼 | **주소 복사**(현업 사용자에게 보낼 창구 주소) · **시험 질문** · **토큰 다시 만들기** · **수정** · **삭제** (시스템 관리자) |
| 성과 수치 | 최근 30일 — 아래 표 |
| **대화 기록** | 창구의 대화. 창구가 여럿이면 오른쪽 위에서 창구를 고르고, 상태로 거른다 |

> **참고** 감사자는 창구와 대화 기록을 볼 수 있지만 카드 버튼이 보이지 않고 **매뉴얼 보강** 버튼이 눌리지 않습니다.

현업 직원이 창구를 쓰는 모습은 [현업 창구 — 현업 직원용](/user/platform/desk.md)을 보세요.

## 창구 만들기

<figure><img src="img/platform/a-desks-edit.png" alt="창구 수정 창 위쪽 — 이름·주소 이름·모델 별칭, 근거 문서함, 유사 사례 도구(pmsx__similar)와 도구 고정 입력값 JSON, 실행 계정(이개발), 사용, 첫 안내, 창구 규칙, 창구 모양(색·로고·자주 묻는 질문·미리보기)"><figcaption>창구 만들기·수정 창(위쪽) — 근거와 실행 계정, 창구 모양</figcaption></figure>

1. **창구 만들기**를 누릅니다.
2. 기본 칸을 채웁니다.

| 칸 | 내용 |
|---|---|
| 이름 | 예: 인사시스템 도움 창구 |
| 주소 이름 (/desk/…) | 예: `hr-help` → 현업 화면 주소 `/desk/hr-help` |
| 모델 별칭 | 게이트웨이의 켜진 대화 별칭 |
| 근거 — 문서함 | 운영 매뉴얼·FAQ 문서함(여러 개) |
| 근거 — 유사 사례 도구 | 지식 문서·끝난 요청을 찾는 허브 읽기 도구. PMS-X 가 연결돼 있으면 `pmsx__similar` 가 기본으로 들어갑니다 |
| 도구 고정 입력값 (JSON) | 유사 사례 도구에 늘 붙일 입력값. 예: `{"projectId": "<PMS-X 프로젝트 ID>"}` |
| 실행 계정 | 모델·도구·검색을 이 계정 권한으로 합니다. 비우면 나(만든 관리자) |
| 사용 | 끄면 창구가 닫힙니다 |
| 첫 안내 | 현업 화면 첫 문장. 예: 인사시스템 사용 중 궁금한 점을 물어보세요. |
| 창구 규칙 | 지시문에 덧붙일 규칙(선택). 예: 권한 신청은 반드시 포털 권한 신청 화면을 안내한다. |

> **참고** **저장**은 이름·주소 이름·모델 별칭이 있고, 근거(문서함 또는 유사 사례 도구)가 하나 이상 있어야 눌립니다.
> **참고** 실행 계정에게 근거 문서함을 볼 권한과 유사 사례 도구를 쓸 권한이 있어야 합니다. 그 계정의 게이트웨이 예산·개인정보 규칙도 그대로 걸립니다.

### 창구 모양

| 칸 | 내용 |
|---|---|
| 색 | 고객사 색. 견본에서 고르거나 HEX 입력. **기본 색**으로 되돌리기 |
| 로고 | PNG·JPG·WEBP·SVG, 150KB 이하. **올리기** · **바꾸기** · **지우기** |
| 자주 묻는 질문 | 현업 첫 화면의 질문 버튼, 6개까지 |

색과 로고는 아래 미리보기 띠에 바로 보입니다.

### 음성

<figure><img src="img/platform/a-desks-edit2.png" alt="창구 수정 창 아래쪽 — 음성(말로 묻기 스위치, 답 읽어 주기 끔·브라우저 음성·게이트웨이 음성 합성), 답을 못 하면 담당자 접수(PMS-X 서비스 요청·고객 ITSM 연결·고객 ITSM 웹훅·플랫폼 접수함), PMS-X 서버·SM 프로젝트·요청 유형·우선순위, Teams 보안 토큰, 늦은 답장 형식·주소"><figcaption>창구 만들기·수정 창(아래쪽) — 음성, 담당자 접수, 채널</figcaption></figure>

| 칸 | 내용 |
|---|---|
| 말로 묻기 (입력창 옆 마이크) | 켜면 **음성 인식 모델 별칭**(게이트웨이 종류 '음성 인식'), **인식 언어**(한국어·영어·일본어·중국어), **받은 글을 바로 보내기** |
| 답 읽어 주기 | **끔** · **브라우저 음성**(PC 에 깔린 목소리) · **게이트웨이 음성 합성**(음성 합성 모델 별칭, 목소리 이름) |
| 답이 오면 자동으로 읽기 | 읽어 주기를 켰을 때만 |

> **주의** 브라우저는 HTTPS 주소에서만 마이크를 엽니다. 사내 HTTP 주소로 쓰면 HTTPS 로 바꾸거나 브라우저 정책에 주소를 허용해야 합니다.

### 담당자 접수 — 답을 못 하면

창구는 근거가 없으면 모른다고 답하고, 사용자가 확인하면 대화 기록과 함께 담당자에게 넘깁니다.

| 접수 방식 | 넣는 값 | 결과 |
|---|---|---|
| **PMS-X 서비스 요청** | **PMS-X 서버**, **SM 프로젝트**(목록에서 고르거나 ID 입력), **요청 유형**(INQUIRY · IMPROVE · DATA · INCIDENT · AUTH), **우선순위**(P1~P4) | PMS-X 에 서비스 요청을 만듭니다. 요청자 이름·연락처와 대화 기록이 본문에 실립니다 |
| **고객 ITSM 연결** | **ITSM 연결**([고객 ITSM 연동](/admin/platform/integrations.md)에서 등록한 것) | 고객 ITSM 에 티켓을 만듭니다 |
| **고객 ITSM 웹훅** | **접수 주소** | 그 주소로 보냅니다 |
| **플랫폼 접수함** | 없음 | 플랫폼 대화 기록에만 남습니다 |

> **참고** SM 프로젝트 목록은 허브의 `<서버>__projects` 도구를 내 권한으로 불러 채웁니다. 목록이 비면 프로젝트 ID 를 직접 넣으세요.
> **주의** PMS-X 접수는 허브에 등록된 PMS-X 서비스 계정으로 요청을 만듭니다. 그 계정이 SM 프로젝트의 **운영자 이상**이어야 합니다. 서비스 계정은 [MCP 허브 서버](/admin/platform/hub.md)에서 정합니다.
> **참고** 플랫폼 접수함만 쓰는 창구는 [현장 연결 점검](/admin/platform/system.md)의 자동화 영역에 `확인` 으로 나옵니다 — 담당자가 놓치지 않게 PMS-X·ITSM 으로 넘기기를 권합니다.

### 채널 — 메신저·메일·Teams

| 칸 | 내용 |
|---|---|
| Teams 보안 토큰 | Teams 나가는 웹훅을 만들 때 받은 값(선택). 비우면 기존 값 유지 |
| 늦은 답장 형식 · 주소 | Teams 는 5초 안에 답해야 해서, 늦으면 이 주소로 답을 보냅니다(Teams · Slack · JSON) |

3. **저장**을 누릅니다. 새 창구면 **창구 연결 정보 — 토큰은 지금 한 번만 보입니다** 창이 뜹니다.

| 창의 항목 | 쓰는 곳 |
|---|---|
| 현업 사용자 화면 | `/desk/<주소 이름>` |
| 포털에 넣기 | `<iframe src="…?embed=1">` 코드 — 사내 포털에 붙입니다 |
| 메신저 봇·메일 게이트웨이 | `POST {text, user:{id,name,email}, threadId}` 주소와 `X-HNIX-Token` |
| Teams 나가는 웹훅 콜백 주소 | HMAC 서명은 창구의 Teams 보안 토큰으로 확인 |

> **주의** 토큰은 창을 닫으면 다시 볼 수 없습니다. 메신저 봇·메일 게이트웨이 설정에 바로 넣으세요. 포털 iframe 을 다른 도메인에 넣으려면 서버 설정의 허용 출처가 필요할 수 있습니다([운영](/admin/operations.md)).

## 토큰 다시 만들기

카드의 **토큰 다시 만들기**를 누르고 확인하면 새 토큰과 연결 정보 창이 다시 뜹니다. 옛 토큰은 바로 못 쓰게 되니 메신저 봇·메일 게이트웨이 설정을 새 토큰으로 바꾸세요.

## 시험 질문

카드의 **시험 질문**을 누르고 질문을 넣은 뒤 **물어보기**를 누릅니다. 현업 사용자와 같은 근거·모델로 답하고 `근거 있음` / `근거 없음 — 담당자 접수를 권하는 답` 과 근거 목록을 보여 줍니다.

> **참고** 시험 질문은 대화 기록과 창구 성과에 남지 않습니다(게이트웨이 요청 로그에는 남음).

창구 카드를 누르면 현업 화면으로 들어갑니다. 거기서 물으면 실제 대화로 기록됩니다. 현업 사용자에게는 카드의 **주소 복사**로 주소를 보내세요.

## 성과 지표

카드의 수치는 최근 30일 기준입니다.

| 지표 | 뜻 |
|---|---|
| 30일 문의 | 대화 수 |
| 자동 해결률 | 상태가 `해결` 인 대화(사용자가 해결됐다고 확인)의 비율 |
| 답변률 | 답한 대화(`답변함` + `해결`)의 비율 |
| 담당자 접수율 | 담당자에게 넘긴 비율 |
| 답 못 찾음 | 근거를 못 찾은 대화 수 |
| 매뉴얼 보강 대기 | 답 못 찾음·담당자 접수 중 아직 매뉴얼에 넣지 않은 수 |

### 대화 기록

| 열 | 내용 |
|---|---|
| 시각 · 경로(웹·메신저·메일) · 요청자 · 첫 질문 · 문답 | |
| 상태 | `진행 중` · `답변함` · `답 못 찾음` · `해결` · `담당자 접수` |
| 서비스 요청 | 만든 요청·티켓 번호, 실패하면 빨간 `접수 실패`(마우스를 올리면 이유) |
| 매뉴얼 | `보강함`, 또는 **매뉴얼 보강** 버튼 |
| **보기** | 질문과 답, 답마다 `근거 있음/없음` 과 근거 문서 |

상태 거르기에서 **매뉴얼 보강 필요**를 고르면 보강할 질문만 보입니다(노란 안내의 **보강할 질문만 보기**와 같음).

## 매뉴얼 보강

<figure><img src="img/platform/a-desks-supplement.png" alt="매뉴얼 보강 창 — 현업 질문, 그때 창구의 답(답을 찾지 못했습니다), 넣을 문서함(운영 매뉴얼), 문서 제목, 마크다운 답 칸, 취소·매뉴얼에 넣고 다시 물어보기 버튼"><figcaption>매뉴얼 보강 — 답을 적어 창구 근거 문서에 넣고 같은 질문을 다시 물어봅니다</figcaption></figure>

답을 못 찾았거나 담당자에게 넘긴 질문의 답을 적어 두면, 다음에 같은 질문이 오면 창구가 답합니다.

1. 대화 기록에서 **매뉴얼 보강**을 누릅니다.
2. 창 위에 **현업 질문**과 **그때 창구의 답**이 보입니다.
3. **넣을 문서함**(이 창구의 근거 문서함 중 하나)과 **문서 제목**을 확인합니다.
4. **답** 칸에 마크다운으로 답을 적습니다. 미리 채워진 틀의 `(여기에 … 적습니다)` 를 어느 화면에서 무엇을 누르는지, 담당 부서·연락처 등으로 바꿉니다. `##` 제목마다 한 절로 색인됩니다.
5. **매뉴얼에 넣고 다시 물어보기**를 누릅니다.
6. 같은 질문을 기록 없이 다시 물어 결과를 보여 줍니다 — `이제 근거로 답합니다` 또는 `아직 근거를 못 댑니다 — 내용을 보태 보세요`.

> **참고** 보강한 답은 [문서 검색](/admin/platform/docs.md)에 새 문서로 들어갑니다. 거기서 보거나 지울 수 있습니다.
