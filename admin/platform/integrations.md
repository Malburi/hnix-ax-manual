# 고객 ITSM · 업무 시스템 · 알림 연동

> 고객 ITSM 티켓과 PMS-X 서비스 요청을 양방향으로 맞추고, 사내 업무 시스템을 허브 도구로 잇고, 승인 요청·창구 접수를 Teams·Slack·메일로 알립니다. **대상**: 시스템 관리자(설정), 감사자(조회 — 알림 보내기 제외). **메뉴**: 현업·연동 › 고객 ITSM 연동 / 업무 시스템 연결, 관리 › 알림 보내기.

## 고객 ITSM 연동

고객 ITSM 을 기록의 원본으로 두고 PMS-X 에서 일합니다. 동기화를 켜면 다음이 자동으로 돕니다.

- 조건에 맞는 **새 고객 티켓 → PMS-X 서비스 요청 접수**(티켓에 요청 번호 댓글)
- **요청 상태 변화 → 고객 티켓 상태·댓글**
- 고객이 티켓을 끝내면 '처리 완료' 요청을 '확인'으로 넘김

주기(기본 5분)로 바뀐 것만 찾고, 고객 ITSM 에서 웹훅을 걸면 그 티켓은 바로 반영합니다. 에이전트는 `itsm__ticket` · `itsm__links` · `itsm__comment` 도구로 봅니다.

<figure><img src="img/platform/a-itsm.png" alt="고객 ITSM 연동 화면 — 왼쪽 연결 카드(demo-itsm · ServiceNow · 동기화 꺼짐 · 이은 티켓 5), 오른쪽 선택한 연결의 고객 ITSM 주소·PMS-X 프로젝트 이름·웹훅 주소, 연결 시험·지금 동기화·설정·토큰 다시 만들기·삭제 버튼, 이은 티켓 (5) 표(고객 티켓·티켓 상태·PMS-X 요청·요청 상태·처음 생긴 곳·마지막 동기화·오류)"><figcaption>고객 ITSM 연동 — 시험용 연결(demo-itsm)과 이은 티켓 5건</figcaption></figure>

| 영역 | 내용 |
|---|---|
| **연결** 카드 | 연결 이름, 종류(servicenow · jira · generic), `동기화 N분` / `동기화 꺼짐`, 이은 티켓 수, 마지막 동기화, 오류 |
| 연결 상세 머리 | 주소 · PMS-X 서버 / 프로젝트 · 웹훅 주소, 버튼 **연결 시험** · **지금 동기화** · **설정** · **토큰 다시 만들기** · **삭제** |
| **이은 티켓** 탭 | 고객 티켓(링크) · 티켓 상태 · PMS-X 요청 · 요청 상태 · 처음 생긴 곳(`고객 티켓` / `현업 창구`) · 마지막 동기화 · 오류 |
| **동기화 기록** 탭 | 시각 · 방향(`← 고객` / `→ 고객`) · 동작(실패는 빨강) · 내용 |

### 처음 연결하기

1. 고객 ITSM 정보를 받습니다 — 주소, 연동용 계정과 비밀번호(또는 토큰), HNIX 담당 범위(배정 그룹·JQL).
2. **연결 추가**를 누르고 칸을 채웁니다.

| 칸 | 내용 |
|---|---|
| 이름 | 예: `cust-snow`. 만든 뒤 바꿀 수 없음 |
| 종류 | ServiceNow · Jira Service Management · 일반 REST |
| 주소 · 인증 · 계정 · 비밀번호·토큰 | 계정 + 비밀번호(Basic) 또는 토큰(Bearer). 수정 때 비우면 유지 |
| ServiceNow | **테이블**(기본 incident), **범위 조건**(예: `assignment_group.name=HNIX-ITO`) |
| Jira | **범위(JQL)**, **만들 프로젝트 키**, **만들 이슈 유형** |
| 일반 REST | **일반 REST 설정** JSON — 조회·검색·댓글·상태 경로, 목록 위치, 필드 대응 |
| PMS-X 연결 · SM 프로젝트 ID | 티켓을 받을 PMS-X 허브 서버와 SM 프로젝트 |
| 동기화 · 분 | 켜기와 주기(1~1440분) |
| 새 티켓 → 서비스 요청 | 켜기와 만들 요청 유형(INQUIRY 등) |
| 요청 상태 → 티켓 상태 | JSON. 예: `{"IN_PROGRESS": "In Progress", "RESOLVED": "Resolved"}` |
| 티켓 우선순위 → P1~P4 | JSON. 예: `{"1 - Critical": "P1"}` |
| 끝난 티켓 상태 | 쉼표로. 기본 `Resolved, Closed, Canceled, Done` |
| 고객 종료 → 요청 확인 | 켜면 고객이 끝낸 티켓의 요청을 '확인'으로 |

3. **저장**하면 **고객 ITSM 웹훅 — 토큰은 지금만 보입니다** 창에 주소와 토큰(`X-HNIX-Token`)이 나옵니다. ServiceNow 는 비즈니스 규칙(after insert/update)에서 REST 메시지로 `{"sys_id": "${current.sys_id}"}` 를, Jira 는 시스템 › 웹훅에서 이슈 생성·수정 이벤트로 이 주소를 부르게 합니다(머리글을 못 넣으면 주소 뒤에 `?token=`).
4. **연결 시험**을 누릅니다. `연결됨 — 최근 하루 바뀐 티켓 N건` 이 나오면 됩니다.
5. **지금 동기화**로 한 번 돌려 보고 **동기화 기록**을 확인합니다.

> **주의** **지금 동기화**는 조건에 맞는 새 티켓마다 PMS-X 에 서비스 요청을 **실제로** 만듭니다.
> **참고** **토큰 다시 만들기**를 누르고 확인하면 기존 토큰은 바로 못 쓰게 됩니다. **삭제**는 연결·이은 목록·기록만 지우고 고객 티켓과 서비스 요청은 그대로 둡니다.

### 고객 ITSM 없이 먼저 해 보기

연결이 하나도 없으면 **처음 연결하기** 카드에 **시험용 연결 만들기** 버튼이 있습니다. 플랫폼 안의 가상 ITSM(ServiceNow 형식, 티켓 5건)에 연결하고, PMS-X 가 연결돼 있으면 첫 SM 프로젝트로 잇습니다. 가상 티켓은 서버를 다시 시작하면 처음으로 돌아갑니다.

현업 창구가 답하지 못한 질문을 고객 ITSM 티켓으로 넘기려면 창구의 담당자 접수에서 **고객 ITSM 연결**을 고릅니다([현업 창구](/admin/platform/desk.md)).

## 업무 시스템 연결

사내 업무 시스템을 에이전트와 업무 자동화가 쓰는 **MCP 허브 도구**로 잇습니다. 연결 이름이 도구 이름 앞에 붙습니다(예: `sap_hr__query`).

<figure><img src="img/platform/a-biz.png" alt="업무 시스템 연결 화면 — 아직 연결이 없는 상태. 처음 연결하기 4단계 안내와 SAP (OData)·Salesforce·Microsoft 365·네이버웍스·일반 REST (OpenAPI) 다섯 가지 종류 상자"><figcaption>업무 시스템 연결 — 연결이 없을 때의 처음 화면</figcaption></figure>

| 종류 | 도구로 되는 일 |
|---|---|
| SAP (OData) | Gateway·S/4HANA OData(v2·v4) — 엔터티 조회, 함수 호출, 생성·수정 |
| Salesforce | SOQL 조회, 레코드 조회·만들기·고치기 |
| Microsoft 365 | Graph — 일정 조회, 메일 보내기, Teams 채널 메시지 |
| 네이버웍스 | 봇 메시지(사람·채널), 구성원 조회 |
| 일반 REST (OpenAPI) | OpenAPI 문서를 넣어 사내 REST API 를 골라 도구로 |

### 연결 추가

1. **연결 추가**를 누릅니다(또는 처음 화면의 종류 상자를 누릅니다).
2. **종류**를 고릅니다.
3. **주소·인증** — **연결 이름**(예: `sap_hr`, 만든 뒤 바꿀 수 없음), **설명**, 종류별 칸을 넣습니다.

| 종류 | 주요 칸 |
|---|---|
| SAP | OData 서비스 주소, OData 버전, SAP 클라이언트, 인증(Basic · OAuth2 앱 인증), 쓰기 전 CSRF 토큰, 쓸 엔터티 집합, 부를 함수(한 줄에 `이름 GET/POST`) |
| Salesforce | Salesforce 주소, 소비자 키(Client ID), API 버전, 쓸 개체 |
| Microsoft 365 | 테넌트 ID, 앱(클라이언트) ID, 기본 보낸 사람, 보낼 수 있는 사람 |
| 네이버웍스 | 인증(Service Account 서명 키 · 발급한 토큰), Client ID, Service Account, 봇 ID, 도메인 ID |
| 일반 REST | OpenAPI 문서(주소 또는 붙여 넣기) → **문서 읽기** → 쓸 operation 체크, API 주소, 인증(없음 · Basic · Bearer · API 키 헤더 · OAuth2), 연결 시험 경로 |

   비밀번호·앱 비밀값 등은 암호화해 저장하고 다시 보여 주지 않습니다(수정 때 비우면 유지). **주소 바꾸기·시간 제한(고급)** 을 펼치면 시간 제한·읽기 재시도·목록 최대 건수·응답 상한(KB) 등을 정합니다.

4. **연결 시험**으로 주소·인증·권한을 가벼운 호출로 확인합니다.
5. **다음 — 도구 고르기**를 누릅니다.
6. **도구·정책** — 도구마다 **쓰기**(사용) 스위치와 **기본 정책**(허용 · 승인 필요 · 차단)을 정합니다. 조회 도구는 기본 허용, 업무 시스템에 쓰는 도구는 기본 **승인 필요**입니다.
7. **저장하고 바로 켜기**를 확인하고 **저장**합니다. 켠 도구만 허브에 등록됩니다.

> **참고** **승인 필요** 도구는 부를 때마다 다른 관리자의 승인을 받은 뒤 같은 인자로 한 번 실행됩니다([승인함](/admin/platform/hub.md)). MCP 허브 **정책** 탭에 따로 만든 규칙이 먼저 적용됩니다.

### 연결 관리

연결을 고르면 주소 · 상태(`도구 등록됨` · `등록 오류` · `확인 전` · `꺼짐`) · 비밀값 개수 · 마지막 연결 시험 결과와 도구 표(도구 이름 · 하는 일 · 구분 · 기본 정책 · 허브 등록)가 보입니다.

| 버튼 | 하는 일 |
|---|---|
| **연결 시험** | 다시 확인 |
| **설정** | 주소·인증부터 다시 열어 도구·정책까지 고침 |
| **끄기** / **켜기** | 끄면 이 연결의 도구를 아무도 쓸 수 없습니다 |
| **삭제** | 연결·허브 도구·기본 정책·비밀값을 지웁니다 |

이 연결로 생긴 허브 서버는 MCP 허브 **서버** 탭에 `업무 시스템 연결에서 관리` 로 보입니다. 호출 기록은 MCP 허브 **호출 기록** 탭에서 봅니다.

## 알림 보내기

> 이 화면은 **시스템 관리자**에게만 보입니다.

머리의 **알림**(종)은 화면을 열어야 보이지만, 여기 설정하면 승인하는 사람이 Teams·Slack·메일로 바로 받습니다. 보내기에 실패해도 승인·접수 업무는 그대로 진행됩니다.

<figure><img src="img/platform/a-notify.png" alt="알림 보내기 화면 — 받는 곳 카드(형식 Microsoft Teams·Slack·메일 게이트웨이·기타 (JSON), 웹훅 주소, 보낼 알림 체크 3개: 도구 승인 요청·승인·반려 결과·현업 창구 담당자 접수, 저장·시험 알림 보내기 버튼, 꺼짐 꼬리표), 마지막으로 보낸 결과 카드"><figcaption>알림 보내기 — 아직 꺼져 있는 상태</figcaption></figure>

1. **형식**을 고릅니다.

| 형식 | 웹훅 주소 |
|---|---|
| Microsoft Teams | 채널의 들어오는 웹훅(Incoming Webhook) 주소 |
| Slack | Slack 앱의 Incoming Webhook 주소 |
| 메일 게이트웨이·기타 (JSON) | 사내 메일 게이트웨이·자동화 도구 — `{source, kind, title, text, link, at}` 를 POST |

2. **웹훅 주소**를 넣습니다. 저장 뒤에는 앞부분만 `저장됨: …` 으로 보이고, 바꿀 때만 다시 넣습니다.
3. **보낼 알림**을 고릅니다 — **도구 승인 요청** · **승인·반려 결과** · **현업 창구 담당자 접수**.
4. **저장**을 누릅니다. 오른쪽 위 꼬리표가 `켜짐` 으로 바뀝니다.
5. **시험 알림 보내기**로 채널에 도착하는지 확인합니다.

**마지막으로 보낸 결과** 카드에 서버가 시작된 뒤 마지막 알림의 시각·종류와 성공(`받는 곳이 받았습니다(상태)`) 또는 오류가 나옵니다. 그만 보내려면 **끄기(주소 지우기)** 를 누릅니다.

> **참고** 트리거별 결과 알림은 [트리거](/admin/platform/agents.md)의 **결과 알림 주소**에서, 창구의 Teams 답장은 [현업 창구](/admin/platform/desk.md)에서 따로 정합니다.
