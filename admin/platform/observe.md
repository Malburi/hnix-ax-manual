# AI 사용 현황 · 생산성 보고서 · 모델 평가

> 전사 AI 사용량·비용·품질을 관리자 관점에서 보고(수집 소스·단가표·외부 AI·AI 자산 대장), 생산성 보고서를 만들고, 모델 별칭을 정답 세트로 견줍니다. **대상**: 시스템 관리자(설정), 감사자(조회). **메뉴**: 관측·보고 › AI 사용 현황 / 생산성 보고서, 에이전트·자동화 › 평가 › 모델 평가.

## 화면 구성

| 메뉴 | 화면 위 묶음 탭 | 화면 안 탭 |
|---|---|---|
| **AI 사용 현황** | **사용량 · 비용** | 대시보드 · 최근 기록 · 단가표 · 수집 소스(관리자·감사자) |
| | **품질 · 지연** | — |
| | **외부 AI · 자산**(관리자·감사자) | 외부 AI 사용 현황 · AI 자산 대장 · 수집 원천 |
| **생산성 보고서**(관리자·감사자) | — | 보고서 · 저장소·커밋 · 기준선·요청 |
| **평가** | **에이전트 평가** · **모델 평가**(관리자·감사자) | — |

사용자는 자기 사용 내역만 봅니다(`내 사용 내역만 표시`). 시스템 관리자·감사자는 전체를 보고, **사용자** 타일과 **사용자**별 집계가 더 보입니다. 사용자 쪽 화면은 [AI 사용 현황](/user/platform/usage.md)을 보세요.

> **참고** 감사자는 모든 화면을 보지만 **단가 추가 · 소스 추가 · 원천 추가 · 자산 올리기 · 저장소 등록 · 평가 시작** 같은 버튼이 보이지 않습니다.

## 사용량 · 비용 — 관리자 관점

**대시보드** 탭: 기간(7일·30일·90일), 프로젝트·모델·소스 거르기, **CSV 내보내기**. 타일은 비용 · 토큰 · 요청 · 캐시 적중률 · 사용자. **항목별 집계**는 모델 · 프로젝트 · 팀 · 사용자 · 작업번호(요청·CR) · 소스 · 도구로 묶어 봅니다.

소스(사용 기록이 들어온 경로): 게이트웨이 · Claude Code · AX-NAVI · 수집기 push · OTLP · 에이전트.

### 단가표

<figure><img src="img/platform/a-insight-prices.png" alt="사용량 · 비용 › 단가표 탭 — 모델 패턴·적용 시작·입력·출력·캐시 읽기·캐시 쓰기 5분·캐시 쓰기 1시간·비고 열의 Claude 모델 단가 표, 오른쪽 위 비용 다시 계산·단가 추가 버튼"><figcaption>단가표 — USD / 백만 토큰</figcaption></figure>

비용은 단가표로 계산합니다. 단위는 USD / 백만 토큰이고, 사내 로컬 모델은 0원으로 집계합니다.

1. **단가 추가**를 누릅니다(행의 **수정**으로 고칠 수도 있음).
2. **모델 패턴**(끝에 `*` 허용, 예: `claude-sonnet-5*`), **적용 시작일**, 입력 · 출력 · 캐시 읽기 · 캐시 쓰기 5분 · 캐시 쓰기 1시간 단가, **비고**(예: 계약 단가)를 넣습니다.
3. **저장**합니다.
4. 이미 쌓인 기록에 반영하려면 **비용 다시 계산**을 누릅니다(`N건의 비용을 다시 계산했습니다`).

> **참고** 모델 이름이 여러 패턴에 맞으면 더 구체적인 패턴이 이깁니다. 단가가 없는 요청은 대시보드 비용에서 빠지고 `단가 없는 요청 N건 제외` 로 표시됩니다.

### 수집 소스

게이트웨이를 거치지 않은 사용 기록(Claude Code 세션 로그, AX-NAVI 감사 로그)을 모읍니다.

**서버가 직접 읽는 폴더**

1. **소스 추가**를 누릅니다.
2. **종류**(Claude Code 세션 로그 · AX-NAVI 감사 로그), **이름**, **경로**(서버에서 읽을 폴더), **사용자**(비우면 기록에 있는 값), **프로젝트**(비우면 저장소 폴더 이름)를 넣고 **등록**합니다.
3. 행의 **스캔**을 누르면 `파일 N개 중 M개 변경 — 신규 · 중복` 이 나옵니다.

같은 파일을 여러 번 읽어도 요청 ID 기준으로 한 번만 집계되고, 크기·수정 시각이 바뀐 파일만 다시 읽습니다. 소스를 **삭제**해도 이미 수집한 기록은 남습니다.

**개발자 PC에서 보내기** — 각자 [내 키](/user/platform/gateway.md)에서 수집(ingest) 권한 키를 발급한 뒤 PC에서 `hnix-ax collect --server <플랫폼 주소> --key <키>` 를 실행합니다. 올린 기록은 키 소유자의 것으로 고정됩니다. Claude Code 텔레메트리(OTLP)를 조직 단위로 받는 **조직 수집(ingest_org)** 키는 시스템 관리자만 발급합니다.

기간(하루·7일·30일)을 고르면 관리자에게는 `전체 사용자` 기준으로 나옵니다.

| 영역 | 내용 |
|---|---|
| 타일 | LLM 성공률 · 응답 지연 p95 · 도구 성공률 · 에이전트 성공률 · 정책 위반 · 사용자 만족도 |
| 일별 LLM 요청 / 일별 응답 지연 p95 | 결과별 누적 막대 |
| 모델 별칭별 지연·오류 | 요청 · 오류율 · 거부 · p50 · p95 |
| MCP 도구 성공률 | 호출 · 성공률 · 거부 · p95 |
| 정책 위반 | 어디서(게이트웨이·허브) · 사유·정책 · 건수 |
| 에이전트 실행 | 실행 · 성공 · 실패 · 승인 대기 · 평균 턴 |
| 사용자 피드백 | 채팅 답변·에이전트 실행·업무 흐름 개선 결과의 👍·👎, 만족도, 최근 의견 |

## 외부 AI · 자산

고객 회사가 이미 쓰는 AI(Claude·Copilot 등)의 사용량과, 에이전트·AI 도구 대장을 관리합니다. 사용량은 각 도구의 관리 API 에서 일별 집계만 가져오고 대화·코드는 받지 않습니다.

### 수집 원천

1. **수집 원천** 탭에서 **원천 추가**를 누릅니다.
2. **이름**, **종류**(Anthropic Admin API(Claude) · GitHub Copilot · CSV 올리기)를 고릅니다.
3. API 종류면 **주소(선택)**, (Copilot) **조직**, **API 키**, **처음 가져올 기간**(1~31일)을 넣고 **저장**합니다.
4. 행의 **지금 가져오기**(CSV 는 **CSV 올리기**)로 바로 받습니다. 그 뒤로는 매일 한 번 자동으로 가져옵니다.

| 원천 | 필요한 것 |
|---|---|
| Claude | Claude Console 조직의 Admin API 키 — Claude Code 분석(사용자·일별)과 API 사용량. Claude Enterprise(claude.ai) 조직은 여기서 받지 않습니다 |
| GitHub | Copilot 지표를 볼 수 있는 토큰(조직 소유자 또는 지표 권한) |
| CSV | 열 `date,tool,user,metric,value` |

**외부 AI 사용 현황** 탭에서 기간을 골라 **조회**하면 도구별 지표 카드와 **사용자별** 표(사용일, 주요 지표, 좌석만 있고 사용 기록 없음 등)가 나옵니다.

### AI 자산 대장

<figure><img src="img/platform/a-enterprise-assets.png" alt="외부 AI · 자산 › AI 자산 대장 탭 — 안내 상자, 비어 있는 대장 카드와 자산 올리기 버튼, 대장에 없는 AI (2) 카드에 m365-copilot(외부 사용량)·axnavi(claude-code)(Insight)와 대장에 올리기 버튼"><figcaption>AI 자산 대장 — 사용 기록에서 찾았지만 대장에 없는 AI 가 아래에 나옵니다</figcaption></figure>

1. **자산 올리기**를 누르거나, **대장에 없는 AI** 목록의 **대장에 올리기**를 누릅니다(MCP 허브 서버 · 외부 사용량 · Insight 에서 찾은 것).
2. 이름, 종류(에이전트 · AI 도우미 · MCP 서버 · 모델 · AI 앱), 공급·만든 곳, 담당, 쓰는 부서, 설명, 주소, 다루는 데이터(등급), 위험도, **MCP 허브 서버**, **사용량 도구**를 넣고 **저장**합니다.
3. 행의 **검토**를 눌러 상태(검토 중 · 승인 · 제한 · 차단)와 근거를 적고 **저장**합니다.

> **주의** **MCP 허브 서버**를 이어 둔 자산은 검토 상태가 허브를 움직입니다 — **차단·검토 중**이면 허브에서 그 서버를 끄고, **승인·제한**이면 켭니다. 검토 창에 `허브 서버 … 를 켭니다/끕니다` 가 미리 표시됩니다.

## 생산성 보고서

커밋·서비스 요청·AI 관여를 묶어 공수 절감과 리드타임 단축을 계산합니다.

<figure><img src="img/platform/a-delivery.png" alt="생산성 보고서 › 보고서 탭 — 기간·프로젝트·기준선(계약 기준값/기준 기간 실적)·목표·계산·보고서(MD)·요청 목록(CSV) 줄, 공수 절감·리드타임 단축·해결한 요청·커밋 연결률·AI 관여 요청 카드, 해석 시 주의 상자, AI 관여 여부별·유형별 표, 해결한 요청 표"><figcaption>생산성 보고서 — 계산 결과와 해석 시 주의</figcaption></figure>

### 준비 — 기준선·요청, 저장소·커밋

1. **기준선·요청** 탭의 **계약 기준값**에 유형별 요청 1건 평균 **공수(시간)** · **리드타임(시간)** · 메모를 넣습니다(**행 추가** → **저장**). 계약 때 합의한 기준(예: 직전 연도 실적)입니다.
2. 같은 탭 **서비스 요청 가져오기**에서 PMS-X 연결과 프로젝트 ID 를 고르고 **PMS-X 에서 가져오기**를 누릅니다. 다른 ITSM 은 `POST /api/v1/delivery/work-items` 로 넣습니다.
3. **저장소·커밋** 탭에서 **저장소 등록** — 이름, 종류(GitLab · GitHub · 일반(수집 명령)), 프로젝트, **업무 번호 형식**(비우면 SR·CR·INC·CHG·REQ-번호 형식)을 넣고 **저장**합니다. 웹훅 주소와 비밀값이 **한 번만** 보입니다 — GitLab·GitHub 웹훅 설정 또는 `hnix-ax collect-git` 명령에 넣습니다.

### 보고서 만들기

1. **보고서** 탭에서 **기간**, **프로젝트**(선택)를 정합니다.
2. **기준선** — **계약 기준값** 또는 **기준 기간 실적**(비교할 기간을 고름).
3. **목표**(%)를 넣고 **계산**을 누릅니다.
4. 결과: 공수 절감(유형 구성 보정, `목표 달성`/`미달`), 리드타임 단축, 해결한 요청, 커밋 연결률, AI 관여 요청, **AI 관여 여부별**·**유형별** 표, **해결한 요청** 목록.
5. **보고서(MD)** · **요청 목록(CSV)** 으로 내려받습니다.

> **주의** **해석 시 주의** 상자를 꼭 읽으세요. 건수가 적거나(20건 미만), 커밋과 이어진 요청이 적거나, 기준선이 없는 유형·공수 기록이 없는 요청이 있으면 숫자를 그대로 쓰면 안 됩니다.

## 모델 평가

게이트웨이 모델 별칭 여러 개를 통합ITO 정답 세트로 견주고, 세트(업무)마다 권장 별칭을 고릅니다. 에이전트·흐름의 결과 채점은 [에이전트 평가](/user/platform/eval.md)를 쓰세요.

<figure><img src="img/platform/a-eval.png" alt="평가 › 모델 평가 — 새 평가 카드(견줄 모델 별칭, 정답 세트 체크 4개, 이름, 평가 시작), 아래 사내 모델 분류 점검 결과 표(세트별 hnix-local·hnix-smart 통과율·점수·평균·p95·토큰, 권장 열과 업무 별칭에 반영 버튼)"><figcaption>모델 평가 — 새 평가와 최근 결과 표</figcaption></figure>

### 평가 실행

1. **새 평가**에서 **견줄 모델 별칭**(대화 별칭, 여러 개)을 고릅니다.
2. **정답 세트**를 체크합니다 — 기본 세트: 근거 답변(현업 창구) · 지식 문서 초안 형식 · 서비스 요청 유형·우선순위 분류 · 도구 호출(PMS-X·문서 조회).
3. **이름**(선택)을 적고 **평가 시작**을 누릅니다. 진행 막대가 차고, 실행 중이면 **멈추기**로 세울 수 있습니다.

> **주의** 사례마다 모델을 한 번씩 부릅니다 — 외부 모델이면 비용이 듭니다. 호출은 게이트웨이를 지나 사용량에 `client=eval` 로 남습니다.

### 결과 보기

- 결과 표: 세트 × 별칭마다 `통과 N%` · 점수 · 평균 · p95 · 토큰. 통과 기준(기본 80%)을 넘는 별칭 중 **가장 빠른 것**에 `권장`.
- **사례별 결과**: 별칭·세트로 거르고 **실패만** 스위치로 실패 사례의 사유·모델 출력을 봅니다.
- **실행 기록**에서 지난 평가를 눌러 다시 봅니다.

### 업무 별칭에 반영

1. 결과 표 **권장** 열의 **업무 별칭에 반영**을 누릅니다.
2. 바꿀 **업무 별칭**(예: PMS-X·창구가 쓰는 별칭)을 고르고 **반영**합니다.

> **주의** 고른 업무 별칭의 대상 모델이 권장 별칭과 같게 바뀝니다. 그 별칭을 쓰는 PMS-X·현업 창구·에이전트가 모두 새 모델을 씁니다(감사 로그에 남음).

### 사내 세트 올리기

**정답 세트** 카드에서 기본 세트의 **사례 보기**로 JSON 형식을 확인한 뒤 **사내 세트 올리기**에 **세트 키**와 **세트 JSON**(kind: classify · grounded · tool · contains)을 넣고 **저장**합니다. 실제 요청·문의로 만들 때는 개인정보를 지우고 넣으세요.
