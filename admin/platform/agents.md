# 에이전트 · 자동 실행 관리

> 플랫폼 에이전트를 만들고 공유 승인하고, 템플릿(ITO 기본 에이전트)과 외부 에이전트를 들이고, 웹훅·예약·감시 **자동 실행**(트리거)으로 사람 대신 깨웁니다. **대상**: 시스템 관리자. **메뉴**: 에이전트·자동화 › 에이전트.

## 화면 구성

<figure><img src="img/platform/a-agents.png" alt="관리자 에이전트 화면 — 맨 위 에이전트 카드 목록(전체 2·내 것 1·외부 1 거르기, 구매팀 LangGraph 에이전트·SM 운영 도우미 카드와 실행하기·수정·평가·자동 실행 단추), 오른쪽 위 에이전트 추가 단추, 아래 왼쪽 에이전트 실행 칸(SM 운영 도우미 고름, 모델 hnix-local, 내가 쓸 수 있는 도구 꼬리표, 입력칸, 자세히 기록, 실행), 오른쪽 실행 결과, 맨 아래 실행 기록 표"><figcaption>관리자에게 보이는 에이전트 화면 — 카드의 '자동 실행' 단추와 실행 칸의 '자동 실행 설정'은 시스템 관리자만 보입니다</figcaption></figure>

| 영역 | 하는 일 | 권한 |
|---|---|---|
| **에이전트 추가** | 템플릿에서 · 직접 만들기 · 외부 에이전트 연결 중 고르기(아래 '에이전트 추가 — 세 가지 길') | 템플릿·외부 연결은 시스템 관리자, 직접 만들기는 누구나 |
| 카드 목록 · 거르기 | **전체 · 내 것 · 함께 쓰는 것 · 외부**(있는 것만 보임). 에이전트가 7개 이상이면 이름·설명으로 찾는 칸 | 누구나 |
| 카드 | 화면 이름, 꼬리표(**외부 · 내 것 · 나만 · 공유 요청 중 · 꺼짐 · A2A 공개**), 부르는 이름, 하는 일, 모델·도구 요약, 최근 실행 | 누구나 |
| 카드 단추 | **실행하기**(아래 실행 칸에 고름) · **수정** · **평가**([에이전트 평가](/user/platform/eval.md)) · **자동 실행**(오른쪽 서랍) | 수정은 만든 사람과 시스템 관리자, 자동 실행은 시스템 관리자 |
| **에이전트 실행** | 고른 에이전트의 설명·모델·도구, 입력칸, 자세히 기록, **실행**. 머리의 **자동 실행 설정**은 카드의 **자동 실행**과 같음 | 누구나 |
| 실행 결과 · 실행 기록 | 실행·결과 확인 | 누구나(관리자는 전체 실행) |

에이전트를 실행하고 결과·단계를 보는 방법은 [에이전트 실행과 내 에이전트](/user/platform/agents.md)를 보세요.

## 에이전트 추가 — 세 가지 길

<figure><img src="img/platform/a-agents-add.png" alt="에이전트 추가 창 — 템플릿에서(추천 꼬리표, 경보 진단·서비스 요청 분류 보조 같은 운영용 에이전트를 골라 바로 설치), 직접 만들기(이름과 하는 일을 적고 쓸 도구를 고르면 AI가 지시문 초안을 써 줌), 외부 에이전트 연결(관리자 꼬리표, 다른 팀·다른 플랫폼에서 이미 만든 에이전트를 연결) 세 상자"><figcaption>오른쪽 위 [에이전트 추가]를 누르면 나오는 고르기 창(관리자)</figcaption></figure>

| 고르는 것 | 언제 | 이어지는 창 |
|---|---|---|
| **템플릿에서** (추천) | 통합ITO 운영에 바로 쓰는 에이전트를 자동 실행까지 한 번에 | [템플릿에서 추가](/admin/platform/agents.md#템플릿에서-추가) |
| **직접 만들기** | 우리 업무에 맞는 에이전트를 새로 | [직접 만들기 · 수정](/admin/platform/agents.md#직접-만들기와-수정) |
| **외부 에이전트 연결** (관리자) | 다른 팀·플랫폼에서 이미 만든 에이전트를 여기서 실행·평가·자동 실행 | [외부 에이전트 연결](/admin/platform/agents.md#외부-에이전트-연결) |

> **참고** 사용자에게는 **템플릿에서**가 흐리게(*관리자가 설치합니다*) 보이고 **외부 에이전트 연결**은 보이지 않습니다.

## 직접 만들기와 수정

1. **에이전트 추가 › 직접 만들기**를 누르거나, 카드의 **수정**을 누릅니다(외부 에이전트는 연결 창이 열립니다).
2. 칸을 채웁니다. 순서대로 채우면 됩니다.

| 칸 | 내용 |
|---|---|
| 이름 | 화면에 보일 이름. 한글로 씁니다(예: *장애 접수 도우미*) |
| 무슨 일을 하나요? | 한 줄 설명(200자 안). 카드와 평가 화면에 보이고, AI 지시문 초안의 재료가 됩니다 |
| 쓸 도구 | 내가 쓸 수 있는 허브 도구가 서버별로 접혀 나옵니다. 하나씩 체크하거나 서버 줄의 체크칸으로 통째로 고릅니다. **쓰기** 꼬리표는 데이터를 바꾸는 도구 |
| 모델 | 게이트웨이의 켜진 대화 별칭. 도구를 골랐는데 도구 호출에 약한 모델이면 *도구 호출은 ○○ 모델이 잘합니다* 줄과 **○○로 바꾸기**가 나옵니다 |
| 지시문 | 에이전트가 따를 역할·순서·답 형식. **AI로 지시문 초안**으로 채운 뒤 고칩니다(아래) |
| **고급** (접힘) | 아래 표 |

| 고급 칸 | 내용 |
|---|---|
| 부르는 이름 (영문) | IDE·Claude Code 에서 `agents__run` 으로 부를 때 쓰는 이름. 이름을 적으면 저절로 제안됩니다(영문 소문자로 시작, 소문자·숫자·하이픈 2~40자). 만든 뒤에는 바꿀 수 없습니다 |
| 직접 적은 도구 규칙 | 목록에 없는 도구(꺼진 서버, 내게 안 보이는 도구)를 이름이나 `*` 규칙(예: `pmsx__*`)으로 |
| 최대 턴 | 모델을 부르는 최대 횟수 1~30(기본 8) |
| 사용 | 끄면 카드에 `꺼짐` 이 붙고 실행할 수 없습니다 |
| 자세히 기록 | 켜면 모든 실행의 단계 본문을 개인정보를 가려 보존 기한 동안 보관 |
| 누가 쓰나 | 관리자는 **나만** · **공개 (워크스페이스)**(새로 만들면 공개가 기본) |
| A2A 로 외부 공개 | 관리자만. 다른 플랫폼의 에이전트가 이 에이전트를 부를 수 있음 |

3. **만들기**(수정이면 **저장**)를 누릅니다. 비어 있는 칸은 창 왼쪽 아래 *채울 것: …* 에 나오고, 다 채워야 눌립니다. 수정 창 왼쪽 아래 **지우기**는 에이전트와 연결된 자동 실행을 함께 지웁니다.

> **참고** 서버를 통째로 고르면 그 서버에 나중에 생기는 도구도 씁니다. 그래도 실행은 **실행한 사람 권한**으로 돕니다 — 그 사람에게 보이지 않는 도구는 쓰지 못하고, 승인 정책에 걸리면 멈춥니다.
> **참고** A2A 공개를 켜면 카드 주소(`…/a2a/<부르는 이름>/.well-known/agent-card.json`)가 보입니다. 부르는 쪽에는 `a2a` 권한 키가 필요하고, 키 주인 권한으로 실행됩니다.
> **참고** 자세히 기록의 보존 일수는 서버 설정 `agents.debugRetentionDays`(기본 7일)입니다. 본문은 실행한 사람과 관리자·감사자만 봅니다.

### AI로 지시문 초안

1. **이름**과 **무슨 일을 하나요?** 를 적고 **쓸 도구**를 고릅니다.
2. 지시문 칸 위 **AI로 지시문 초안**을 누릅니다(하는 일과 모델이 있어야 눌립니다).
3. 고른 모델이 하는 일·도구에 맞춰 지시문을 써 넣습니다. 읽어 보고 고친 뒤 저장하세요. 이미 적어 둔 지시문을 덮었으면 **이전 지시문으로 되돌리기**가 나옵니다.

> **참고** 초안은 저장되지 않습니다. 모델 호출은 누른 사람 권한으로 게이트웨이를 거치므로 예산·개인정보 가리기가 채팅과 같고, 감사 기록에는 본문 없이 모델·글 길이·도구 수만 남습니다.

## 공유 요청 승인

사용자가 만든 에이전트에서 **고급 › 누가 쓰나**를 **팀에 공유 요청 (관리자 승인)** 으로 두면 카드에 `공유 요청 중` 꼬리표가 붙습니다.

1. 그 카드의 **실행하기**를 누릅니다(또는 실행 칸의 고르는 칸에서 `· 공유 요청 중` 인 에이전트를 고릅니다).
2. 실행 칸의 노란 안내 상자에서 지시문·도구를 확인합니다(필요하면 **수정**).
3. **공개 승인**(워크스페이스 사람들이 실행 가능) 또는 **돌려보내기**(만든 사람만 봄)를 누릅니다.

업무 자동화의 공유 요청도 같은 방법으로 흐름 편집기에서 결정합니다([업무 자동화](/admin/platform/automation.md#공개와-공유-승인)).

## 템플릿에서 추가

<figure><img src="img/platform/a-agents-templates.png" alt="템플릿에서 추가 — ITO 기본 에이전트 창. 경보 진단(웹훅·모니터링 경보), 서비스 요청 분류 보조(감시·새 요청 감시), 변경 영향 리포트(웹훅·CI 변경 알림), 주간 운영보고 초안(예약·매주 월요일 08:00) 카드마다 하는 일·필요한 연결·쓰는 도구와 설치 단추"><figcaption>에이전트 추가 › 템플릿에서 — 설치하면 자동 실행까지 함께 만들어집니다</figcaption></figure>

| 템플릿 | 자동 실행 | 하는 일 | 필요 |
|---|---|---|---|
| 경보 진단 | 웹훅 · 모니터링 경보 | 비슷한 과거 장애·서비스 요청·지식 문서와 운영 매뉴얼로 원인 후보와 확인 순서 정리 | PMS-X 커넥터, 문서 검색의 운영 매뉴얼 |
| 서비스 요청 분류 보조 | 감시 · 새 요청 감시 | 새 요청의 유형·우선순위·대상 화면·담당 후보 의견 | PMS-X 커넥터 |
| 변경 영향 리포트 | 웹훅 · CI 변경 알림 | 변경 내용으로 영향받는 화면·SQL·테이블과 볼 테스트 정리 | AX-NAVI 커넥터, PMS-X 커넥터 |
| 주간 운영보고 초안 | 예약 · 매주 월요일 08:00 | 처리 기한 현황과 요청 현황으로 보고 초안 | PMS-X 커넥터 |

1. **에이전트 추가 › 템플릿에서**를 누릅니다. *템플릿에서 추가 — ITO 기본 에이전트* 창이 열립니다.
2. 카드의 **설치**를 누르면 입력 칸이 열립니다.
3. **모델 별칭**을 고르고, **PMS-X SM 프로젝트 ID**(PMS-X 프로젝트 ID, `pmsx__projects` 도구로 확인)를 넣습니다.
4. **설치**를 누릅니다. 웹훅 템플릿이면 **웹훅 연결 정보** 창에 주소와 토큰이 **한 번만** 보입니다 — 모니터링 도구·CI 설정에 바로 넣으세요.

> **참고** 템플릿 도구는 모두 읽기 전용이고, 조치는 사람에게 제안만 합니다. 이미 설치한 템플릿은 `설치됨` 으로 표시되고 다시 설치할 수 없습니다.

## 외부 에이전트 연결

<figure><img src="img/platform/a-agents-external.png" alt="외부 에이전트 연결 창 1단계 — 안내 문장, 종류·주소·인증·연결 시험·이름·공개 범위 4단계 표시와 A2A 에이전트·LangGraph 서버·OpenAI 호환 채팅·일반 HTTP 네 상자(상자마다 언제 고르는지 한 줄과 기술 설명)"><figcaption>에이전트 추가 › 외부 에이전트 연결 — 4단계로 등록합니다</figcaption></figure>

다른 팀·다른 플랫폼에서 이미 만든 에이전트를 플랫폼 에이전트(`외부` 종류)로 등록합니다. 등록하면 실행 기록, 업무 자동화의 '에이전트에게 맡기기' 단계, 에이전트 평가, 자동 실행, MCP `agents__run` 에서 다른 에이전트처럼 씁니다.

1. **에이전트 추가 › 외부 에이전트 연결**을 누릅니다.
2. **종류** — 상자마다 *언제 고르는지*가 적혀 있습니다. 상대가 에이전트 카드 주소를 주면 A2A 에이전트, 개발팀이 LangGraph 로 만들었으면 LangGraph 서버, 'OpenAI 방식으로 부를 수 있다'면 OpenAI 호환 채팅, 그 밖의 사내 API 면 일반 HTTP 를 고르고 **다음**.
3. **주소·인증**

| 칸 | 내용 |
|---|---|
| 주소 | `http(s)://` 주소 |
| LangGraph | 어시스턴트(그래프) 이름 또는 ID, 대화마다 스레드로 이어 묻기 |
| OpenAI 호환 | model 값(서버가 요구할 때만) |
| 일반 HTTP | 요청 본문 템플릿(JSON, `{{input}}` 자리에 질문), 응답에서 답을 꺼낼 경로(예: `data.answer`) |
| 인증 | 없음 · Bearer 토큰 · API 키 머리글(머리글 이름) + 비밀값 |
| 시간 제한 (초) | 1~600 |
| 사내 주소만 허용 | 기본 켜짐. **끄면 사외 주소도 부릅니다(관리자만)** |

4. **연결 시험** — 작은 입력으로 한 번 불러 답을 꺼낼 수 있는지 봅니다(저장하지 않음). `연결됨 · N초` 또는 실패 이유가 나옵니다.
5. **이름·공개 범위** — 이름, 설명, 사용, 누가 쓰나, 자세히 기록, (관리자) A2A 로 다시 공개를 정하고 **연결**을 누릅니다.

> **주의** 외부 에이전트가 모델을 직접 부르면 플랫폼의 예산·개인정보 보호를 거치지 않습니다. 외부 에이전트에는 게이트웨이 가상 키(`hx-`)를 주고 모델 주소를 플랫폼의 `/v1` 로 두게 하세요.
> **참고** 비밀값은 시크릿 저장소에 보관하고 다시 보여 주지 않습니다. 고칠 때 비워 두면 기존 값을 유지합니다.
> **참고** 화면의 [에이전트 추가]에서는 시스템 관리자에게만 **외부 에이전트 연결**이 보입니다. API(`POST /api/v1/agents/external`)로 누가 등록할 수 있는지는 서버 설정 `agents.externalImport` 로 정합니다(`all` = 누구나 '내 에이전트'로, `admin` = 관리자만). 설정 파일은 [운영](/admin/operations.md)을 보세요.

외부 에이전트 카드의 **수정**을 누르면 같은 창이 2단계(주소·인증)부터 열립니다.

## 자동 실행 — 웹훅 · 예약 · 감시

카드의 **자동 실행**(또는 실행 칸 머리의 **자동 실행 설정**)을 누르면 오른쪽에 *자동 실행 — 에이전트 이름* 서랍이 열리고, 그 에이전트의 자동 실행(트리거)이 보입니다. 닫으려면 오른쪽 위 ×.

### 자동 실행 추가

<figure><img src="img/platform/a-agents-trigger-edit.png" alt="서랍 위에 열린 자동 실행 추가 창 — 종류(웹훅 — 경보·CI 가 부름)·이름·실행 계정, 에이전트에 줄 입력({{body}} 자리표시), 중복 키·중복 무시(분)·시간당 최대 실행, 결과 알림 주소·알림 형식, 사용 스위치, 취소·저장"><figcaption>자동 실행 추가 창</figcaption></figure>

1. 서랍의 **자동 실행 추가**를 누릅니다.
2. **종류**를 고릅니다(만든 뒤에는 바꿀 수 없음).

| 종류 | 깨우는 때 | 추가 칸 | 입력 자리표시 |
|---|---|---|---|
| 웹훅 — 경보·CI 가 부름 | 외부 시스템이 웹훅 주소를 부를 때 | 없음(저장하면 주소·토큰 발급) | `{{body}}`, `{{body.필드}}` |
| 예약 — cron | 정한 시각 | cron(분 시 일 월 요일, 서버 현지 시간). 예: `0 8 * * 1` = 매주 월요일 08:00 | `{{now}}` |
| 감시 — 새 항목마다 | 읽기 도구 결과에 새 항목이 생길 때 | 감시할 허브 도구(읽기 전용), 도구 입력값(JSON), 목록 위치, 항목 ID 필드, 간격(분), 한 번에 최대 | `{{item}}`, `{{item.필드}}` |

3. 공통 칸을 채웁니다.

| 칸 | 내용 |
|---|---|
| 이름 | 예: 모니터링 경보 |
| 실행 계정 (비우면 나) | 이 계정 권한으로 실행. 그 계정의 예산·개인정보 규칙·도구 정책이 그대로 걸립니다 |
| 에이전트에 줄 입력 | 자리표시를 넣은 지시 문장 |
| 중복 키 · 중복 무시 (분) | 예: `{{body.alertId}}` 가 같으면 N분 동안 한 번만 |
| 시간당 최대 실행 | 1~600 |
| 결과 알림 주소 · 알림 형식 | Teams·Slack 수신 웹훅 등(선택), 형식 Teams · Slack · JSON |
| 사용 | 끄면 깨우지 않습니다 |

4. **저장**합니다. 웹훅이면 **웹훅 토큰 — 지금 한 번만 보입니다** 창에 주소, 토큰, 시험용 curl 예시가 나옵니다.

> **참고** 감시 자동 실행은 처음 감시할 때 이미 있는 항목을 기준선으로만 기록하고 깨우지 않습니다.
> **참고** 승인이 필요한 도구는 승인함에서 결정되면 자동으로 이어서 실행합니다. 경보 본문은 데이터로만 다루도록 지시문에 적어 두세요.
> **참고** 웹훅 토큰은 `X-HNIX-Token` 머리글, `Authorization: Bearer`, 또는 주소 뒤 `?token=` 으로 보냅니다.

### 자동 실행 줄의 버튼

| 버튼 | 하는 일 |
|---|---|
| **지금 실행** | 시험 본문(`{test: true}`)으로 바로 한 번 깨웁니다. 실행되면 서랍이 닫히고 결과가 실행 결과 칸에 열립니다 |
| **기록** | 깨운 기록 — 시각, 경로, 결과(`실행` · `건너뜀` · `한도` · `오류`), 실행 보기, 알림 결과, 중복 키·내용 |
| **토큰 다시 만들기** | 웹훅만. 새 토큰을 한 번 보여 주고 옛 토큰은 못 쓰게 됩니다 |
| **수정** | 설정 변경. 결과 알림 주소는 비워 두면 기존 주소를 유지합니다 |
| **삭제** | 자동 실행 설정과 깨운 기록을 지웁니다 |

줄 아래에 웹훅 주소(또는 cron·다음 시각, 감시 도구·간격·본 항목 수), 마지막 깨운 시각과 결과, 시간당 최대, 중복 규칙이 보입니다. 실행 기록 표에서 자동 실행으로 돈 실행에는 `자동 실행` 꼬리표가 붙습니다.

> **주의** 토큰을 잃어버리면 다시 볼 수 없습니다. **토큰 다시 만들기** 후 외부 시스템 설정을 새 토큰으로 바꾸세요.
