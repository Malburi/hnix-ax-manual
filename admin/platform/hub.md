# MCP 허브 · 정책 · 승인

> 에이전트가 쓰는 업무 도구를 한 주소로 모으고, 정책으로 거르고, 위험한 호출은 사람이 승인합니다. **대상**: 시스템 관리자(설정·승인), 감사자(조회). **메뉴**: AI 통제 › MCP 허브, 맨 위 **승인함**.

## 화면 구성

MCP 허브는 위쪽 탭으로 오갑니다(주소 `?tab=servers` 처럼 바로 열 수 있음).

| 탭 | 하는 일 | 보이는 사람 |
|---|---|---|
| **개요** | 흐름 그림, 오늘 도구 호출·정책 거부·승인 대기, 도구 서버 상태, 많이 쓴 도구 | 모두 |
| **연결 · 내 도구** | 클라이언트 연결 방법과 내가 쓸 수 있는 도구, 도구 시험 | 모두 |
| **서버** | 도구 서버 등록·동기화 | 시스템 관리자·감사자 |
| **도구 승인** | 외부 도구 승인, 스키마 변경 재승인, 도구 끄고 켜기 | 시스템 관리자·감사자 |
| **정책** | 누가 어떤 도구를 쓰는지 — 허용·차단·사람 승인 | 시스템 관리자·감사자 |
| **호출 기록** | 도구 호출 기록(인자 값은 저장하지 않음) | 모두(관리자·감사자는 전체) |

승인 대기 목록은 허브 탭이 아니라 왼쪽 메뉴 맨 위 **승인함**에 있습니다. 옛 주소(`/hub?tab=approvals`)로 들어와도 승인함으로 넘어갑니다.

> **참고** 감사자는 모든 탭을 보지만 **서버 등록 · 동기화 · 승인 · 규칙 추가** 같은 버튼이 보이지 않습니다. 승인함에서도 결정은 시스템 관리자만 합니다.

`연결 · 내 도구` 탭 사용법은 [MCP 허브 — 내 도구 쓰기](/user/platform/hub.md)를 보세요.

## 서버 등록과 동기화

<figure><img src="img/platform/a-hub-servers.png" alt="MCP 허브 서버 탭 — axnavi·agents·docs·evals·flows·itsm·platform·runbook·datalake·pmsx 서버 표와 각 행의 동기화·수정·삭제 버튼"><figcaption>서버 탭 — 내장 서버는 동기화만, 직접 등록한 서버는 수정·삭제도 됩니다</figcaption></figure>

| 열 | 내용 |
|---|---|
| 이름 | 도구 이름 앞에 붙는 이름(예: `pmsx` → `pmsx__sr`) |
| 종류 | 내장 · PMS-X (As-Is·서비스 요청·영향도) · AX-NAVI (코드 인덱스) · 외부 MCP 서버 (Streamable HTTP) · 외부 에이전트 (A2A) |
| 연결 | 주소 또는 설치 폴더. 내장은 `플랫폼 내장` |
| 도구 · 상태 | 받은 도구 수, `정상` · `오류` · `미확인` 과 마지막 동기화 시각, 오류 내용 |

### 서버 등록

1. **서버** 탭에서 **서버 등록**을 누릅니다.
2. **종류**와 **이름**을 정합니다(둘 다 등록 뒤에는 바꿀 수 없습니다).
3. 종류에 따라 칸이 바뀝니다.

| 종류 | 넣는 값 |
|---|---|
| PMS-X | **PMS-X 주소**, **서비스 계정**(조회 전용 계정 ID), **비밀번호** |
| AX-NAVI | **AX-NAVI 설치 폴더**, **저장소**(한 줄에 `이름=경로`) |
| 외부 MCP 서버 | **MCP 주소**, **토큰**(Bearer, 없으면 비움) |

4. **설명**을 적고 **저장 후 동기화**를 누릅니다. 도구 목록을 받아 오면 `저장했습니다 — 도구 N개` 가 뜹니다. 받아 오지 못하면 창 아래에 이유가 나옵니다(저장은 됨).

> **참고** PMS-X·AX-NAVI 커넥터는 읽기 전용이며 등록 즉시 도구가 승인됩니다. 외부 MCP 서버의 도구는 **도구 승인** 탭에서 승인해야 쓸 수 있습니다.
> **참고** 비밀번호·토큰은 수정할 때 비워 두면 기존 값을 유지합니다.

### 동기화

행의 **동기화**를 누르면 서버의 도구 목록을 다시 받습니다. 결과에 `새로 · 변경 · 사라짐` 개수가 나옵니다. 바뀐 외부 도구는 **도구 승인** 탭에서 다시 승인할 때까지 막힙니다.

- 내장 서버(agents·docs·flows 등)는 **동기화**만 됩니다.
- [업무 시스템 연결](/admin/platform/integrations.md#업무-시스템-연결)에서 만든 서버는 `업무 시스템 연결에서 관리` 로 표시되고 여기서는 동기화만 됩니다.

## 도구 승인과 스키마 변경

<figure><img src="img/platform/a-hub-tools.png" alt="도구 승인 탭 — 도구 이름과 서버, 설명, 조회/쓰기 꼬리표, 스키마 보기 버튼, 상태(사용 중), 켜고 끄는 스위치가 있는 표"><figcaption>도구 승인 탭 — 도구마다 조회/쓰기, 스키마, 상태, 켜기 스위치</figcaption></figure>

외부 도구는 스키마(설명·인자)를 승인한 그대로만 씁니다.

| 상태 | 뜻 | 할 일 |
|---|---|---|
| 사용 중 | 승인됨, 켜짐 | 스위치로 끄기 |
| 승인 대기 | 새로 받은 외부 도구 | **승인** |
| 스키마 변경 | 승인 뒤 서버에서 설명·인자가 바뀜 — 막힘 | **스키마** › **보기**로 확인 후 **변경 확인·재승인** |
| 꺼짐 | 관리자가 끔 | 스위치로 켜기 |
| 서버에서 사라짐 · 서버 꺼짐 | 서버 쪽 사정 | 서버 탭에서 확인 |

1. 오른쪽 위 **서버 전체**·**상태 전체** 목록으로 걸러 봅니다. `확인 필요 N건` 이 보이면 승인 대기·스키마 변경이 있다는 뜻입니다.
2. **보기**로 인자 스키마(JSON)를 확인합니다.
3. **승인** 또는 **변경 확인·재승인**을 누릅니다.

> **주의** 조회/쓰기 꼬리표가 `쓰기` 인 도구는 업무 데이터를 바꿀 수 있습니다. 승인 전에 아래 정책으로 **사람 승인 필요**를 걸어 두세요.

## 정책 규칙

<figure><img src="img/platform/a-hub-policies.png" alt="정책 탭 — 순서·이름·조건·동작·사용 열의 규칙 표. 런북 실행은 사람 승인, 요청 상세 조회는 승인 후, 서버 색인 다시 만들기는 사람 승인 규칙"><figcaption>정책 탭 — 시연 환경의 '사람 승인 필요' 규칙 3개</figcaption></figure>

순서가 작은 규칙부터 보고 **처음 맞는 하나만** 적용합니다. 아무 규칙에도 맞지 않으면 **허용**입니다.

1. **정책** 탭에서 **규칙 추가**를 누릅니다.
2. 칸을 채웁니다.

| 칸 | 내용 |
|---|---|
| 이름 · 순서 | 예: `쓰기 도구는 운영팀만`, 순서 숫자가 작을수록 먼저 |
| 서버 | 이 서버의 도구만(여러 개, 비우면 전체) |
| 도구 패턴 | 도구 이름 패턴. 예: `pmsx__*`, `*__delete*` |
| 역할 | 시스템 관리자 · 감사자 · 사용자(비우면 전체) |
| 쓰기 도구만 | 켜면 쓰기 도구에만 맞음 |
| 동작 | **차단** · **사람 승인 필요** · **허용** |
| 안내 문구 | 막힐 때 에이전트에게 보여 줄 말 |

3. **저장**합니다.

- **차단**된 도구는 에이전트의 도구 목록에서 아예 빠집니다.
- **사람 승인 필요**는 승인함에서 결정될 때까지 실행되지 않습니다.
- 런북을 켜면 순서 1의 **런북 실행은 사람 승인** 규칙이 자동으로 생깁니다. 이 규칙을 지우거나 끄면 런북 실행 요청이 `승인 없이 실행할 수 없습니다` 로 실패합니다.
- 업무 시스템 연결의 쓰기 도구는 연결을 만들 때 고른 기본 정책(대개 **승인 필요**)을 따릅니다.

## 승인함 — 검토 · 승인 · 반려

왼쪽 메뉴 맨 위 **승인함** 옆 빨간 숫자는 **내가 결정할 수 있는 대기 건수**입니다(내가 요청한 건은 세지 않습니다. 20건이 넘으면 `20+`).

여기에는 세 종류가 쌓입니다.

- 에이전트·채팅의 도구 호출 중 **사람 승인 필요** 정책에 걸린 것
- 런북 **실행 요청**(`runbook__…`) — [런북](/admin/platform/automation.md#런북)
- 자동화 흐름의 **사람 확인** 단계(`flows__confirm`)

<figure><img src="img/platform/a-approvals-review.png" alt="승인함 — 대기 2건 목록 위에 도구 호출 승인 창이 열려 있음. 요청자·도구·정책 사유·인자 JSON·결정 사유 칸·반려·승인 버튼"><figcaption>승인함에서 검토를 눌러 연 도구 호출 승인 창</figcaption></figure>

### 한 건씩 결정

1. **승인함**을 엽니다. 기본은 **대기**만 보입니다(**전체**를 누르면 결정된 것도).
2. 행의 **검토**를 누릅니다(내가 낸 요청에는 검토 버튼이 없습니다 — 다른 관리자가 결정합니다).
3. 창에서 요청자, 도구, 걸린 정책과 사유, **인자 원문(JSON)** 을 확인합니다.
4. 필요하면 **결정 사유**를 적고(요청자에게 보임) **승인** 또는 **반려**를 누릅니다.

| 결과 | 그 뒤 |
|---|---|
| 도구 호출 승인 | 요청자가 **같은 인자로 다시 부르면 한 번** 실행됩니다. 트리거로 깨운 에이전트 실행은 자동으로 이어지고, 화면에서 실행한 에이전트는 실행한 사람이 **이어서 실행**을 누릅니다 |
| 흐름 사람 확인 승인 | 자동화 흐름이 이어서 진행합니다. 반려하면 흐름의 '거부' 갈래로 갑니다 |
| 반려 | 실행되지 않습니다 |

### 여러 건 한꺼번에

1. 행 앞 칸을 체크합니다(대기 중이고 내 요청이 아닌 것만 체크됩니다).
2. 위에 나타난 줄에 **결정 사유**(선택, 요청자 모두에게 보임)를 적습니다.
3. **선택 승인**(확인 창이 한 번 더 뜸) 또는 **선택 반려**를 누릅니다. **선택 해제**로 취소합니다.
4. 일부가 실패하면 `N건 승인, M건 실패` 와 첫 실패 이유가 나옵니다.

> **주의** 선택 승인은 인자를 하나씩 보지 않고 승인합니다. 쓰기 도구·런북은 한 건씩 검토하세요.

| 규칙 | 내용 |
|---|---|
| 자기 요청 | 스스로 승인·반려할 수 없습니다. 다른 관리자가 결정합니다 |
| 기한 | 요청 뒤 하루 안에 결정하지 않으면 `만료` |
| 승인 효력 | 결정 시각부터 하루, 같은 인자로 한 번 |
| 인자 원문 | 결정 전까지만 보관합니다 |

상태 꼬리표: `대기` · `승인` · `반려` · `실행됨` · `만료`. **경로** 열에는 요청한 클라이언트(web 등) 또는 에이전트 실행 번호가 나옵니다.

> **참고** [알림 보내기](/admin/platform/integrations.md#알림-보내기)를 켜면 승인 요청을 Teams·Slack·메일로 받습니다.

## 호출 기록

허브를 지난 모든 도구 호출입니다. 인자 값과 결과 본문은 저장하지 않습니다(개인정보·소스 코드가 들어갈 수 있음).

| 열 | 내용 |
|---|---|
| 시각 · 사용자 · 클라이언트 · 도구 | |
| 인자 | 인자 **이름**과 크기 |
| 결과 | `성공` · `오류` · `차단`. 마우스를 올리면 오류 내용 |
| 응답 · 시간 | 응답 크기, 걸린 시간 |

최근 300건을 보여 주며 **새로고침**으로 다시 읽습니다.

## 자주 묻는 질문

**Q. 승인함 숫자는 1인데 목록에는 2건입니다.** 한 건은 내가 요청한 것입니다. 자기 요청은 결정할 수 없어 배지에서 뺍니다.

**Q. 승인했는데 실행이 안 됐습니다.** 도구 호출 승인은 요청자가 같은 인자로 다시 불러야 실행됩니다. 하루가 지나면 승인이 만료됩니다.
