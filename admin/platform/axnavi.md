# AX-NAVI 사용 허가 · 조직 설정

> 누가 AX-NAVI IDE 를 쓸 수 있는지(사용 허가), 어떤 기기가 연결됐는지, 밖에서 발견한 지침 글이 어느 기기에서 나왔는지 확인하고, 규칙·양식·스킬·MCP 묶음을 전사·팀에 배포합니다. **대상**: 시스템 관리자(변경), 감사자(조회). **메뉴**: 관리 › AX-NAVI 관리(화면 위 **사용 허가** · **조직 설정**).

## 화면 구성

| 묶음 탭 | 화면 안 | 하는 일 |
|---|---|---|
| **사용 허가** | **사용 허가 (N)** · **기기 (N)** · **유출본 확인** | 사람별 허가·엔진, 연결된 기기 끊기, 표식으로 유출본 출처 찾기 |
| **조직 설정** | 설정 묶음 · 파일 편집 · 배포 이력 · 받아 간 기록 | 규칙·양식·스킬·MCP·정책 배포 |

화면 위 파란 안내 상자에 지금 서버 설정이 요약됩니다 — 예: `허가한 사람만 · 1인 기기 2대 · 사용권 60분마다 갱신 · 플랫폼에 닿지 않을 때 3일까지 사용`.

| 서버 설정(hnix-ax.yaml `axnavi` 절) | 뜻 | 기본 |
|---|---|---|
| `seats` | `listed` = 관리자가 허가한 사람만, `all` = 활성 사용자 모두 | listed |
| `maxDevices` | 1인 기기 수 | 2 |
| `licenseMinutes` | 사용권 갱신 간격(분) | 60 |
| `offlineDays` | 플랫폼에 닿지 않을 때 쓸 수 있는 날 | 3 |
| `defaultEngine` | 새 허가의 엔진(local · server) | local |

설정 파일은 [운영](/admin/operations.md), AX-NAVI 서버 엔진은 [AX-NAVI 관리 개요](/admin/axnavi/README.md)를 보세요. 사용자가 기기를 승인받는 과정은 [설치 · 로그인 · 기기 승인](/user/axnavi/install.md)에 있습니다.

## 사용 허가

<figure><img src="img/platform/a-axnavi-seats.png" alt="AX-NAVI 관리 › 사용 허가 탭 — 안내 상자, 사용 허가(2)·기기(1)·유출본 확인 탭, 이름·ID·팀 찾기 칸, 사용자·팀·허가 스위치·엔진(PC(IDE 에 자동 설치))·기기(1/2)·마지막 사용·메모 열의 표"><figcaption>사용 허가 — 사람마다 허가 스위치, 엔진, 기기 수, 메모</figcaption></figure>

AX-NAVI IDE 는 이 플랫폼에서 기기 승인을 받아야 동작합니다. 개발 PC 에는 IDE 만 설치하고, 스킬·에이전트와 분석 엔진은 로그인한 기기에만 내려갑니다. 내려갈 때 기기마다 보이지 않는 표식이 들어갑니다.

1. **이름·ID·팀으로 찾기** 칸으로 사람을 찾습니다.
2. **허가** 스위치를 켭니다. 끄면 그 사람의 기기 연결이 모두 끊기고 `기기 N대의 연결을 끊었습니다` 가 뜹니다.
3. **엔진**을 고릅니다.

| 엔진 | 뜻 |
|---|---|
| PC(IDE 에 자동 설치) | 로그인한 IDE 에 분석 엔진이 자동으로 깔려 CLI 와 똑같이 씁니다 |
| 서버만 | PC 에 엔진을 두지 않고 서버 엔진으로만 씁니다(외주 인력 등). 검증 빌드·하네스 초기화·위키 생성 스킬은 빠집니다 |

4. **메모** 칸에 계약·소속을 적습니다(예: `운영 1팀 · 계약 2027-06`). 칸을 벗어나면 저장됩니다.

| 열 | 내용 |
|---|---|
| 사용자 | 이름(ID), 비활성 사용자는 `비활성`(허가 스위치가 잠김) |
| 허가 | `seats: all` 이면 스위치 대신 `전원 허가` |
| 기기 | `연결된 기기 / 최대` |
| 마지막 사용 | 마지막으로 플랫폼에 닿은 시각 |

> **참고** 허가를 회수하거나 기기를 끊으면 그 IDE 는 다음 요청부터 잠깁니다.

## 기기

<figure><img src="img/platform/a-axnavi-devices.png" alt="기기 탭 — 사용자·기기(이름·OS)·프로그램(IDE 버전)·상태(사용 중/끊김)·연결·마지막 사용(시각·IP) 열의 표, 사용 중 기기 행에 끊기 버튼"><figcaption>기기 탭 — 탭 이름의 숫자는 사용 중인 기기 수입니다</figcaption></figure>

| 열 | 내용 |
|---|---|
| 사용자 · 기기 | 사람, 기기 이름 · OS |
| 프로그램 | `IDE` 또는 `CLI` 와 버전 |
| 상태 | `사용 중` · `끊김` |
| 연결 · 마지막 사용 | 처음 연결 시각, 마지막 사용 시각 · IP |

잃어버린 PC·퇴사자 기기는 행의 **끊기**를 누르고 `이 기기의 AX-NAVI 를 바로 잠글까요?` 를 확인합니다. 1인 기기 수가 꽉 차서 새 PC 를 승인받지 못할 때도 옛 기기를 끊어 줍니다.

## 유출본 확인

밖에서 발견한 스킬·에이전트 지침 글이 어느 사용자·기기에 내려간 것인지 찾습니다.

1. **유출본 확인** 탭의 **발견한 글** 칸에 글을 그대로 붙여 넣습니다.
2. **찾기**를 누릅니다.

| 결과 | 뜻 |
|---|---|
| `표식이 없습니다.` | 표식이 없거나, 글을 옮기며 표식이 지워졌습니다 |
| `표식 N개를 찾았지만 이 플랫폼의 기기와 맞지 않습니다.` | 다른 플랫폼에서 내려간 글입니다 |
| 기기 표 | 그 표식이 들어간 사용자·기기. 필요하면 바로 **끊기** |

## 조직 설정 — 규칙·양식·스킬·MCP 배포

<figure><img src="img/platform/a-axnavi-profiles.png" alt="AX-NAVI 관리 › 조직 설정 — 왼쪽 설정 묶음(e2e-all v1 · 전사 · 우선순위 100)과 새 묶음 버튼, 오른쪽 파일 꼬리표(rules/e2e.md·mcp.json·modes/e2e-sr.json)와 파일 내용 편집 칸, 초안 저장·저장하고 배포… 버튼, 배포 이력(v1)과 받아 간 기록 표"><figcaption>조직 설정 — 묶음, 파일 편집, 배포 이력, 받아 간 기록</figcaption></figure>

규칙·SDLC 양식·스킬·MCP 서버·인증 정책을 묶어 **전사** 또는 **팀(워크스페이스)** 에 배포합니다. 개발자 PC 의 AX-NAVI 는 시작할 때(10분 간격) 또는 `axnavi org pull` 로 받아 CLI(정책·MCP·양식·규칙)와 IDE(전역 규칙 `~/.roo/rules` · 스킬 `~/.roo/skills`)에 깝니다. 받을 때는 각자의 플랫폼 키(`HNIX_AX_KEY`)를 씁니다.

> **주의** **IDE 로그인만으로는 받지 않습니다.** 받는 것은 AX-NAVI CLI 이고, PC 에 `HNIX_AX_SERVER`·`HNIX_AX_KEY` 환경 변수가 있어야 합니다. IDE 만 쓰는 PC 에 묶음을 보내려면 [조직 설정 배포와 CI 게이트](/admin/axnavi/profiles.md)대로 환경 변수를 배포하세요. 받아 간 PC 는 아래 **받아 간 기록**에서 확인합니다.

### 묶음 만들기

1. **설정 묶음** 카드의 **새 묶음**을 누릅니다.
2. **이름**(영문 소문자·숫자·하이픈, 예: `all-company`, `team-hr`), **설명**, **대상 워크스페이스**(비우면 전사), **우선순위**, **사용**을 정하고 **저장**합니다.

> **참고** 우선순위가 작을수록 먼저 깔리고, 같은 경로의 파일은 뒤 묶음이 이깁니다. 대상·우선순위는 나중에 **대상·우선순위** 버튼으로 바꿉니다.

### 파일 편집

1. 묶음을 고릅니다. 파일은 위에 꼬리표로 보이고, 누르면 아래 칸에서 내용을 고칩니다(꼬리표의 × 로 빼기).
2. 새 파일은 **파일 추가(예시)** 목록에서 고르거나(예시 내용이 채워짐), 경로를 적고 **추가**합니다.

| 경로 | 내용 |
|---|---|
| `rules/이름.md` | 코딩 규칙 등 전역 규칙 |
| `templates/종류.md` | SDLC 산출물 양식(머리에 `required: [절 이름…]`) |
| `skills/이름/SKILL.md` | 팀 스킬 |
| `modes/이름.json` | IDE 모드(역할·지시·쓸 도구 묶음) |
| `mcp.json` | MCP 서버 목록(예: 플랫폼 허브 `${HNIX_AX_SERVER}/mcp`) |
| `policy.json` | 인증 정책(예: 허용 경로 `subscription`·`gateway`) |

3. **초안 저장**을 누릅니다(아직 배포 전). 목록에 `초안 변경` 꼬리표가 붙습니다.

### 배포 · 되돌리기

1. **저장하고 배포…** 를 누릅니다(초안을 먼저 저장합니다 — 창을 닫아도 저장한 초안은 남습니다). 창에 지난 배포 대비 `추가` · `삭제` · `변경` 파일이 나옵니다.
2. **배포 메모**(예: SQL 규칙 추가)를 적고 **배포**를 누릅니다. 새 버전 `vN` 이 생기고, AX-NAVI CLI 를 쓰는 PC 는 다음 시작(또는 `axnavi org pull`) 때 받습니다.
3. **배포 이력**의 **바뀐 것**으로 버전 사이 차이를 나란히 봅니다.
4. 문제가 있으면 옛 버전의 **되돌리기**를 누릅니다 — 그 내용을 **새 버전**으로 다시 배포합니다.

**받아 간 기록**에는 사용자(키·로그인), 받은 배포본(해시), 클라이언트, 받은 시각이 남습니다. 모든 PC 가 새 버전을 받았는지 여기서 확인합니다.

> **주의** 묶음 **삭제**는 묶음과 배포 이력을 지웁니다. 개발자 PC 에서는 다음 받기 때 빠집니다.

배포 운영과 CI 게이트는 [조직 설정 배포와 CI 게이트](/admin/axnavi/profiles.md)를 보세요.
