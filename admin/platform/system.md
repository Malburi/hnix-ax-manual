# 사용자 · 워크스페이스 · 감사 · 현장 점검

> 플랫폼 사용자와 시스템 역할, 워크스페이스를 관리하고, 감사 로그를 조회하고, 설치 뒤 연결 상태를 한 화면에서 점검합니다. **대상**: 시스템 관리자(변경), 감사자(조회). **메뉴**: 관리 › 사용자 · 워크스페이스, 관리 › 현장 연결 점검, 관리 › 감사 로그.

## 화면 구성

| 메뉴 | 화면 | 하는 일 | 감사자 |
|---|---|---|---|
| **사용자 · 워크스페이스** | 위 묶음 탭 **사용자** | 사용자 추가·수정·비활성화 | 조회만 |
| | 위 묶음 탭 **워크스페이스** | 워크스페이스 추가, 구성원 넣기·역할·빼기 | 조회만 |
| **현장 연결 점검** | | 설치 뒤 연결 상태 점검 | **다시 점검**만(연결 시험은 시스템 관리자) |
| **감사 로그** | | 누가 무엇을 했는지 조회 | 조회 |

`관리` 묶음은 시스템 관리자·감사자에게만 보입니다. 사내 AD(LDAP)·SSO(OIDC) 로그인 연동, 로그인 잠금, 처음 관리자 계정은 [계정 · 권한 · 로그인 연동](/admin/accounts.md)을 보세요.

| 역할 | 시스템 관리자 · 감사자 · 사용자 |

| 사용자 | 자기 작업 화면과 자기 기록만 |

### 사용자 추가

1. **사용자 추가**를 누릅니다.
2. **로그인 ID**, **이름**, **비밀번호**(8자 이상, 영문·숫자·특수문자 중 2종), **팀**, **이메일**, **역할**을 넣습니다.
3. **만들기**를 누릅니다. 새 사용자는 기본 워크스페이스에 자동 배정됩니다.

여기서 만드는 계정은 **로컬** 계정입니다. 사내 AD·SSO 계정은 연동 설정의 `autoCreate` 가 켜져 있으면 처음 로그인할 때 만들어집니다([계정 · 권한 · 로그인 연동](/admin/accounts.md)).

### 사용자 수정

1. 행의 **수정**을 누릅니다. 창 제목은 `사용자 수정 — <로그인 ID>` 입니다(로그인 ID 는 바꿀 수 없음).
2. **이름** · **팀** · **이메일** · **역할**을 고칩니다.
3. 비밀번호를 다시 정하려면 **새 비밀번호**에 넣습니다(바꿀 때만, 비우면 그대로).
4. **저장**합니다. 비밀번호를 바꿨으면 `새 비밀번호를 본인에게 알려 주고 첫 로그인 뒤 바꾸게 하세요` 가 뜹니다.

> **참고** **사내 AD** · **사내 SSO** 계정은 비밀번호 칸이 없고 `사내 AD 계정 — 비밀번호는 회사 계정에서 바꿉니다` 처럼 안내됩니다.
> **참고** 내 행을 수정할 때는 **역할**이 잠깁니다. 관리자가 한 명도 남지 않는 일을 막기 위해 내 역할은 스스로 바꿀 수 없습니다 — 다른 시스템 관리자에게 부탁하세요.

### 비활성화

행의 **비활성화**를 누르면 그 사람은 더 이상 로그인할 수 없습니다. 기록(요청·실행·감사)은 남습니다. **활성화**로 되돌립니다. 내 행에는 이 버튼이 없습니다.

> **참고** 퇴사자는 지우지 말고 비활성화하세요. AX-NAVI 를 쓰던 사람이면 [AX-NAVI 사용 허가](/admin/platform/axnavi.md)에서 허가를 끄고 기기를 끊습니다. 비활성 사용자는 허가 스위치가 잠깁니다.

## 워크스페이스

<figure><img src="img/platform/a-workspaces.png" alt="워크스페이스 탭 — default · 기본 워크스페이스 행과 구성원 버튼, 아래 구성원 표(역할 선택 칸·빼기)와 구성원 넣기 칸"><figcaption>워크스페이스 탭 — 구성원을 누르면 아래에서 사람을 넣고 빼며 역할을 바꿉니다</figcaption></figure>

워크스페이스는 키·예산·도구 정책·문서의 경계입니다. 문서 컬렉션은 워크스페이스에 속하고 그 구성원만 검색합니다. 데이터 등급에 따라 게이트웨이가 사내 모델을 강제할 수 있습니다.

| 열 | 내용 |
|---|---|
| 슬러그 · 이름 | |
| 기본 데이터 등급 | **공개 · 사내 · 기밀 · 제한(사내 모델만)** — 이 워크스페이스의 요청·문서 컬렉션 기본 등급. 제한 등급의 요청은 사내 모델로만 갑니다 |
| 생성 | |
| **구성원** | 아래에 구성원 표와 넣기 칸이 열립니다 |

### 워크스페이스 추가

1. **워크스페이스 추가**를 누릅니다.
2. **슬러그**(예: `sm-ops`), **이름**, **기본 데이터 등급**을 넣고 **만들기**를 누릅니다.

### 구성원 넣기 · 역할 바꾸기 · 빼기

1. 워크스페이스 행의 **구성원**을 누릅니다.
2. 넣기: 위 칸에서 사람을 이름·아이디로 찾아 고르고, 역할을 고른 뒤 **구성원 넣기**를 누릅니다.
3. 역할 바꾸기: 구성원 표의 **역할** 칸에서 바로 고르면 저장됩니다.
4. 빼기: 행의 **빼기** → 확인. 그 사람은 이 워크스페이스의 문서·에이전트를 더 쓰지 못합니다(기록은 남습니다).

| 역할 | 할 수 있는 일 |
|---|---|
| 워크스페이스 관리자 | 문서 컬렉션 만들기·올리기·지우기, 구성원의 에이전트 공유 |
| 구성원 | 문서 올리기·검색, 에이전트 실행·내 에이전트 |
| 보기만 | 문서 검색·보기 |

> **참고** 새 사용자는 처음에 기본 워크스페이스에 들어갑니다. 사내 AD·SSO 로 처음 로그인한 사람도 같습니다. 모든 바꾸기는 감사 로그에 `admin.workspace.member.*` 로 남습니다.

## 감사 로그

<figure><img src="img/platform/a-audit.png" alt="감사 로그 화면 — 행위 접두어 입력 칸과 조회 버튼, 시각·행위(auth.login)·결과(ok)·주체·대상·상세·IP 열의 표"><figcaption>감사 로그 — 최근 200건</figcaption></figure>

| 열 | 내용 |
|---|---|
| 시각 · 행위 | 행위 이름(예: `auth.login`, `gateway.budget.create`, `hub.server.create`, `runbook.create`, `docs.collection.delete`) |
| 결과 | `ok` · `denied` · `error` |
| 주체 | 이름(로그인 ID), 시스템이 한 일은 `시스템` |
| 대상 · 상세 · IP | 대상 종류·ID, 바뀐 내용 요약(JSON) |

1. **행위 접두어** 칸에 앞부분을 넣습니다(예: `auth.` = 로그인, `admin.` = 사용자·워크스페이스·백업, `gateway.` · `hub.` · `runbook.` · `docs.`).
2. **조회**(또는 Enter)를 누릅니다. 최근 200건이 나옵니다.

> **참고** 설정 변경·승인·키 발급·문서 추가 같은 일이 남습니다. 비밀번호·키 같은 비밀값은 값 대신 설정 여부만 남깁니다(예: `secretSet`).

## 현장 연결 점검

<figure><img src="img/platform/a-readiness.png" alt="현장 연결 점검 화면 — 안내 상자, 다시 점검·연결 시험 포함 점검 버튼과 정상 11·확인 4·문제 2·안 씀 1 꼬리표, 기본 설치·LLM 게이트웨이·도구 서버(MCP 허브) 카드의 항목·상태·내용·할 일 표"><figcaption>현장 연결 점검 — 영역별 항목과 할 일</figcaption></figure>

고객사에 설치한 뒤 연결 상태를 한 화면에서 확인합니다.

1. **현장 연결 점검**을 열면 이미 남은 기록(마지막 동기화·웹훅 수신·최근 요청)만 읽어 점검합니다. 다시 하려면 **다시 점검**을 누릅니다.
2. 실제로 붙어 보려면 **연결 시험 포함 점검**을 누릅니다(시스템 관리자). MCP 서버·고객 ITSM·외부 AI 관리 API 에 실제로 접속합니다.
3. 위 꼬리표에서 `정상` · `확인` · `문제` · `안 씀` 건수와 점검 시각을 봅니다.
4. 영역 카드마다 **항목 · 상태 · 내용 · 할 일**을 읽고 `문제`·`확인` 부터 고칩니다.

| 영역 | 보는 것 |
|---|---|
| 기본 설치 | 데이터베이스, 접속 주소(publicUrl), 로그인 연동, 백업, 여러 대 운영 |
| LLM 게이트웨이 | 모델 연결마다 최근 하루 성공·실패 |
| 도구 서버(MCP 허브) | 서버마다 도구 목록 받은 시각 |
| 고객 ITSM | 연결·동기화·웹훅 수신 |
| Git 저장소(생산성) | 저장소 웹훅·커밋 수신 |
| 외부 AI 사용량 | 수집 원천의 마지막 수집 |
| 자동화 | 런북·트리거·현업 창구(예: 플랫폼 접수함에만 쌓는 창구) |
| AX-NAVI 조직 설정 | 배포 상태 |

> **참고** **할 일** 열에 설정 이름이 나오면(예: `backup.time`, `auth.ldap`, `server.publicUrl`) 서버 설정 파일을 고칩니다 — [운영 — 백업 · 업그레이드 · 점검](/admin/operations.md), [계정 · 권한 · 로그인 연동](/admin/accounts.md).
