# PMS-X 관리 개요

> PMS-X(1.3.24)의 **관리** 메뉴로 사용자·프로젝트·기준 정보·처리 기한·알림·감사·라이선스를 다루고, 서버 설정으로 AI·연동을 켭니다. **대상**: 시스템 관리자(SYS_ADMIN), PMO, PM. **메뉴**: 왼쪽 메뉴 › 관리.

## 화면 구성

|---|---|---|
| 프로젝트 관리 | 프로젝트 등록·수정, 참여 인원·역할·투입 기간, 투입 체크리스트, 협력사 열람 범위, SI → SM 인수인계 | [프로젝트와 멤버](/admin/pmsx/projects.md) |
| 사용자·역할 | 로그인 계정과 시스템 역할, 잠금 해제·비밀번호 초기화 | [프로젝트와 멤버](/admin/pmsx/projects.md#사용자-등록) |

| 엑셀 양식 연결 | 고객사 엑셀 양식에 필드·셀 위치 연결 | [기준 정보](/admin/pmsx/settings.md#엑셀-양식-연결) |
| 처리 기한 정책·업무 캘린더 (SM) | 요청 유형·우선순위별 응답·해결 목표와 업무시간 | [기준 정보](/admin/pmsx/settings.md#처리-기한-정책·업무-캘린더) |

| 감사 로그 | 로그인·다운로드·소스 조회·변경 이력 | [시스템](/admin/pmsx/system.md#감사-로그) |
| 라이선스·시스템 정보 | 버전·DB·사용자 수, 라이선스 키 등록 | [시스템](/admin/pmsx/system.md#라이선스·시스템-정보) |

As-Is 분석의 **시스템 관리**와 **수집 이력 / 업로드**는 관리 메뉴가 아니라 As-Is 분석 메뉴에 있습니다 — [As-Is 수집기 운영](/admin/pmsx/collector.md).

## 관리자 역할

PMS-X 역할은 두 가지 층입니다.

| 층 | 역할 | 정하는 곳 |
|---|---|---|
| 시스템 역할 | **시스템 관리자**(SYS_ADMIN), **PMO** | 관리 › 사용자·역할 |
| 프로젝트 역할 | 프로젝트 관리자(PM) · 파트 리더(PL) · 분석 담당 · 개발자 · 품질 담당 · 운영 담당 · 협력사 · 고객 담당자 | 관리 › 프로젝트 관리 › 참여 인원 |

관리 메뉴에서 역할별로 할 수 있는 일:

| 메뉴 | 시스템 관리자 | PMO | PM | 운영 담당 |
|---|---|---|---|---|
| 프로젝트 관리 | 등록·수정·인원·인수인계 | 등록, 조회 | 수정·인원·인수인계 | — |
| 사용자·역할 | ○ | — | — | — |
| 방법론 템플릿 | 편집 | — | 조회 | — |
| 공통코드·용어 | 편집 | — | 조회 | — |
| 엑셀 양식 연결 | ○ | — | ○ | — |
| 처리 기한 정책·업무 캘린더 | 편집 | 조회 | 편집 | 조회 |
| 감사 로그 | ○ | ○ | ○ | — |
| 라이선스·시스템 정보 | 정보·라이선스 상세·키 등록 | 정보만 | 정보만 | — |
| 알림 설정 (오른쪽 위 이름 메뉴) | 본인 것 | 본인 것 | 본인 것 | 본인 것 |

> **참고** 운영 설치를 처음 띄우면 사용자가 한 명도 없을 때 `admin` 계정이 만들어집니다. 비밀번호는 환경 변수 `PMSX_ADMIN_PASSWORD`로 주거나, 없으면 무작위로 만들어 설치 폴더의 `run\initial-admin-password.txt`에 남깁니다. 로그인한 뒤 비밀번호를 바꾸고 그 파일은 지우세요. 시연용 계정은 운영에 쓰지 마세요.

> **주의** 시스템 관리자도 프로젝트 화면(WBS 편집·작업 배분 등)은 그 프로젝트의 **PM으로 참여**해야 씁니다. 프로젝트를 만들 때 지정한 PM은 자동으로 참여 인원(프로젝트 관리자)이 됩니다.

## 처음 설정 순서

1. [라이선스 키 등록](/admin/pmsx/system.md#라이선스·시스템-정보) — 운영 설치는 라이선스가 없으면 시스템 관리자만 로그인됩니다.
2. [공통코드](/admin/pmsx/settings.md#공통코드) 확인 — 공휴일(HOLIDAY), 기술 등급, 소속 구분, 투입 체크리스트.
3. [방법론 템플릿](/admin/pmsx/settings.md#방법론-템플릿) 정리.
4. [사용자 등록](/admin/pmsx/projects.md#사용자-등록) — 자체 계정 또는 LDAP·AD 사용자.
5. [프로젝트 만들기와 인원 추가](/admin/pmsx/projects.md).
6. SM 프로젝트면 [처리 기한 정책](/admin/pmsx/settings.md#처리-기한-정책·업무-캘린더) 확인.
7. 필요하면 [AI · 메일 · 메신저 · 경보 연동](/admin/pmsx/system.md) 설정.
8. As-Is 분석을 쓰면 [시스템 등록과 수집기](/admin/pmsx/collector.md).
